## 先保留已经确认的意图

本次用户要四层水雷效果：水刃、水花尾流、紫电、蓝白亮芯。角色为占位，不要求依赖皮肤。月牙不仅要处在竖直XY面，长轴和动线也要从高处向下扫。当前发布中斩、打、突共用这一款，远程保持原样。

用户明确要求单人完成后，本轮停止子代理，后续用主线程顺序完成研究、实现和复查。后续继续同一会话时应保留这个要求；不要因为仓库的默认流程又重新开启代理。

需求会被后续反馈修正，记录里要保留“最终采用什么”和“为什么旧解释不再适用”：

- 用户最初说几个圈逐渐扩大，后来明确否决夸张圆圈，改为水纹散点扩散。最终方案没有可见大圆环。
- “命中点怎么这么多”后来被用户确认为退场圆圈问题。不要继续削减真正命中爆发。
- 用户要的是亮部扫过并由蒙版增强。整张材质渐显、从尾部开始逐段Reveal都不满足这个要求。
- “可以用ImageGen”是允许，不是强制。这个案例的技术纹理和Mask使用可复现的Python生成。

## 形状、入场和尾流要分开设计

只把网格放在XY面，仍可能得到横着掠过的刀光。先检查白模的长轴、曲率、重心、前锋方向及最低高度，再调材质。透明Shader的Cull Off会隐藏反面绕序问题，因此白模也要用常规剔除材质看一次。

本次早期三角面朝向错误直到白模才暴露。另一次电弧端点NaN来自浮点sin(π)略小于0，再取小数次幂。对端点包络先做非负保护：

```csharp
float taper = Mathf.Pow(Mathf.Max(0, Mathf.Sin(q * Mathf.PI)), exponent);
```

尾端被捏到零宽时，换任何发散Mask都撑不开几何。最终先给尾端留扇形空间，再用独立分叉Mask切出长短、粗细不同的断续水丝。尾部位移记录在UV3，材质TailSpread可调，避免复制同形透明外壳。

入场要与静态造型分开：

1. 保留完整网格，主层Reveal固定1。
2. 运动前锋使用前窄后宽的尖楔；亮芯使用居中尖楔，水体使用外侧尖楔。
3. 亮部沿pathT扫过后，局部水体才横向展开。
4. 早期TailGrowth=0，前锋通过后才允许扇尾扩散。
5. 起手亮芯要达到可见像素宽度。静态“尾部少亮”不能把正在起手的运动尖头一起压没。

## 遮罩各自只负责一件事

| 数据 | 职责 | 主要约定 |
| --- | --- | --- |
| Shape RGBA | 水体颜色、透明结构 | 不把RGB误当覆盖率 |
| WaterMask / TailFanMask R | 主体负形、分叉尾流 | Linear、Clamp |
| SweepBrushMask R | 沿弧线运动的亮部和宽度 | Linear、Clamp；前端尖、后方宽 |
| Flow / Caustics | 内部流动与亮纹 | Linear、Repeat；对边连续 |
| WaterNormal RGB | 水滴表面法线 | 原始线性数据，不作sRGB颜色采样 |
| Evap_WaterScatter RGBA | R主体溶解高度、G水滴溶解高度、A可见散点 | Linear；颜色由散点材质BaseColor提供 |
| WhiteFluidQuadMask R | 四角弯曲流纹 | 只在水体覆盖内平移/旋动 |

主层、辅助粒子和水滴共用兼容Shader时，必须明确材质模式。水滴Color.r存seed、g存年龄、b存水丝标志、a存透明度；Liquid未启用时会把这些数据画成错误颜色。本次出现过命中水花发绿：补上明确的材质绑定、EditorUtility.SetDirty和重新加载后的Liquid=1检查才收口。

## 水滴的流体感不能只靠一张椭圆图

早期固定长宽、固定朝向、整圈均匀亮边的小椭圆像玻璃碎片。最终组合了这些行为：

- 轨迹使用可直接seek的重力/线性阻力闭式解；顺当前速度定向，减速后回圆。
- 长轴变化时宽厚相应缩放，近似保持体积，减少随意膨胀。
- 每个粒子使用不同seed和相位的衰减毛细波；位置轨迹不靠同步正弦摆动冒充湍流。
- 少量短水丝拉长、收颈、分成小滴。形状过渡混合距离场，直接叠加两套alpha会出现重影。
- 水体保持较薄透明度，小范围移动高光替代整圈等亮轮廓，避免实心珠子感。
- 最终水滴数量80；出生离刀痕更近，向外速度降低。密度、出生域、粒径和速度要一起调整。

本次用固定中心的实际GPU放大序列检查材质形变，另外看正常尺寸、正常速度的整体效果。放大图好看不能代替游戏尺度下的可读性。

## 溶解要证明覆盖被移除

只降低alpha，或者把完整材质软过渡到一张散点图，容易缺乏明确溶解感。最终做法是：

1. 用连续高度场与阈值逐步蚀掉覆盖。
2. 主体使用较细碎R场，水滴使用较柔和G场，避免一套尺度到处套。
3. 主体的高度场按固定局部坐标采样，阈值持续上升；散点残影另行扩散和上浮。
4. 水滴在自身寿命后段溶解，最后12%寿命才做短alpha收尾。
5. 给出固定Alpha=1的验证帧。候选16中可见覆盖依次为23181、22305、20137、15588、6618、453像素，证明覆盖本身在减少。

低频高度场会把细长水刃切成几大块。这个案例曾因此返修：改成多尺度细碎水纹后才采用。不要只凭Shader中存在Dissolve参数就宣称溶解成立。

## 旋流纹样和电枝要有各自的运动依据

白色四方流纹通过格内UV旋转与沿水流平移表现自旋，受原水体/扫光/溶解共同约束。不要把纹样做成离开水体的方框或法阵，也不要靠另一张同形透明壳提亮。

电枝需要真正相连的几何主干和分支。最终L3用UV2.x记录权威扫过时间，UV2.y记录局部能量储备；着电后快速充能，再阻尼脉冲和放电。小枝储备低先熄灭，较早经过的段放电时间更长先衰减。命中碎电有自己的局部时钟，不能直接使用全局Phase冒充粒子年龄。这是视觉近似，不把它称为完整电磁模拟。

## Unity 2019上实际遇到的坑

| 现象 | 本轮可复用处理 |
| --- | --- |
| 冷启动直接seek到命中帧，粒子不见了 | 先Simulate(0)初始化，再SetParticles；不要让首次初始化清掉刚填入的粒子 |
| 已设置Material数值，重新读取却不对 | 明确绑定角色材质、SetDirty，重新加载后再断言；检查实际GPU颜色 |
| MonoBehaviour导入时报CreateImpl不允许 | MaterialPropertyBlock等原生对象在正常调用/Awake中延迟创建，避免字段初始化 |
| OnValidate触发反序列化阶段原生对象创建 | OnValidate只标记dirty，实际创建和采样放到正常Editor update |
| 保存场景时引用了临时飞沫Mesh | 保存前恢复源Mesh引用，实例克隆用DontSave并由实例释放 |
| 放大、镜像、换父级后水滴落地判断错误 | 使用TransformPoint换算世界位置，避免局部Y与世界Y相加 |
| 编辑器预览停住 | ExecuteAlways不保证每帧编辑态Update，提供受控EditorApplication.update时钟 |
| ffmpeg报告Unknown encoder libx264 | 选用imageio-ffmpeg已验证的可执行文件，不依赖PATH中碰巧命中的版本 |

本机批处理使用D3D11真实RenderTexture，不能加-nographics后仍声称GPU画面验收。CPU affinity和OpenSSL兼容变量是本机已有运行条件，只对子进程设置，不推广成通用Unity修复。

## 制作工程接入游戏时重新验证调用链

静态AB能加载和播放脚本能运行，仍不足以证明卡牌会调用它。最终包只含原生Transform/MeshFilter/MeshRenderer/ParticleSystem等组件，自定义驱动由Steria.dll提供。

这轮新增竞争工厂前缀时，注册表里可见priority=800，直接调用新工厂能初始化，但真正DiceEffectManager仍返回旧类型。没有凭这些局部成功放行；改成既有注册表三行类型替换，并复用已存在的成功命中路由后，真实工厂才返回新类型。记录这个观察，不推断成某个通用Harmony缺陷。

发布中的坐标/事件约定：

- 仍用J/H/Z原生挂点，保留近战2倍和骰子倍率各一次。
- 素材默认+X、原版默认-X，固定局部反向作为素材坐标基转换；继续继承一次角色朝向。
- 原型单位归一化0.55；命中位置落在目标胸前，世界锚点冻结，攻击者移动不拖走残影。
- 原生同帧、同目标、同攻击类型的成功表现才启用命中爆发；取消/空挥/错误目标/过期配对不会被计时器误判为成功。
- SetDestroyTime、OnDisable和OnDestroy都清理自有粒子与Mesh。暂停/重放不依赖全局realtime推进视觉。

注意卡牌Spec.Range与单颗骰子的实际EffectRes不总是一回事。部分Far卡内仍有J/H/Z近战/反击入口。本轮以三个资源键识别替换范围，保留FarHit和FarArea，XML无需重写。

## 精确发布与证据边界

工作区有其他未发布改动时，先核对安装DLL、匹配PDB和对应源码。最终从已部署基线重建，只加入5份源码、限定修改2份旧源码；97份旧业务源码及13份内嵌资源保持。尤其不要为了改3行注册把整个dirty HarmonyPatches.cs打包发布。

程序集构建后看DLL/PDB是否匹配、源码checksum、内嵌资源和引用，随后在原生夹具加载实际DLL和AB。独立Runtime/Editor asmdef用于避免游戏Assembly-CSharp与夹具默认程序集的边界混淆；整包加载还需要匹配的BaseMod依赖。测试工具准备问题与产品调用缺陷分别记录。

最终102项原生检查包含三类、双朝向、缩放、世界命中点、真实Update、成功/空挥/错误目标/取消、原远程与守备。D盘为真实游戏目录，C盘入口为同一目录别名：按真实路径去重，备份后原子写入，再对D/C/仓库包逐项核SHA256。XML和旧风系AB也作为“保留文件”核验。

实际文件已部署，提交为62946d59；本轮没有启动完整接待，不能写成实战通过。具体hash、收据、备份和本机路径见部署记录。冻结发布源码快照在deployment/release-03-sources.zip，既有参考DLL不随快照分发。
