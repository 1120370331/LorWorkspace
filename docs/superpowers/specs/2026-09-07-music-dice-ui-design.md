## 用户意图与边界

用户：‘修一下乐章骰子用这个贴图，他太突兀了，还是用废墟图书馆自带的icon来改一个出来，以及相关卡颜色的显示也是逻辑很乱的，不美观。’

成功标准：自行绘制借鉴原版六边轮廓的干净乐章底框和唯一音乐中心，形成一致柔和笔触，没有 Slash 残影或生硬白贴纸感；整卡稀有度、EGO、高亮和禁用状态保持已经修复的原版一致逻辑；战斗/卡组/详情/动作骰/伤害图标的乐章中心一致。保留游戏原有行距和骰子顺序。

本任务只修 UI，不改伤害倍率、威力、拼点、反击触发、XML 骰种、卡牌稀有度或卡面立绘。尤其不要为了 UI 判定去修改共享战斗判定 `IsMusicDiceBehaviour`。反击攻击骰的当前战斗判定与注释冲突记录在风险里，机制修正另行授权。

## 根因诊断

1. **图标语言改变。** 旧 `MusicDiceSpriteFactory` 优先从运行 DLL 上级的 `Resource/ArtWork`（回退 DLL 同级）读取 `music_dice_die_icon.png`；旧 `EnsureBookDiceBackdrop` 把它添加为 sibling Image，隐藏原版斩/突/打图标。额外宝石的旋涡雕饰、厚重体积和大面积饱和渐变与当前原版六边框白线稿不协调。原版自身的细框、轻光泽、笔刷边应保留。所有乐章骰合并为一个中心符号本身符合用户意图，之前将三种中心保留是设计错误，已由本轮修订纠正。
2. **整卡边框被当成每颗骰子的高光。** 原版 `UIOriginCardSlot.img_linearDodge` 是 `SetLinearDodgeColor` 遍历的整卡稀有度/高亮框数组（源码约 145-166 行），不是骰子图标数组。当前 `ApplyOnOriginSlot` 用骰子下标对齐它，禁用若干框段。原版 `BattleDiceCardUI.img_linearDodges` 同样由整卡 `SetLinearDodgeColor` 管理（约 751-763 行），当前 `ApplyBattleDiceCardFaceStrip` 将部分条段设白。卡牌含几颗乐章骰便可能有几段框被破坏，是‘逻辑很乱’的直接根因。
3. **布局补偿造成混合骰错位。** 自定义图标用 `BookDieIconScale`、0.75 卡面缩放、0.62 向乐章骰中心收拢；普通 Guard 仍在原位。混合骰的间距/队列关系因此失真。
4. **颜色语义被重置。** 战斗描述行把 `txt_ability` 和 `txt_range` 全部设白，覆盖原版 `Rwbp` 文本语义和骰种点数色；卡组详情却未统一点数色。清理仅强制白色/HSV 1，不保存原先状态，可能覆盖刚由原版更新的稀有度、目标抗性、交互状态。不能把‘白色’等同于‘恢复原版’。
5. **动作 UI 以整卡判定。** 两个 `PrepareDice` Postfix 只检查 cardOfBehaviour，`汐音：海之还愿`（9008006）末尾两颗 Guard 也会被染蓝。`PrepareDice(BattleDiceBehavior)` 原版存在但未覆盖。应以该次参数的真实骰子 Type/Detail 判定，不能靠卡页整体或图标名。
6. **静态 XML 对齐运行时列表。** 当前 BattleDiceCardModel 的 `TryGetDiceBehaviourAt` 取 XmlData.DiceBehaviourList；原版 UI 使用 `GetBehaviourList()`。`汐音：光耀万海`（9009006）动态复制骰后，新增行可能丢样式。显式 SetBehaviourInfo 参数优先，其次与原版相同的运行时列表。
7. **伤害图标另有入口。** `ApplyOnDamageText` 也使用宝石；只修卡片会留下战斗伤害时的突兀图形。`DamageTextEffect.Update` 会把 bg 颜色复制给主图标并更新 alpha，因此只改主 Image.color 会在淡出时被覆盖。

## 冻结设计合同

### 原版图标

- 小图标底框与中心都自行绘制：几何路径生成一个干净蓝灰六边底框与唯一连音符，不再从 `_cardBehaviourDetailIcons` 的攻击图像取像素。所有乐章攻击骰固定同一合成输出。防御和反击继续保留原版资源，包括 `CardStandbyBehaviourDetailIcons`。
- 保留现有 Image 的整体位置、尺寸、pivot、排布及原有 UI 状态逻辑；图形内部采用下方新轮廓/填充/边缘合同。中心不能复用音乐 Buf、字体、Emoji 或现成图标，不能添加立体宝石、光圈或第二套背板。
- 从原创矢量/代码路径超采样生成并缓存卡页完整图标与中心-only 图标。删除或停用 `ClearBakedAttackCenter`、攻击图 atlas 读取和色相补底链，不能以更大清除 mask、更久扩散或额外 blur 继续修补旧素材。
- 动作骰继续使用 `BattleSimpleActionUI_Dice.GetFaceSprite` 已配置的原版多面骰及边缘材质；不替换骰面几何，`imgIcon` 与 `imgDetailIcon_Center` 的乐章中心均用同一音乐符号。
- 伤害入口的乐章中心也复用同一个音乐符号，不再使用动作类别中心或旧宝石 PNG；保持数字、HP/混乱伤害颜色、现有原版外围状态及淡出节奏。
- 旧 `music_dice_die_icon/face/glow` 文件即使仍在部署目录，也不能再影响该路径；避免仅靠删文件让旧程序回退生成圆角面板。

### 色彩分工

| 信息 | 控制范围 | 规则 |
| --- | --- | --- |
| 书页稀有度、EGO | 原版 frame、linearDodge、cost、range 系统 | 完全由 UIColorManager 和原版状态方法负责，绝不索引/染白/隐藏整卡框数组 |
| Hover/selected/disabled | 原版状态和原版 graphic 集合 | 保留优先级，乐章 refresh 不重新亮起被禁用/置灰的控件 |
| 乐章类型 | 本颗普通攻击骰的图标和点数范围；动作骰自身 | 默认蓝灰 `#8FAFC4` (143,175,196)，亮边 `#C9D8E1` (201,216,225)，单一色系；不要叠蓝渐变面板 |
| 防御、闪避、反击 | 原版该骰图标和点数范围 | 完全原版，含乐章卡上的 Standby 攻击骰 |
| 能力正文和关键词 | txt_ability | 保留原版 Rwbp 和富文本局部颜色，不统一染白或染蓝 |
| 点数变化/胜败/破碎 | 原版动作状态处理 | 保留 Normal/Increase/Decrease、动画和 alpha；仅乐章默认基色参与，不在 refresh 强制回 Normal |

颜色为设计目标，不硬编码其他原版稀有度色值（原版值由序列化配置决定）。若实际原版 shader/色样需要微调，可报告技术差异并在预览复核后微调此两色；不扩大为重新设计卡牌配色。

### 判定与状态恢复

- 新建或局部限定 **UI 专用**判定：卡有 SteriaMusicDice 且 `Type == Atk` 且 Detail 属 Slash/Penetrate/Hit。`IsMusicDiceBehaviour` 战斗逻辑保持原状。不得静默修改反击的战斗规则。
- 每次数据绑定前恢复上一次由本模块修改的字段，再执行原版绑定，最后按新数据施加当前样式；清理作用域仅为本模块拥有的 icon/文本字段。不要在原版 Postfix 后用旧快照覆盖新原版状态。
- 对刷新/复用要幂等；不添加与删除装饰层，不重复添加 HSV、不改变共享材质。非乐章回收、隐藏描述及空列表都可恢复；null 或失败 PrepareDice 不拿旧 cardOfBehaviour 误上色。
- 不遍历无关子树后统一白色；不要猜 img_* 字段名字并做数组配对。已知原版字段就明确取已知字段。
- `SetPreviewResist` 本次保持显示合同：目标抗性状态不得被简单样式刷新清零；若乐章固定抗性需要更正文字，是独立的信息准确性工作，不能顺手改战斗规则。本次预览要检查选目标前后没有残色/明度突变。

## 统一中心补充合同（本轮唯一实施范围）

- **唯一中心锁定为自己绘制的白色连音双音符。** `Orchestra_Enthusiastic`、`SingingMachine_Rhythm` 等原版候选只保留为已放弃的研究历史，本轮禁止读取、描摹或复用这些中心；不再搜索资源。不能调用字体、Emoji、图标库或现成音乐 glyph。使用仓库自有 SVG 路径，或代码定义多边形/Bezier 路径，超采样生成透明 sprite。
- **可执行笔形规格：** 以 100×100 的中心-only 设计坐标绘制，内容边界约 x=13..87、y=10..91。两枚白色实心斜椭圆音头，左中心约 (29,78)，大小约 29×19，向右上倾斜 20°；右中心约 (73,67)，大小约 26×18，向右上倾斜 15°。两个音头不能机械复制同一形状。左音杆由约 (39,77) 向 (40,27) 上伸，右音杆由约 (82,65) 向 (83,15) 上伸；主体宽约 7..9，轻微弧度，顶端略收尖。用一条从 (40,27) 向 (83,15) 右上扬的短连梁连接，厚约 8..10，接点重叠避免细缝。整体仅两音头、两音杆、一连梁，轻微不规则轮廓控制在设计单位 1..2 内，不能加噪点、飞白碎屑或细小装饰。
- **栅格与小尺寸规则：** 512×512 或更高超采样后下采样为 128×128 RGBA，采用下方柔白而非纯白；在实际 24、32 px 显示时两音头和连梁清楚，连接处圆滑，无透明针孔、重复描边、锯齿或尖刺。若缩小后断裂，局部加粗/平滑路径，不靠 glow 补可读性。
- 中心视觉宽高约占内框 60%，与边线至少留实际显示 2 px 空隙；图标整体位置、尺寸和 UI 排布保持不变，内部新底框按下方合同绘制。
- 卡组卡面、战斗卡面、两种详情、动态新增乐章骰使用同一自绘完整图标；动作侧图标、动作中心、伤害图标使用同一原创透明中心-only 图标，音乐中心形状完全一致。动作骰原版大骰壳不改，不能把带框小图标再塞进动作骰。
- **伤害三层明确规则：** 主线程批准 `img_resistIcon`、`img_resistIconBg`、`img_resistIconFg` 三层均换为同一个原创透明 glyph-only sprite；仅替换 sprite，保留每层本来的 enabled、color、material 与 alpha 和原有淡出更新。禁止为了表现音符擅自开启隐藏层、重置颜色或加第四层。
- 验证只补唯一中心合同：Slash/Hit/Penetrate 的乐章中心一致；所有入口同一符号；Guard/Standby 保持原状；乐章→普通复用恢复原始中心。复用已经通过且不受影响的卡色/布局检查证据，重跑受中心替换影响的 fixture 与代表预览即可。

## 干净底框修订（覆盖前述历史素材保持要求）

**诊断已读源码：** 当前 `ClearBakedAttackCenter` 只在内框按低饱和亮像素挑出最大连通域并扩展 3 px，再从周围传播颜色、迭代扩散 120 次。旧 Slash 周围的有色光与暗部没有被识别为中心，反而成为补底边界条件，所以会残留弯月形亮底/暗影。`CompositeGlyph` 再叠加纯白音符，把残影留在后面；继续扩大 mask 或 blur 不能建立干净的图形来源。此前关于保留原版外围像素、禁止自绘框、清旧 Slash 后合成的要求均已过期。

**可执行图形合同：**

1. **来源与形状。** `GetCardSprite` 不读取 `UISpriteDataManager`、原攻击 sprite、原 atlas 或其他位图。以 100×100 自有坐标定义六边形，参考顶点 (50,10)、(83,29)、(83,70)、(50,89)、(17,70)、(17,29)；顶点采用约 3 单位圆滑过渡，闭合连续。内容外是干净透明边距。只有一条主边线，没有内立方分面线、第二个嵌套六边框、中心辐射线或颗粒底纹。
2. **内底。** 使用低亮度蓝灰 `#223541`，允许沿整幅高度极轻地由顶部 `#293E4B` 向底部 `#20313C` 过渡。色阶只能由预先定义的全局坐标函数产生，不能由音符/旧 Slash 形状驱动；内部不出现局部强亮区、暗补丁或弯月渐变。完整的干净底框需要另存一张无音符 QA 图，证明残影不被新中心遮住。
3. **边线。** 主边为已接受蓝灰方向 `#8FAFC4`，宽约 3..3.5 单位，允许顶部略浅 `#A3BDCD`、底部略深 `#6F8FA3`；轻微明暗变化要沿轮廓连续，不形成高光断点。使用圆接点、统一抗锯齿；不加 bloom、外光圈、发光底片或模糊遮缝。24 px 实际显示主边约 0.8 px，32 px 约 1 px，视觉重量接近原版小骰图。
4. **音符材质。** 沿用原创双音符结构，改主体纯白为柔冷白 `#D7E1E6`；可由上部 `#E0E8EC` 向下部 `#CBD8DF` 做非常轻的全局垂直色阶，禁止额外边框、阴影或光晕。音头、音杆、连梁应先几何合并为一个轮廓再栅格化，接点用 Bezier 圆滑连接，避免独立形状重叠出硬角、毛边或暗缝。底框和中心以同一超采样/抗锯齿方式处理，形成一致边缘质感。
5. **缓存与范围。** 一份固定原创完整小图标供所有乐章卡页/详情使用，一份同形同材质的中心-only 图供动作和伤害使用；不改外部 UI transforms、原版卡牌稀有度框、费用、正文、Guard/Standby、战斗机制。原版动作大骰壳及既有数值/状态颜色不必改；伤害三层继续仅换同一中心 sprite 并保留状态。

**本轮验收：** 对比 `output/music-dice-ui/before-clean-frame/` 用户拒绝候选，展示无符号底框、完整图标、24/32 px 原尺寸条以及一个真实卡页混合骰场景。底框独立看应是均匀/轻全局过渡，没有任何 Slash 弯月亮底或暗影；完整图的音符和边框接点圆滑、透明边缘自然、不呈硬白贴纸，两个音头可辨且不碰框。源验证明确确认当前 `GetCardSprite` 完全不读原图，并移除旧清白/扩散链。所有乐章同图、防御反击保持原图；只重跑此变更影响的生成/复用/中心与代表 UI fixture，未受影响的卡色证据可复用。

## 2026-09-08 体积微调（当前最高优先级增补）

用户反馈：‘感觉音乐骰子的体积偏大了’。本轮只将所有自绘小图标的可见内容围绕原画布中心统一缩至当前 **80%**；图案、柔白/蓝灰色、材质和已有卡色修复不重新设计。

已定向阅读 `SteriaBuild/VFXSource/MusicDiceUI/MusicDiceSpriteGenerator.cs`：`Rasterize` 在 0..100 作者坐标里采样，Card 与 BlankFrame 为 256×256，Glyph-only 为 128×128，pivot (0.5,0.5)，Card 内 glyph 已有 0.60 局部布局。统一缩放应发生在该局部布局之前：每个超采样点先做 `authorX = 50 + (px - 50) / 0.80`、`authorY = 50 + (py - 50) / 0.80`，再以 authorX/authorY 执行原有框、填充色阶、glyph 局部映射与距离采样。这样框线宽、音符及内部留白一起同比缩小，颜色场跟着图形走，不会重复缩放 Card 中心。

- Card/BlankFrame 保持 256×256；动作/伤害用 Glyph-only 保持 128×128。新增的体积差由四周透明边距体现，不裁切回可见包围盒，不更改 pivot、PPU、UI RectTransform、布局或控件尺寸。
- 缩放仅在离线作者生成器完成，重新烘焙并嵌入 PNG。运行时继续加载缓存图片，不引入 runtime SDF、逐像素生成或缩放逻辑。
- 原版动作大骰壳大小保持不动；只缩小其两个自绘中心及伤害中心。伤害三层继续共用同一 Glyph-only，并保留各层已有 enabled/color/material/alpha。
- 最小验收：同画布/同 UI 尺寸并排比较上一候选、80% 候选与原生普通小图；可见内容宽高应约为原候选的 0.80（容许抗锯齿边界 1 px 偏差），居中无偏移。检查实际 24/32 px 音头和连梁仍可读；确认普通/Guard/Standby、原版动作骰壳尺寸不变，颜色/复用恢复无回归。其他已通过且不受影响的验证证据继续使用。

## 2026-09-08 原版材质回归（当前最终视觉合同）

### 亲看对照与诊断

已重新查看当前 `SteriaBuild/VisualAssets/MusicDice/Card.png`，以及 `output/music-dice-ui/native-sprites/CardAttack_0_AfterIcon_0_8.png`、`CardAttack_1_AfterIcon_0_9.png`、`CardAttack_2_AfterIcon_0_10.png`、`CardStandby_0_AfterIcon_3_10.png`。当前图像是均匀暗蓝灰填充、等粗单层六边线与极整齐的浅白音符，读起来像现代矢量标牌。原版的关键不是‘六边形’本身，而是：黑暗且不均匀的内底、相邻两层有亮度差的框线、轻微内分面线、局部饱和亮边、外围不规则粗笔刷与破边、亮处和暗处有明显节奏。Slash/Penetrate/Hit 三张外围笔刷也不是同一个完美规则描边；Standby 以同类材质改为金黄，说明材质层次与骰种色彩是两回事。

### 唯一制作路径：原版无中心壳，先验空底，再合原创符号

采用此前已实际查看的原版 **`Dice_6.png` 无攻击中心骰壳**作为底框来源：其原生灰阶六边壳包含外围笔刷、亮暗边线和内部结构线，没有 Slash/Hit/Penetrate 中心。主线程负责确认该原版空壳的精确资源出处/导出回执；实现使用这份明确的无中心位图进行离线作者制作，最终仍烘焙嵌入 PNG。它与原版 `AfterIcon_*` 属同一种视觉语言，`AfterIcon_*` 只作为严格的同尺寸材质参考，**禁止从完整攻击图标取内部像素、清白、inpaint 或扩散补底**。

这条路径取代自绘单线平面底框，不再补救现代标牌轮廓。不得沿用 SDF 平面六边形后仅叠一层 glow 声称达到原版风格，也不把原版整幅攻击图像盖上音符。素材没有攻击中心，因此空壳从来源上就不可能包含攻击剪影。若精确原版空壳无法确认，报告这一个具体缺口，不能静默退回 Slash 图。

### 材质、轮廓、亮度与大小

- **原生层次保留。** 保留空壳所有笔刷边缘、暗部缺口、双层边线及细内分面线；不描成等粗平滑轮廓，不加规则第二个 UI 徽章。内部接近黑色，不能重新填成均匀 `#223541` 色块。原先禁止内分面、双边、边光的要求作废。
- **低饱和蓝灰仍是色相，不是统一明度。** 暗底约 `#090E13` 到 `#17242E`，主要框面落在现有 `#8FAFC4` 蓝灰方向，最亮边线可到 `#C9D8E1`，不要把每个像素提到同一亮度。以原图灰阶/alpha 分布控制输出：暗处保持暗，刷痕半透明仍半透明。保留局部高光峰值和衰减，外刷痕整体低于主框亮度。
- **边光只依附主边线。** 为匹配原版 `AfterIcon` 的柔亮边，可从原版空壳的高亮边线生成一层很弱的近边亮度过渡：实际 32 px 显示向外约 0.5..1 px，亮度低于实线；不得用均匀环形光圈包边，不得把内部照成发白色块。主框仍清楚，笔刷仍有断续，不能模糊全部纹理。
- **中心仍是同一个原创双音符。** 保留两枚不等大的斜音头、两杆、上扬连梁这一已确认结构，不换回原版音符/字体。当前过于机械平直的肩部可作轻微不对称与收尖，调整量限约 100 坐标中的 1..2 单位；连梁与音杆连贯，不制造缺口。颜色主体柔白 `#D7E1E6`，局部笔锋可略亮到 `#E2EBF0`，根部略暗到 `#BDCED8`；很轻的笔触明暗使它与框同材质，不能变成厚描边、阴影贴纸、Emoji 或装饰性碎屑。原版中心本身亮而明确，不能为了‘融合’让符号灰到读不清。
- **大小锁定。** 仍保持刚验收的 80% 可见尺寸，Card/BlankFrame 256×256、Glyph-only 128×128、中心 pivot 和 UI transforms 不变。新原版空壳按已接受候选的可见包围盒匹配一次，不再对结果额外乘一次 0.80，也不能因原壳 alpha 边距不同重新撑满画布。字形与壳的留白关系以当前 80% 候选为尺寸基准。
- **应用范围不扩展。** 卡面/详情用原版材质空壳＋原创同中心；动作两处/伤害三层用同一个原创中心-only。原版动作大骰壳不动，伤害 enabled/color/material/alpha 保持原状。稀有度卡框、费用、正文、Guard/Standby 与所有战斗规则保持不变。
