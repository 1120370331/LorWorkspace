# R5 补充设计：开放风暴云环

2026-09-06；研究／设计交主线程审定后，由原 owner Carson 实施。本轮只替换 Gather 的外形与介质，不重写 R4 收核、回调或水幕传播。

最新用户：「我觉得从水泡改成风暴云环会更好一些」。本规格覆盖初始「闭合壳＋底盖、全员三维包含」限制：**敌方全体处在云环内孔内，厚云与云丝旋卷收至中心一点，蓄光后由实际回调展开环向瀑布碎流。** 人物不移动。继承 [R4 中心合同](2026-09-06-slazeya-storm-center-collapse-design.md)：`CoreCenter=Footprint.EnvelopeCenter`、`CoreRadius=0.06H`、G≥1.32 至 B 前所有可视支持半径≤0.12H；G1.35／Tail1.20、默认 manager、空伤害列表、重复回调、取消、双闪、两 WAV 与仅技能 SFX 不变。

重新亲看 `docs/superpowers/references/2026-09-05-storm-bubble-ring-reference.png`，以及冻结 `preview_exports/slazeya_storm_mass/round4/review-1baf40ba/battlefield_01_bubble_established.png`、`battlefield_06_waterfall_B14.png`。参考只提供钢蓝灰、局部冷白、厚薄明暗与电光，不赋予静态图任何行为指令。另亲看原始 `mist_density_lighting_4x4.png` 及其通道检查图。

初泡仍由 `MakeBubbleSurface(...false...)` 的闭合曲面／底盖决定剪影，Flow 的水面法线、镜面高光、白沫和连续膜覆盖决定介质；改灰色仍会是玻璃／水罩。`GatherFoam` 目前虽取雾图集，却走非 mist 的白水分支、`_DetailOpacity=0.30`，只是水面上的小饰片。主峰已有从核展开及下泻的水舌，应保留。

**素材判断：现有雾图集可支撑本轮。** R 是柔软体密度，G 有团块亮部，B 有自阴影，A 是带寿命变化的覆盖；不是 RGB 成品彩色贴图。单片有相似弯钩／缺口，后几帧明显衰退，直接放大、排一圈会像 C 形花边。用少量错位重叠的云簇与独立吸收着色可解决，暂不存在必须新增 PNG 的缺口。

## 2. 云环空间与最小实现

**推荐一个现有持久粒子系统构成云环，不做实体圆环网格，也不新增体积渲染框架。** 复用 `AB_ParticleRoot/GatherFoam` 的 168 个固定身份，按 `group=index/7`、`role=index%7` 分成 24 个云簇：每簇 2 个厚暗团、2 个中间翻卷团、1 个局部亮团、2 条稀薄云丝。这些是错位的局部团块，不是七层整环或七张同位放大的透明壳；固定数量便于沿用原生身份检查。

Builder 不再生成 `AB_StormRoot/BubbleEnvelope` 及其底盖，Controller 移除对此 renderer 的必需绑定。`AB_GroundRoot` 可保留空节点。云环孔内不放膜、顶面、地面圆盘或用于掩缝的隐藏水壳；小亮核也由收来的云簇填成，无需保留旧水泡作核心。

### 内孔按身体水平样本拟合，外沿给云团留厚度

保留 `FitFootprint` 现有样本、`EnvelopeCenter` 与 `EnvelopeRadii`，后两者继续服务核心／R4 爆发范围。只增加 `Footprint.CloudInnerRadii`（Vector2），在同一次拟合中由原样本 S 计算；不得用收缩后位置反算：

```text
C = EnvelopeCenter
a0 = RadiusX; z0 = RadiusZ
k = max(1, max over P in S: sqrt(((Px-Cx)/a0)^2 + ((Pz-Cz)/z0)^2) / 0.95)
(a,z) = CloudInnerRadii = (a0*k, z0*k)
E(theta) = (Cx+a*cos(theta), Yring(theta), Cz+z*sin(theta))
N(theta) = normalize((cos(theta)/a, 0, sin(theta)/z))
cloud spine = E(theta) + 0.45H*N(theta)
Yring(theta) = GroundY + H*(0.48 + 0.14*sin(theta) + 0.035*sin(3*theta))
```

全部身体／脚头样本的 XZ 投影位于内孔椭圆内，归一化半径≤0.95。云簇相对 spine 的偏移加卡片可视半对角，早期限制在半径 0.45H 内；由此不会侵入该内孔。外围可以缺齿、透气，整体必须围绕阵型四周。高度无需盖过头顶：原相机近侧（−Z）略低、较薄，远侧较高且在人物后方，头部和上躯干通过开放空间直接可见。异高个体不再把云环抬到所有人头顶之上；核心仍用原 C，故云团会在收缩时同时向 C.y 聚拢。

**标准 H=6 的具体界限已按当前 `PreviewBodies` 核算**：内孔半轴为 **9.60×7.60**，身体 XZ 最大归一化半径约0.93437，故 k=1；spine 外偏2.70，整个云簇支持半径最多2.70，云环整体外沿 X/Z 半跨度不超过 **15.00×13.00**。这不是把旧13.17×10.43椭球再加厚。C.x=10时右端≤25；原正交相机中心x=2、orthographicSize=13.8、1280×720的右界为26.533，理论右侧保留约 **40px**。此为几何预算，不冒充已渲染结果：原生初环两帧仍须确认主云支持距画框≥24px，薄云丝不得越框。非标准阵型重新由S算k，优先减局部云厚／支持界；不压缩内孔到身体样本之外，不为标准场景改镜头。

云团起点尺寸：厚团约宽 0.55–0.65H、高 0.35–0.45H；错位约 0.03–0.05H；次团较小；云丝约长 0.45–0.70H、宽 0.08–0.14H，朝周向切线拉长。实际偏移与尺寸组合须满足上述 0.45H 支持界，不能把所有最大值相加。三维位置有径向、上下与前后错位；大团轮廓叠小卷边，云丝接到下一簇，不能全是同大小圆棉球。

24 簇角距做稳定的小抖动（≤基础间距的20%），四个宽强区的厚度／透明度约为弱区的 1.3–1.6 倍；细节不按固定齿轮重复。近侧降低竖向尺寸与 alpha 约20%，不要切掉整个近侧半环。保留原相机／H／阵型；若外沿裁屏，先在上述范围内减外侧团厚，不通过缩人物或拉远镜头掩盖问题。

## 3. 独立云材质与旋卷收核

新增 `UnityProject/Assets/Shaders/SlazeyaStormCloud.shader`，名 `Steria/SlazeyaStormCloud`，仅赋给这个云环粒子系统。采用现有 Particles 的顶点流与 4×4 图集取样、半 texel 内缩、双帧插值，保留 `Blend One OneMinusSrcAlpha / ZWrite Off / ZTest LEqual / Cull Off`。以 CPU 明确相位、固定 seed 与材质参数驱动；不引入 raymarch、3D noise、深度纹理依赖或场景灯。

| 层次 | 着色／运动起点 |
| --- | --- |
| 厚暗团 | `_CloudDark=#283642`，中层 `#536674`；G 控制宽亮部、B 加自阴影、R 高处略吸收，厚处偏暗而非越厚越白。单片 alpha 起点0.30–0.48。 |
| 受光翻卷 | `_CloudLight=#91A4B2`，仅最高少量 G 亮部到 `#DCE5EB`；单片 alpha 0.22–0.38。明暗由大团内部形成，禁止整圈描边、菲涅尔或水面镜面。 |
| 云丝 | 同色系、alpha 0.08–0.18；切向拉长，疏密与速度不同，局部有缺口，不能变成一条均匀细圆线。 |
| 体积错觉 | 由三维错位、遮挡、密度吸收和图集中 G/B 的明暗共同形成。单像素常用2–4个有效团块重叠，不让7片都同位饱和；建议云系统内部用 Distance 排序，保留场景深度。 |
| 局部光变化 | 灰蓝中层随显式 `_Phase`／seed 变化约±6%，两三股缓慢光暗沿环传播，Gather 常态 emission 为0。正式雷光只沿用 B 附近两闪，云 shader 接收现有局部光位置／能量，不新加雷击或音效。 |

颜色示意可从 `illum=saturate(0.20+0.75*G-0.30*B+localVariation)`、`color=lerp(dark,light,illum)*(1-0.25*R)` 起调；高 G 的少量亮团另混冷白。覆盖采用 **`A * 单片强度 * 整体显隐` 一次**，不再乘 R、A 或旧寿命渐变。`i.color.a` 可承载角色层强度与聚合衰减；当前通用 mist 分支不消费它，不能只换 `_Grid.w=1` 就期待单片调色生效。原尾雾／喷沫 shader 保持自身合同。

Gather 持久云从图集较完整的 1–7 帧选择稳定 seed 帧及相邻插值，不随真实等待寿命跑到12–15帧消散，也不循环整套消散动画。小幅局部 UV 扭动（≤0.008 个 tile）可复用 `water_flow_rg.png` 的 RG 方向数据，始终在当前 tile 的安全范围；云的主要旋转由真实位置与轮廓搬运表达，不靠高速滚动纹理。错位团补掉单片弯钩中心，不直接把弯钩高亮成重复白 C。

**保持 R4 的时间与径向收束函数。** 0–0.18s 在完整环位置显现；0.18–0.82s，簇沿椭圆绕行约0.25–0.40rad，各层略有差速。0.82 时捕获每个身份的云起点和形状相位，复用 `CollapseAt`、`CollapseOffset` 将实际团块和云丝一起旋进 C；继续冻结大形，仅保留小幅内部明暗，不重新计算游走的初始半径。

为避免平面云环最后变成微型空心圈，给7种 role 设终点内缩系数：两种取0，其余取0.35–1.0。具体位置使用 `C + CollapseOffset(P0-C,c,H) * lerp(1,roleEnd,c)`；仍单调缩小且最终都≤0.06H，其中部分云团真实到达 C。尺寸同步插值到不超过0.05H的方片，关闭所有 velocity stretch；终点中心距＋半对角≤0.096H，给0.12H总上限留余量。若使用非均匀卡片，原 `GetCurrentSize()` 单值验证须改成实际二维半对角／四角支持范围，不能漏测云丝长边。

1.20–1.32s 以同一云材质的 `_Charge` 把收来的内层逐渐压成冷白亮核、外层留短灰蓝边，控制重叠不满屏发白。核内没有孔或第二亮点；等回调时保持 R4 的亮度／清理合同。停用早期从旧 `BubblePoint` 出生的 `CrestSpindrift` 水滴；本轮不新增自由云发射器，168 个持久云已承担主体与尾丝，因此无需让外围新存量追赶收核。

## 4. 接入现有水幕爆发与修改边界

`TriggerBurst` 捕获各云身份的实际核内位置，B 后继续用该位置向原 `ExpandedRingPoint` 插值，`WaveProgress` 仍为 `smoothstep(B/0.23)`。同一个粒子材质可用 `_WaterMix=smoothstep(B/0.10)`，将局部云阴影平滑过渡到 R4 冷白湿沫读法；位置、seed 和支持尺寸不中断。核的短高亮继承 `1-smoothstep(B/0.065)`，因为现有 `Charge` 在 B 后返回0，不能直接令材质黑掉。

原 `RingJet` 水面从核连续展开，0.10–0.23s 成为主形；云团变成沿水舌携带的湿雾／凝结碎沫并按原尾期退去。保留 `ExpandedRingPoint`、`WaveVelocity`、四股水舌、瀑布下泻、两闪与落点雾的原路径；所有新增云的 B0 支持也在0.12H内，不能在远端重新生成一圈云来衔接。无需把尾段瀑布也改成纯烟，用户此前要求仍有效。

## 5. 少量原生与目视验收

1. **初始开放环**：沿用单人、五人、1.8H高个体、抬脚0.35H样本，G=0.25／0.80 验证全体样本 XZ 内孔半径≤0.95、云支持位于内孔外；标准五人使用上述15×13外沿预算与≥24px画框余量。每个30°方位扇区至少有有效主云团，结合原生图确认其不是透明占位；允许局部边缘缺口，不允许缺一整象限。同镜头确认头／上躯干清楚、内孔无膜／顶盖／底盖，不能只通过一个足点或 shader 名称证明。输出一份 `cloud-ring-fit.json` 和五人初环侧视，替换旧“闭合壳全员包含”证据。
2. **材质与体积**：1280×720、H=6、原相机／代理阵型不变，检查初环两时刻与半收帧。必须能读到厚暗团→受光卷边→稀云丝，边缘有局部破碎；拒绝硬轮胎、均匀白烟、重复 C 形花边、灰水面、薄亮圆线或填满内孔的雾盘。主张云厚度须由正面和一次侧视共同支持，不靠加白整体 alpha。
3. **沿用核心／传播实测**：更新168身份的初始取样后继续运行 `VerifyFoamTransport`、`InspectCoreSupport` 与波前检查，采样 G=1.28／1.333／1.35／等待2.0，B0／B+1、2、4、7、14帧。包括所有云卡片长边、云丝、光晕；仍为同一 C、0.06H核心、0.12H全部支持，B0无外围出生，云与水从核连续接上，不能微型空心环或黑帧换材质。
4. **候选与收尾**：新 round5 原生序列、初环／半收／核／B14／下泻／清空代表帧及新的 `review-<hash>`，不得覆盖 round4 冻结目录。稳定候选执行受影响源码／Unity API／新shader／Bundle回读及Release检查，复用现有 manager、双闪、SFX、取消和Tail1.20清理场景确认无回归。旧46项PASS不是新云层的证据；Carson交改动、命令、预览与剩余问题，独立评审和主线程接受后再按原合同游戏同步。

本研究仅写本补充设计，未修改实现、资源、构建或部署，未派生代理。若素材组合后仍无法消除特定弯钩轮廓，报告对应帧、云层和原生图再提出纹理缺口；当前方案不要求新图。

## 附录 A：可读自旋与随风平流的连续云密度

用户补充：「云环可以带自旋，并且每个地方密度用类似云的模拟不均匀密度」。本附录增强第3节：**固定图集帧与7种角色alpha只提供素材和层次，不能替代动态空间密度。** Carson可并入当前实现，不需要停工等待或引入真实流体模拟。

**整体转，内部也翻。** Controller让簇的角参数沿固定椭圆前进，`theta=theta0+SpinAngle`，G=0.18–0.82起点角速度0.65rad/s；G=0.25到0.80可辨识同一大云簇前进约20°。用第2节的 `E(theta)+0.45H*N(theta)` 重算位置，不能直接旋转整个椭圆根节点而使内孔轴转过人物／外沿越框。云丝略快、厚团略慢（±10%）；单簇内部可加约0.02–0.03H的法向／上下环绕翻滚，周期约0.8–1.2s，计入原0.45H支持预算。到G=0.82捕获实际位置，之后由原 `CollapseOffset` 的0.55rad旋进接管；不在收缩点外另加位移而破坏单调收核。后续内部翻滚由着色继续表达。

**一个共享三维密度场，而非逐片随机闪alpha。** 在现有 cloud shader 的 vertex→fragment 传世界位置 `pWS`；Controller经现有 MPB 接入同义参数 `_CoreCenter`、`_CloudInnerRadii`、`_Height`、`_CloudTime`、`_CloudSpinAngle`、`_Collapse`。时间沿现有显式技能时钟，禁止改用 `_Time`；所有簇用同一个场，seed不偏移整套噪声坐标。下式为最小接线，`noise3D`用固定格点hash、平滑三线性插值的连续值噪声即可，无新增贴图：

```text
(a,z)=CloudInnerRadii; r=(a+z)/(2H)
Q=((pWS.x-C.x)/a*r, (pWS.y-C.y)/H, (pWS.z-C.z)/z*r)
Qw=rotateY(Q,-CloudSpinAngle) - (0,0.10,0)*CloudTime
Qw+=0.06*(sin(0.8*Qw.z+0.9*t), sin(0.8*Qw.x+0.7*t), sin(0.8*Qw.y+0.8*t))
rho=0.55*noise3D(0.9*Qw)+0.30*noise3D(2.4*Qw)+0.15*noise3D(6.0*Qw)
```

其中 `C=CoreCenter`、`t=CloudTime`，扭动项同时从扭动前的Qw求值。这里的旋转按 `x'=cos(a)*x-sin(a)*z; z'=sin(a)*x+cos(a)*z` 定义，与theta增角一致；复用现有C#反号约定的 `RotateY` 时翻转实参，保证采样逆风、图案顺风。三档约为H量级厚团、0.4H翻卷、0.17H碎边；逆旋转采样让同一浓淡结构随整体风旋平流，缓慢纵向平流与小幅扭动形成内部翻滚。以连续笛卡尔坐标取样，0／2π和跨卡片处没有接缝；不能用每帧随机数刷新密度，也不能只滚动每张卡片的独立UV。

用 `alpha=A*角色强度*显隐*lerp(0.35,1,smoothstep(0.28,0.72,rho))` 起调；A仍只用一次，新增因子是动态密度，不重复乘烘焙R。rho同时轻调吸收／局部受光（浓处更厚暗、薄处透亮），避免只有整片亮灭。近侧／弱区保留云丝，密度低谷不能抹掉一整象限；大团高低密度区域必须肉眼可跟踪。随Collapse将动态调制幅度收敛到原幅度的约15%，核光仍由Charge主导；不除以趋零的收缩尺度，不扩大卡片或额外发射云。B后的WaterMix、波前、正式双闪与SFX保持正文合同。

最少补看G=0.25／0.55／0.80及0.55附近三个60fps相邻帧：①同一厚云簇沿环前进，而团内亮暗卷动不与整簇完全锁死；②浓淡块连续随风移动、相邻团交接自然，无逐片跳闪、静态贴图滑板或匀速刚性轮胎；③这几个旋转位置仍满足内孔、角向覆盖和≥24px画框余量。随后沿用原G末／B0支持检查，核内全部≤0.12H、原时序不变。短序列和既有seed位置记录足够，不另建流体／资产／测试框架。

## 附录 B：宏观体积云承载纠偏（覆盖卡片主体限制）

用户再次明确：「你这个云也太散了，根本不想‘风暴中的大体积云’」。已亲看参考图、R5.1冻结 `round5/review-2074a66c/battlefield_01_cloud_ring.png`，以及本次读取的R5.2本地 `round5/battlefield_01_cloud_ring.png`／`cloud_ring_five_side.png`（manifest为round5.2、Bundle `A3850C28…`，尚非稳定handoff）。前者是羽毛薄雾串，后者放大后仍是相似半透明棉球串；侧视不足以形成云墙。当前shader把贴图A转换成光学厚度再放大，仍只在卡片表面采样一次，没有视线穿过云体的长度或朝光方向的遮蔽；此问题不能继续靠alpha修补。

**本附录明确撤销「只用168卡片」「主云全向支持≤0.45H」「禁止raymarch」三个自加限制。** 采用10个交叠的各向异性宏观体积云（允许8–12），168粒子仅做云丝／碎边／输运细节；关闭粒子后主体仍须是一道有显著高度、彼此连成整体的风暴云墙。保留开放内孔、旋卷、原C与收核／回调／瀑布／双闪／SFX合同，不增加全场天气、真实流体、PNG或资产框架。

### B1. 尺寸：径向留孔，纵向形成云墙

仍令 `E(theta)=(Cx+a*cos(theta),Y(theta),Cz+z*sin(theta))`，`(a,z)=CloudInnerRadii`，N为内孔椭圆外法线、T为其单位切线、U为世界Up；中心 `P=E+0.45H*N`。不继承旧 `EnvelopeRadii` 缩放。

| 宏观云参数 | 有界起点 |
| --- | --- |
| 切向半长L | 0.8–1.0H；10体近似均匀分布，小幅错开角度，连续几个云体不要同尺寸。相邻主体重叠约25–40%，薄连接处也有真实体积。 |
| 径向半厚R | 0.32–0.40H；只限制径向，不用它砍掉高度。中心径向微动≤0.02H。 |
| 竖向半高V、中心高度 | `V=H*(0.60+0.10*sin(theta))`，`Y=GroundY+H*(0.75+0.10*sin(theta))`；近侧较低，远侧较高，整段实体高度1.0–1.4H。 |
| 剪影 | 以交叠椭球作为密度载体；低频浓淡决定大云腹，边界局部侵蚀，细噪声不把主体打碎。不描每个椭球的独立亮边。 |

**内孔与画框核算：** 椭球沿N的最内点仍在E外至少0.05H，切向L与竖向V均不改变这个支持平面结论，故不会因增加高度／切向长度侵入内孔。H6、a/z=9.6/7.6时，按L=1.0H、R=0.4H和上表高度，以3600个角位置采样解析椭球投影：原1280×720正交镜头下范围约x=462–1235、y=77–502，右边余量约45px；覆盖整圈自旋位置，满足24px预算。此为设计核算，原生仍须复验。初期按实际椭球支持 `sqrt((L*T.x)^2+(R*N.x)^2)` 等投影计算，不能将包围盒空角当可见密度，也不能在画框外裁云来通过。细云丝同样不得越框。

### B2. 有限体积积分与透明接线

外部技术依据已实际读取：[Sebastian Lague / Clouds.shader](https://github.com/SebLague/Clouds/blob/master/Assets/Scripts/Clouds/Shaders/Clouds.shader)（[MIT许可](https://github.com/SebLague/Clouds/blob/master/LICENSE)）。采用其射线与包围区间、Beer–Lambert透射、朝光方向采样及低透射提前退出方法。该实现是透视相机出发的全屏后处理，使用相机深度、3D纹理、`ZTest Always`和`_Time`；这些接线不移植。本项目改为局部mesh proxy、现有程序3D噪声和显式时钟，尤其不能照抄其透视射线用于正交预览。

Builder建立 `AB_StormRoot/CloudMacroRoot` 和10个低模椭球proxy，根为单位缩放，各体的局部轴为T/U/N与L/V/R；可复用一份单位球mesh。新增 `SlazeyaStormCloudVolume.shader`（建议target3.5，实际Unity2019.3.15f1须supported／无shader错误），使用 `Cull Back / ZTest LEqual / ZWrite Off / Blend One OneMinusSrcAlpha`，只绘制前表面并在其内部积分。相机位于这些局部proxy外，原始云墙及收核两状态均如此。

**射线合同：** `unity_OrthoParams.w` 区分投影。正交时 `D=normalize(-UNITY_MATRIX_V[2].xyz)`，`O=Psurface-D*dot(Psurface-CameraPos,D)`，每像素起点不同、方向相同；透视时O=CameraPos、D=normalize(Psurface−O)。将O、D变换进单位椭球：O用点变换，D只用逆线性变换，**不可再normalize局部D**，这样二次方程交点t仍以世界长度计量。解析求单位球的入／出t，限制在相机前方区间，再按世界步长积分；小核时宜重定位射线原点到proxy附近并保留t偏移，避免远原点／小尺度造成判别式精度损失。

**共享体密度：** 把现有 `cloudHash/valueNoise/cloudFbm` 与逆自旋／平流坐标提取为局部 `.cginc`，供云丝shader和体积shader调用。每个体提供世界中心与三个逆尺度轴，最多12项固定数组。对采样点算各椭球软包络 `e_i=1-smoothstep(0.55,1,dot(local_i,local_i))`，合并 `E=1-product(1-e_i)`；以共享低频场形成浓厚主体，细频只侵蚀边缘，内部密度保留约0.6的相对底值。各proxy只积分自身份额 `rho_i=rho_union*e_i/max(sum(e_j),epsilon)`，避免交叠处同一团云被重复加厚成黑接缝。噪声只需在世界点求一次，不为12个包络各算一套噪声；方向光遮蔽使用合并密度。透明分体合成的散射颜色仍是近似，必须看交叠处与侧视，不能宣称等价于精确体积排序。

```text
ds=(tExit-tEnter)/viewSteps               // 世界长度，使用中点采样
dTau=(sigmaT/H)*rho_i*ds                 // sigmaT起点3–5
dA=1-exp(-dTau)
L += T*dA*(ambient + litColor*Tlight + coreEmission)
T *= (1-dA)                             // T<0.02可提前退出
output=(L,1-T)                          // 已预乘，禁止再乘一次alpha
```

光方向继续效果自有 `normalize(-0.4,0.8,-0.45)`，不新建Light；向光3次短程密度采样得到 `Tlight=exp(-integratedLightDensity)`。推荐默认32个视线步，每4步更新一次3采样光遮蔽并平滑使用，总约56次密度求值／命中proxy像素；硬上限48个视线步，先剔除空区，光采样可只用较低频。固定中点而非逐帧随机抖动；不加蓝噪声资产或时间累积。记录1280×720原生GPU耗时／硬件和过绘范围，性能不足先降到24步／减少重叠，不退回卡片或牺牲宏观高度。以上是可测起点，不预报帧率。

厚云腹取深钢蓝灰、低环境填充（约0.12–0.20），受光卷边由Tlight升亮至冷灰白；不以椭球表面法线的镜面高光造“云泡”。典型0.8H厚路径、平均密度约0.6、sigmaT=4时透射约0.15，薄边保留透光；变化来自路径长度和遮蔽，不是调高整片alpha。

**遮挡边界：** 每个proxy独立renderer，保持Character层及现有角色排序约定，让Unity按当前相机排序，不能将整环强制画在所有角色之上或按battlefield镜头写死前后顺序。前表面ZTest可处理初始云墙与内孔人物分离的情况；它不能精确截断“物体位于一个体积内部”的积分，也不能独自解决不写深度的透明角色。此处保留明确近似，需原生人物前后及实战排序验收；收缩穿过角色仍是授权行为，不为追求精确截断开启全局深度／新后处理。若出现明显错盖，按实际角色材质／排序证据修正，不能以调alpha掩盖。

### B3. 主云体必须参与收核与既有爆发

0.82前宏观中心沿固定椭圆自旋，基轴T/N随theta变化；共享密度同向平流，云丝翻滚仅作外缘补充。0.82捕获每个体的完整位置／轴，之后中心用原径向收束并乘 `lerp(1,0.2,c)`，终点中心距≤0.012H；轴统一缩小到最终包围盒半对角≤0.045H，故**每个proxy全角点**距C≤0.057H，主密度在0.06H核心内，全部云丝／光晕继续受0.12H限制。旋进基轴与中心同向，尺寸连续下降；不用“关大云、另开亮球”。

有限终尺度可用于补偿消光系数（随均匀缩放s约乘1/s），避免云体缩小时仅因路径变短而消失；s有上述正下限，不能除以1−c。云内发光由原Charge压成单一实心亮核，体积重叠权重避免10倍亮度堆积。B后浓缩云在原0.065s核退光窗口内把权重交给从该核展开的原RingJet／湿沫，所有宏观体始终留核内并按时关闭；不把10个大proxy直接弹回外围。水幕传播、四股瀑布、两闪、SFX、G1.35／Tail1.20与manager不改。
