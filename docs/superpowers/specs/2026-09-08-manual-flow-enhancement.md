# 流：手牌主动强化与下幕获取

日期：2026-09-08。

## 用户合同

有激活流 Buff 的当前玩家角色，在手牌右侧显示流图标与圆形棱镜半透明底座按钮。点击按钮，再点击手牌，恰好强化一次。可重复操作至书页与被动原有上限。可用流必须大于等于所需骰子数；相等允许强化并耗尽。一般产流在下幕开始到账，已经延迟的来源不能再多延迟一幕；安希尔「自我之流」保留当幕立即获得5流。

神脉原有获取倍率、额外一次强化、伤害产流、耗流强壮和输拼扣流保持。只按用户要求调整流的获取时机。

## 规则与接入

- 普通强化沿用既有非 Standby 骰子范围：反击不参与、不计费。每次消耗参与骰子数量，每颗 +1。普通上限1，神脉额外+1；洋流/风暴基础4，百川基础2。界面明确显示所需骰子数，纯反击牌提示不可普通强化。
- 记录绑定当前 BattleDiceCardModel 和单位，不使用卡牌ID或UI槽位作为身份；共享XML保持不变。同名手牌独立，跨幕保留，实际使用后清除。
- 布置阶段扣除预留额；开始战斗后，仅对当幕新增投入提交一次耗流被动与流转记录；未装备书页保留强化，不能因未使用退回流。历史投入与新增投入分账。这样撤换免消耗书页不会刷耗流被动。退回预留不属于获取流，不翻倍、不延迟。
- 战斗时只绑定已经锁定的强化记录，不再重新分配或二次扣除普通强化费用。输拼扣除剩余流，不回溯已支付的强化。
- 流转下幕返还实际支付额，不翻倍。免消耗仍沿用“视为消耗”触发被动，但不产生虚构返还。
- 无尽的尽头放入友方行动槽后，布置阶段即可识别同阵营免消耗；加牌释放已有普通强化预留，撤牌重新计费。不足时保留可负担层数并提示撤回不足部分。群攻的特殊全额投入不被普通免消耗豁免。
- 百川的虚弱、流血和洋流追加防御骰读取手动强化次数。百川额外8流的重复攻击仍为独立使用时效果，保留随机目标和每幕一次约束。
- 倾覆通过同一按钮投入全部可用流，一幕至多一次；保留每8流+1威力和命中追加投入额伤害，不获得普通强化加成。未手动投入时不自动清空余额。
- 敌方和不可控角色由准备阶段自动规划调用同一强化入口：按原始光芒费用降序、同费按牌面骰子总数升序，完全同优先级保留行动槽顺序。优先牌尽量强化至原有上限或余额不足，再尝试后续牌；余流保留。采用原始费用，避免敌方临时0费使排序失效。普通玩家角色不自动强化。重复规划先释放该AI单位尚未提交的预留再按最终卡组重排，不重复触发消耗收益。
- 代行保留资源不减少、普通强化额外威力以及流转不返还的规则。

## 获取时机

CardAbilityHelper 先计算一次来源倍率，战斗中的新增流进入“下幕流”记录。下幕开始结算已存储数值，不再次翻倍。原有 OnRoundStart 来源、SlazeyaFlowNextTurn、AntieFlowNextRound 和流转返还仍在原定幕初结算。形态切换保留已有资源、代行恢复资源快照属于状态还原，不是新产流。

## 交互与验证

右键、Esc、切换角色、隐藏手牌、进入战斗会退出选择模式。强化点击拦截原版出牌选择；成功后保持强化模式，可连续点击；归零或失败时退出。卡面显示加成点数和+X，独立恢复自身修改的文字，不改原版卡色、乐章图标或共享骰子数据。

机制验证加载实际候选 Steria.dll 与原版 Assembly-CSharp.dll，覆盖严格门槛、神脉上限、实例隔离、重复绑定、衍生查询、被动只提交一次、免消耗撤销、返还与翻倍、已有延迟来源、群攻、跨幕清理、敌方规划。

UI夹具加载候选DLL和原版手牌组件，在Unity中调用实际按钮与被Harmony拦截的OnPdSubmit。夹具使用简化布局，不能替代完整游戏战场的分辨率与遮挡验收。

## 立即显示补充（2026-09-08）

手牌对应单位（选中优先，否则悬停）有激活流就显示按钮。可见性不再依赖准备阶段、玩家阵营、可控或非混乱状态；强化操作仍限准备阶段选中的可控玩家单位。手牌初始化、绑定、列表更新与流实际到账后同步刷新，不等待额外点击或新一帧Update。非操作状态按钮可见但不可点，零流或隐藏手牌时隐藏。

## 自我之流待到账显示补充

自我之流恢复为本幕立即获得5流。其他新待到账流仍使用流图标，因此手牌按钮同时承认激活流和待到账流。有待到账量时显示“可用 N / 下幕 +M”；可用为0时显示按钮但不可强化。公共产流入口完成后同步刷新，不能等下一幕才首次显示。到账后恢复普通流数量显示。

## 操作反馈补充

成功调用原版CARD_APPLY并让当前书页边框短暂发光；失败调用原版PlayVibeCard（抖动与CARD_LOCK）并显示原因。骰子范围与(+X)保持同字号分两行。强化图标与×Levels接入原生卡牌Buff图标栏，移除立绘胶囊；未使用跨幕保留，使用后的手牌状态与标记清除，本次攻击仍使用其快照。
