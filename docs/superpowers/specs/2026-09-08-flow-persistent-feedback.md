# 流强化：持续选牌、持久强化与操作反馈

日期：2026-09-08。覆盖此前“成功退出”“失败保持”“严格大于”“幕初清除强化”的约定。

## 最新用户合同

- 可用流大于等于参与强化的骰子数时允许强化。
- 成功后继续处于选牌强化状态，可连续点击；归零或强化失败退出。主动取消入口保留。
- 书页强化跨幕保留，实际使用后清除。当前行动仍获得锁定加成，下一次重新使用不继承；同一次使用产生的百川重复动作继承本次行动快照，不重新扣费。
- 新投入只结算一次耗流收益与下幕流转返还；跨幕、AI重排和免消耗切换不能重复计数或退还历史投入。
- 成功瞬间播放原版CARD_APPLY并出现短暂青白卡框发光。失败使用原版PlayVibeCard（CARD_LOCK和抖动）并显示原因，不重复播音。
- 骰子范围与(+X)同字号分两行显示，检查高度与相邻行，不使用65%小字。
- 被强化书页使用原版Buff图标区显示流图标和×Levels；真实卡面可见，不依赖立绘胶囊叠层；图标不能覆盖其他Buff。
- 自我之流5流恢复为本幕立即获得。其他待到账流也立即显示按钮，明确可用0/下幕+M，不提前使用待到账资源。

## 分工与验收

核心worker拥有FlowPlanning、机制夹具、必要行动绑定与百川继承小段。UIworker拥有FlowHandUI与UI夹具。Get(card).Levels等读取接口保持。主线程整合、核对账务和真实UI证据，单独review代理审查代表帧。

核心检查至少覆盖等额成功归零、未用强化跨两幕、使用消除但本次骰子加成保留、百川衍生继承、跨幕新增一级只结算一次、流转精确返还、免消耗/AI重排不退历史付款。UI检查覆盖成功保持选牌、失败退出、装备/锁定音入口、短暂闪光、原生图标与×次数、同字号换行不裁切、待到账显示。

简化Unity场景不足以单独证明完整战场的显示与声音；应尽可能补真实游戏的代表手牌路径，并明确未实测范围。

## 双行间距修复

禁用按邻行距离推导负行距的旧逻辑。点数与(+X)使用自然正向行距并保持原字号；仅对实际可见骰子按渲染字形边界留出间隔，空间不足时整体下移后续骰子行。隐藏预制行不参与测量。渲染前再次检查以适配原版布局刷新，复用时恢复原位置、字号、对齐、文本框大小。验证包含隐藏行贴近、极窄行距、重复刷新无累积漂移、缩放及恢复。

参考用户真实截图，夹具原生Buff标记区改至立绘上方，牌体为可容纳标准多行骰子描述的高度；不再以立绘下方的虚构图标位置代替原版布局。
