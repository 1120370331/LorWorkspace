# 战斗单位分层建模与核心书页投影

本章是**新角色与角色重制的默认制作流程**。以美术效果为第一标准，先设计独立部件，再装配动作；不再把“整个人物多动作生图 → 抠白/抠绿 → 修补每一帧”作为起点。旧教程中的九宫格与抠图方法仅用于维护历史整图资源。

**部件来源不设限制。** 每一个部件或一组相关部件，都可以带参考图交给生图接口制作，也可以直接绘制；脸型、五官、头发、身体、衣装、武器和特殊部件都适用。原版素材只是一种可选参考或复用来源。优先复用成熟的加载与装配机制，不代表必须复用原版美术；现有素材与人物气质或画风不协调时，应重绘。降低成本依靠分层与部件复用，而不是牺牲画面效果。

这里的“模型”是《废墟图书馆》的 **2D 分层角色模型**，不是 3D 网格。核心书页携带衣装，单位持有自己的头部身份。玩家穿戴或投影核心书页时，应保留司书的长相。

## 1. 制作规范：head 与 wearing

这些名称是**项目制作端规范**，不能直接当作游戏 XML 标签。游戏字段映射见第 2 节。

| 域 | 部件 | 内容与归属 |
|---|---|---|
| `head.hair` | 前发、后发、侧面前后发 | 发型、与发型绑定的个人饰品；属于人物身份 |
| `head.face` | 眼睛、眉毛、嘴；可选鼻部/脸部标记 | 表情组至少规划 normal / attack / damaged；没有对应美术时明确复用 |
| `head.facemodel` | 脸部轮廓与耳朵等基础皮肤 | 五官画在上面；与眼睛、嘴分开 |
| `head.color` | 肤色、发色、瞳色 | 参数或叠乘颜色，不是必须额外生成一张“颜色图” |
| `head.attachments` | 作为独立单位且有逻辑绑定的头部饰物（可选） | 无独立逻辑的头饰、伤疤等直接绘入所属头部部件 |
| `wearing.body` | 躯干、衣袖、裙摆/裤腿、鞋、手套等 | 可以继续按关节与遮挡关系拆分；制作时多张，默认每动作烘焙一张衣装图 |
| `wearing.hat` | 帽子、兜帽、制服配饰 | **随核心书页迁移**的头饰；位置在头上也属于 wearing |
| `wearing.weapon` | 武器本体、持握关系、必要前后层 | 无武器角色明确为空；不要为了填槽添加武器 |
| `wearing.accessories` | 作为独立单位且有逻辑绑定的饰品（可选） | 必须同时满足独立单位与逻辑绑定；纯视觉配件直接画进衣装 |
| `wearing.ego_specials` | 状态贴图、挂点、粒子/材质引用 | 按 EGO/特殊状态显隐，默认不烘焙进普通衣装 |
| `rig` / `poses` | 站位、头部/肩/手等锚点、层序、动作配方 | 制作元数据，不是新的角色器官 |

**归属判定**：换一个司书穿这张书页，它应该带过去吗？应该带过去的是 wearing；应当保留原人物身份的是 head。同一件饰品只能有一个默认所有者。礼物、书页投影、EGO 状态是不同系统，不应混为一个开关。

### 饰品独立规则（用户明确约定）

**饰品只有作为单独单位、有逻辑绑定才应该独立。两个条件必须同时成立。**

- 独立前，必须能够明确说明这个单独对象是什么，以及它绑定的逻辑行为或状态是什么，例如独立装备/卸下、状态切换、损毁或脱落。
- 仅仅在外观上是挂坠、徽章或发饰，或者为了方便改图，不足以成为独立单位。只随衣装或头部一起显示的装饰，默认画入所属部件，不增加独立饰品槽、开关或运行时对象。
- 为绘制或遮挡临时分层，不等于把饰品定义成独立单位；最终仍按所属头部/衣装合成。
- 薇莉亚当前十字挂坠属于衣装细节，直接逐动作绘入衣服，`wearing.accessories` 保持为空。

裸露手脚需要另行规划：固定肤色、手套遮挡，或可着色 skin 层。不能只修改头部肤色就声称全身肤色联动。

## 3. 两种文件：编辑源与运行时导出

```text
CharacterModels/<Character>_<Version>/
├── model.json                 # head / wearing / parts / poses / aliases
├── sources/
│   ├── head/{hair,face,facemodel}/
│   ├── wearing/{body,accessories}/
│   ├── generated_parts_rgba.png
│   └── provenance.json        # 原版资产 ID、来源、裁切坐标与 SHA-256
├── prepare_sources.py         # 可选的一次性导入
├── build_model.py             # 离线确定性装配，不调用生图服务
├── preview_template.html
├── verify_model.py
└── build/
    ├── preview.html           # 可切动作、头部、图层的自包含预览
    ├── assembled/             # 完整人物参考图；不是投影皮肤
    ├── <Name>_Projection/
    │   ├── ModInfo.Xml
    │   └── ClothCustom/       # 只包含 wearing
    ├── comparison.png
    └── poses.png
```

一个动作的身体、衣袖、武器和衣装配件通常合成一张 PNG。因此“wearing 最终是一张贴图”与“源文件可以分层”并不矛盾。这里的一张指**每个动作**，不是所有动作只能共享同一张姿势图。

如果帽子/手/武器必须盖过头或前发，普通加载器已支持 `_front.png`，应按遮挡关系另导出前层。更细的前后层与身体 skin 层可采用明确依赖 BaseMod 的扩展路径。薇莉亚 R2 的前侧手臂需要盖过头发，已输出衣装主层与 `_front` 前层；挂坠按用户要求直接画在衣服上。

## 4. 标准制作流程

1. **冻结身份与投影边界。** 写清原型的发型、衣装、武器和配件归属。先比较当前 Default 与方向明显的攻击动作；不要让生图重新设计人物。
2. **按美术目标选择来源。** 比较当前角色、原版或其他合适参考的比例、笔触、轮廓与材质。符合目标的素材可复用，不合适的直接重绘或带参考生图。使用原版 Sprite 时保留 alpha，并记录资产文件、path ID、名称、rect、pivot、PPU、textureRectOffset。紧裁图不能丢掉偏移后仍使用旧 pivot。
3. **按独立部件或相关部件组制作。** 发型前后层、脸型与一组表情、身体与衣袖可以分别带参考图制作，也可直接绘制。分组有助于保持同一部位的画风与几何关系，不要求所有部件硬塞进一张版图。不要每个动作重生整个人物。生成背景选用与部件明显不同的纯色；关节连接处有遮挡余量。
4. **统一处理背景并验收最终 alpha。** 不依赖生图接口遵从透明背景指令，优先要求无渐变、无投影、无背景纹理的纯色底，然后按背景色处理。白发、白袍不能用白底抠白；本次浅色脸部与灰绿色眼睛采用纯品红 `#FF00FF`。含品红的部件应换用其他色底。处理抗锯齿边缘时要同时去除色底污染；不能只粗暴将所有近白像素删除。最终交给装配器的 PNG 才必须有真实 alpha，并在深/浅背景上检查。若接口已返回合格 RGBA，可直接使用，不重复抠图。
5. **装配一个 Default。** 固定画布、站位、头部锚点、肩部锚点和层序。使用可重复的坐标与缩放，不按各动作的整体包围盒重新拉伸。先验收轮廓、脸与头发遮挡、袖口连接、颈部与脚底，再增加动作。
6. **复用部件建立姿势。** 移动/旋转已有部件；超出合理变形范围时，只补绘对应衣袖、手势、裙摆或侧视图。僵硬旋转可以验证装配方案，不能代替最终动作美术验收。
7. **分离导出。** 完整人物用于来宾预览；投影输出只烘焙 wearing，`head_enable=True`。来宾固定头部的注册另走已经核实的自定义头部路径。
8. **做换头检查。** 同一套衣装换上明显不同的原版司书头部，衣装像素必须不变。隐藏 head 后不能留下头发、脸或个人饰品；换 wearing 不能改五官数据。
9. **通过制作验收后再接入游戏。** 先以独立皮肤名称试装，再测敌我左右朝向、常用动作、投影后的头部保留和特殊状态。验证完成后才替换正式书页指向。

生图提示词骨架：

```text
用途：2D 战斗单位的独立部件，供后续装配；不是完整人物动作版图。
参考：现版角色，只保留指定的身份、材质、颜色与比例。
本次部件：列出确实缺少的部件；每个部件单独占格，不重叠、不跨格。
连接：肩/腕/颈等接点应有被遮挡的连接余量。
背景：与本部件颜色明显区分的纯色，例如 #FF00FF；无渐变、阴影、纹理或棋盘格。
边缘：不让背景色染到部件内部；保留浅色区域，方便后续色键处理。
保持：原服装、饰品含义、光源与统一前视/侧视约定。
排除：不属于本部件的脸、头发、身体、武器和技能特效。
```

目标是把昂贵的图像工作集中在**可复用部件**上。正常修改坐标、换头、组合衣装、导出动作都在本地完成。不要把“永远一次生图成功”作为成本假设。

### 实践记录应随制作更新

- **2026-09-08，薇莉亚：** 强调透明背景仍可能得到画在 RGB 图片里的棋盘格，反复要求 alpha 并不可靠。将生成输入的要求改成“方便处理的纯色底”，把最终 alpha 验收放到本地导入阶段。
- **白色部件：** 白发、白袍、眼白都属于必须保留的内容，不能用抠白捷径。已有合格 alpha 的衣装源直接保留；新的脸型与三组表情统一用纯品红底导入。
- **相关部件组：** 一次制作脸型、normal / attack / damaged 表情，再分别保存眼、眉、鼻、嘴。成组设计保持画风，分层保存保留独立修改能力。
- **美术优先：** 原版脸部与新发型组合不协调时，应重绘脸型与五官；原版部件可以留作换头对照，不必成为正式美术来源。
- 每次发现新的背景处理、锚点、层序或动作问题，都把适用条件、处理方式和实际验证结果补到本章或模型 README；没有验证的经验要标为候选方案。

## 5. 坐标换算：512 散图路径

### R2 返修经验：先校准局部母版，再拆层

首版虽然通过了文件与隔离校验，但动作、五官和颈部没有达到美术要求。以下规则来自这次实际返修：

- **五官不能各自紧裁拉伸后猜位置。** 脸型、眼线、鼻口、下巴和颈根先在完整头部母版中校准；再拆到同尺寸画布，各层共用同一个 pivot、缩放和旋转。局部母版可以是一组紧密相关的部件，不是重新生成整个人物。
- **颈根与头部中心是不同锚点。** 作者母版用颈根接领口；游戏自定义头部的局部原点另行换算。缩短脖子应调整可见颈段与挂接点，不移动五官补偿。R2 将母版颈根从 `(239,452)` 调到 `(248,395)` 并去除多余颈部，五官相对关系不动。
- **饰品独立必须有单位与逻辑依据。** 只有作为单独单位且有逻辑绑定，才建立独立饰品。薇莉亚当前十字挂坠属于衣装细节，直接绘入各动作衣服；祈祷与防御的手臂盖在它上方。
- **固定衣装细节要逐张画入。** 统一 U 形链圈贴到不同胸前会出现转向、长短、拳头遮挡等瑕疵。九个动作已全部改为在各自衣装中绘制链子曲线与小十字，按领口、胸部透视和动作方向设计；不再加载共用吊坠图片。防御、闪避与祈祷中，手臂遮住吊坠是正常遮挡，不应为强行露出十字而把它挪到胸外。绘制只影响衣装的已有 alpha 区域，避免画出悬空片段。
- **不要转一件站姿长袍充当所有动作。** 参考 [Modicos 动作版图](../SteriaBuild/Templates/CharacterSkin/CharacterSkin_Template_3x3_512_Modicos.png) 的跨步、弯肘、重心和衣料张力；R2 补绘待机/防御/祈祷、攻击组、移动/闪避/受击组，按领口、肩肘腕和支撑脚逐张标定。
- **姿势不要等高归一化。** 站姿、蹲闪、跪姿应保留实际高度差；以人体尺度和支撑脚校准，不能把所有包围盒拉成相同高度。
- **缩小也需要正确采样。** 将数百像素的五官直接用仿射 Bicubic 缩到几十像素会产生碎点。R2 先用 Lanczos 预滤波，再以 3 倍尺寸合成后整体缩小。
- 原理参考：[Spine IK](https://esotericsoftware.com/spine-ik-constraints) 的关节与弯曲方向、[Spine Meshes](https://esotericsoftware.com/spine-meshes) 的局部形变。当前使用预绘姿势和作者锚点，没有引入 Spine 运行时或声称使用了骨骼 IK。

### 底盘与鞋底基线（用户明确约定）

**除非有明确的特殊设计，鞋底/实际支撑底部必须与默认站姿基线齐平，角色之间的底盘也要等高。** 人物身高、头顶高度与动作包围盒可以不同；不能因此让普通动作悬空或陷地。

- 先选原版默认站姿作项目参考，再对齐角色自身的 Default 和其余落地动作。不能仅证明自己九张图的底部接近，就认为已经与游戏对齐。
- 使用鞋底、裸足或跪姿实际支撑位置；不取透明画布底边、光圈、粒子、阴影或武器的最低像素。当前无独立影效的衣装在鞋底带内按 alpha > 32 测量，后续拖尾越过鞋底时应重新指定接地区域。
- 图像原点、角色运行时原点、鞋底接地线是三个概念。保持人物比例与部件相对坐标，通过每动作 Pivot 修正底盘；启用原生头部时，Head 坐标必须同步换算，避免修底盘后拉长脖子。
- 浮空、跳跃、台座等偏离默认地面的设计必须记录独立高度偏移及原因。没有说明的偏移按错误处理。跪姿仍需支撑底部着地。
- 在相同缩放、相同选中/未选中状态下对照。原版 `UICharacterSlot.SetHighlighted` 会把选中槽位放大到 1.05 倍；不能从选中薇莉亚与未选中角色的屏幕差值反推全部皮肤偏移。

2026-09-09 核对 Bada：界面默认动作 `char_187.pres` 与战斗外观 `char_418.pres` 的鞋底均为角色原点上方约 `0.06` 单位（`1.685 - 325 × 0.5 / 100`）。当前薇莉亚在同一坐标下偏低 `0.06～0.08` 单位。已按该基线计算每动作运行时锚点：Default / Slash 的 `pivot_y` 从 `-268` 改为 `-274`，其余当前动作改为 `-276`；投影 Head 的 y 坐标同步增加 `6` 或 `8`。PNG 与头部相对结构不改动。

参数位于 `model.json/grounding`，原版测量依据在模型目录 `sources/grounding/bada_reference.json`，每动作结果在 `build/Velia_Layered_v1_Projection/grounding.json`。默认无高度例外；例外必须填写 `offset_world_y` 和 `reason`。

通用换算（P 为贴图 PPU，g 为参考鞋底相对角色原点的高度）：

```text
运行时原点的图像 y = 鞋底有效像素下边界 y + g × P
此原点再用于计算每动作 Pivot 与 Head
```

### 普通 512 散图公式

制作坐标为左上角原点，x 向右，y 向下；旋转正值按屏幕顺时针。所有原始攻击动作统一朝左，游戏负责敌我方向翻转。`Direction=Front/Side` 是视图类型，不是左右方向。

固定画布 512×512、站位像素 `(rx, ry)` 时：

```text
pivot_x = 2 * rx - 512
pivot_y = 512 - 2 * ry
head_x  = 2 * (hx - rx)
head_y  = 2 * (ry - hy)
rotation = -制作端顺时针角度
```

依据：加载器的 pivot 为 `(value+512)/1024`；头部坐标除以 100 得到局部单位；普通散图为 50 PPU。公式中的 `(hx,hy)` 是动作变换后的**头部锚点**，不是头顶或面部包围盒中心的猜测值。BaseMod 动态尺寸、自定义 PPU、头部缩放等扩展路径要按实际参数重新计算。

## 7. 希维尔、艾莉蕾尔与多角色工具

实例：[希维尔分层模型](../SteriaBuild/CharacterModels/Sivier_Layered_v1/README.md)、[艾莉蕾尔分层模型](../SteriaBuild/CharacterModels/Ailierel_Layered_v1/README.md)。两位均有九种绘制姿势、三组配准表情、衣装投影、原版换头对照与运行时包；目前供美术审阅，未覆盖两位角色的游戏旧资源。

本轮可复用的经验：

- **动作跟随角色定位。** 希维尔用细剑守势、切斩、长刺与援护；艾莉蕾尔用双短刀交叉招架、低姿闪避、连续刺击与伏击。共享制作方法不等于共享一套肢体姿势。
- **握持关系先画完整。** 服装、手、刀柄/护手在同一姿势母版中完成，再分离武器。这样保留接触关系，也可以让持械前层正确盖过头发。
- **先审空间结构，再看分层校验。** 艾莉蕾尔首版横斩把前臂画成横跨领口的长筒，肩部归属和两只手的前后关系不清。检查穿戴母版时应分别追踪两条肩→肘→腕→刀柄链，确认关节、手掌和胸胯转向一致；源画结构错误应重画，不能靠换锚点修补。本次改为攻击臂向左下展开、另一只手收在后侧，保留可辨认的两个肩部起点。
- **头部比例按完整轮廓判断。** 头发、猫耳和发饰也会增加视觉体积，不能只量脸型或机械指定“三头身”。本次将希维尔头部统一缩放从 `0.250` 调到 `0.215`，艾莉蕾尔从 `0.235` 调到 `0.205`；围绕原颈根缩放所有头部层，五官、领口和底盘关系保持一致。
- **刀剑不参与底盘测量。** `wearing.weapon` 与 `wearing.body` 分开，基线只取身体和鞋底。下垂细剑可能比鞋底更低，不能把人物整体包围盒当鞋底。
- **预览不要裁掉剑尖。** 固定窄裁切会让完整 PNG 看起来像缺少刀尖；使用覆盖全武器范围的统一取景，不逐张缩放角色。
- **配准整头轮廓，保留五官关系。** 同一角色的表情母版按整体轮廓平移配准，记录偏移；不对单独的眼眉鼻嘴重新拉伸。
- **SP 名称必须与代码一致。** 希维尔 `PlayPhantomDreamSpecialMotion` 调用 `ActionDetail.Special`，旧外观只有 `S1`。新模型同时提供 Special 与 S1 别名；不能只保存一个名叫 SP 的文件就认为接通。
- **闭眼祈祷不是受伤表情。** 薇莉亚 SP 现使用闭眼层搭配平静眉嘴，Special/S1 均已修正并同步游戏。不要为了闭眼而套用整张受伤脸，连痛苦嘴形也带进去。
- **共用经过验证的计算，独立保存美术参数。** 三个角色现在共用 `CharacterModels/shared/layered_model.py` 的装配与底盘导出；各角色的形体、锚点和分层区域独立。迁移共用工具时逐像素对照旧输出，本次确认薇莉亚只有 Special/S1 按需求改变。
