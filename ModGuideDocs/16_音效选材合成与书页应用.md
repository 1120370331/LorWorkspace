# 音效选材、合成与书页应用

**角色配音另见：** [18_剧情对白与事件语音制作](18_剧情对白与事件语音制作.md)。剧情逐句配音与开幕、击杀等事件语音使用 voice 音量和各自触发规则。

**先核原版声音，再决定是否自制：** AceTaffy 第一版纯正弦/噪声因听感生硬被否决；`AceTaffy/ArtSource/Audio/v2/` 保留 Kenney CC0 金属与 bart CC0 蒸汽录音的中间候选、来源和技术检查，但用户最终选择直接使用原版声音，v2 未获主观听感接受，也不是当前运行时依赖。最终实现删除 `src/TaffyAudio.cs` 及初始化音频调用；两个核心页没有 `SoundInfo`，`[Prefab]Appearance_Custom` 的原生 `CharacterSound` 六动作表因此保留，由原生 `PrintSound` 处理胜负与 FX 音量，不创建新的 AudioClip、PCM 解码或自定义覆盖。原始 `resources.assets` 的组件和非空 clip 证据见 `AceTaffy/ArtSource/Audio/native-main.log`；具体动作名与可选覆写入口见[第 10 章动作音效绑定](10_角色外观与特效系统.md#五动作音效绑定)。资源可解析、构建成功和主观听感是不同结论；本次没有观察用户实机播放或试听，不记为已听感通过。

本章以安希尔回忆系书页的纯火焰音效为例。最终采用用户试听认可的 **v5 短版**：斩击 0.46 秒、打击 0.55 秒、突刺 0.36 秒。较长的烈焰掉落、持续燃烧以及此前金属/素材库候选仅用于探索，没有随模组发布。

## 1. 找素材时先确定声音职责

先区分挥动、接触、尾声、能力提示，再搜索声音，而不是只搜角色名或“魔法”。例如 `sword swish`、`metal impact`、`fire crackle`、`flame whoosh`、`water splash`。同一书页可以有不同动作声，翻页、抽刀或恢复提示不应自动叠在每次命中上。

本次曾核对以下开放来源，全部选入试听的原件均由各发布页明确声明 CC0；最终成品没有使用这些录音：

| 来源 | 可找的素材 | 链接 |
|---|---|---|
| Kenney RPG Audio | 刀刃、抽刀、衣料、翻页 | [原页](https://kenney.nl/assets/rpg-audio) |
| Kenney Impact Sounds | 金属接触、轻重打击 | [原页](https://kenney.nl/assets/impact-sounds) |
| artisticdude / OpenGameArt | 挥动与风切 | [Swishes Sound Pack](https://opengameart.org/content/swishes-sound-pack) |
| rubberduck / OpenGameArt | 水花、气泡 | [Water / Splash / Slime](https://opengameart.org/content/40-cc0-water-splash-slime-sfx) |
| JaggedStone / OpenGameArt | 带音高的能力提示 | [Magic Spell SFX](https://opengameart.org/content/magic-spell-sfx) |

逐作品核对许可，不能将 OpenGameArt 全站当作同一种许可。免费、可试听和免版税也不等于 CC0。保存作者、发布页、原文件名、包内路径、下载日期、授权文本与 SHA256。CC0 不强制署名，仍建议保留来源记录；遇到 CC-BY 等许可则按其要求署名。

先给用户少量代表与同类备选，以稳定编号组织试听。原件保持字节完整，对比副本的增益/声道变化必须标注。**用户确认音色后再剪辑、混音、写入生产资源。** 不把网页能播放或波形检查通过当成主观听感认可。

## 2. 本次纯火焰声音的制作

直接合成采用 [Andy Farnell《Designing Sound》Practical 11: Fire](https://aspress.co.uk/sd/practical11.html) 的声音组成思路：火焰翻卷、嘶燃和不规则爆裂。实现独立编写，没有复制其录音或 Pure Data patch。

`SteriaBuild/VFXSource/MemoryFlameAudio/combustion.py` 使用无量纲热量、含氧量和燃料状态控制持续起伏，加入不同长度、频带和强度的成簇噼啪声；掉落参考加入接近、距离和轻微多普勒变化。这是**程序化燃烧声学近似**，不是完整燃烧 CFD 或真火录音。

v4 建立持续燃烧质感，v5 根据“长、拖沓”的反馈，剪掉远处接近与长余焰，加入 4ms 淡入和提前收尾。v5 不再改变播放速度、音高或归一化增益。必须先经过 v4 的 PCM16 量化，再按 v5 参数编辑，才能逐字节重现批准文件；`build_audio.py` 保留了该次序。

| 正式文件 | 时长 | 帧数（44100 Hz） | 采用的 v5 文件 |
|---|---:|---:|---|
| `slash.wav` | 0.46s | 20286 | 回忆斩击_短版.wav |
| `hit.wav` | 0.55s | 24255 | 回忆打击_短版.wav |
| `pierce.wav` | 0.36s | 15876 | 回忆突刺_短版.wav |

三文件均为 44100 Hz、立体声、PCM16，保持原试听文件的字节与音量。正式目录是 `SteriaBuild/SteriaModFolder/Resource/CustomAudio/MemoryFlame/`；源副本和不可随意重录的批准哈希在 `SteriaBuild/VFXSource/MemoryFlameAudio/source_audio/`、`accepted-audio.json`。

## 3. 书页范围和动作映射

声音跟随书页，不跟随安希尔或 Bada 皮肤。玩家使用这些书页时同样生效；其他角色共享回忆贴图素材，也不会因此被全局替换声音。

| 书页 | 应用的攻击骰 |
|---|---|
| 9001002 回忆侧斩 | 第 1、2 骰斩击 |
| 9001003 奥塔尔的荣耀 | 第 2 骰斩击 |
| 9001004 回忆协奏之刃 | 第 1 骰斩击、第 2 骰打击、第 3 骰突刺 |
| 9001005 攫取回忆 | 第 1、2 骰斩击 |
| 9001009 以执为攻 | 第 1 骰斩击、第 2 骰打击 |
| 9001010 寒地后勤 | 第 2 骰斩击 |

共 6 张书页、11 颗攻击骰。`MemoryFlameAudio.Select` 同时检查：

- LorId 的包名必须为 `SteriaBuilding`，并命中上述卡牌白名单。
- 普通近战攻击骰、实际胜利/单方攻击结果、未跳过，动作与骰子细节一致。
- `EffectRes` 为匹配动作的 `Steria_AnhierTextureMemorySlash/Hit/Pierce` 或公共别名 `Steria_MemorySlash/Hit/Pierce`。
- `ActionScript` 为空或已知的三个回忆协奏节奏入口。

失败、平局、近战对远程攻击的弹反、守备、闪避、未批准的反击/群攻/Instance、外来特殊动作或其他书页均回到原声。回忆协奏末闪避、弃牌加威力、骰子点数与战斗结算没有改变。本功能不需要改 CardInfo.xml，也不修改共享角色声音字典。

## 4. 为什么在 PrintSound 接入

`RencounterManager.MoveRoutine` 在真实 PRE/POST 时点调用 `PrintEffect`；后者按交锋条件调用 `PrintSound`，再由 `CharacterSound.PlaySound` 播放角色声音。新的 `MemoryFlamePrintSoundPatch` 只在这个私有方法前缀中做有界选择。

回忆协奏已经由 [第 15 章](15_书页动作与出刀节奏制作.md) 的 ActionScript 定义准备、出手和收势。这里自然跟随那一次 PRE，不再启动独立秒表，也不在 OnUseCard 或伤害能力回调里重播三刀。原版负责骰子结果与伤害；音效接入只替换合格出手的原动作声音。

选中后，从当前角色 `CharacterSound` 读取原生 `_soundPrefab`，实例化同一种 `BattleEffectSound`，挂在 `BattleSoundManager` 下，调用 `Init(clip, manager.VolumeFX, false)`。按原生 FX 音量传入一次，不额外再乘 master/effect，不调 pitch，不创建循环或自定义慢放时钟。普通短动作声的暂停、音量更新与销毁沿用原生播放器；没有额外豁免 AudioListener 暂停的设置。

只有新文件成功加载、播放器初始化成功后，前缀才阻止该次原声。缺文件、错误格式、缺皮肤/声音 prefab 或初始化异常会保留原声。已经创建但初始化失败的播放器会销毁，避免残留。三份 clip 按需加载并缓存；失败只记录一次，替换文件后应重新加载模组/重启游戏，不依赖热更新缓存。

不要在 `DiceAttackEffect.Initialize` 再叠一份声音：共享特效可出现在其他书页或不同胜负路径，而且会与 PrintSound 重复。也不要只增加效果寿命来延长音频，或为了音频修改战斗等待时间。

## 5. 复现和验证

依赖现有游戏引用、.NET Framework 4.7.2 支持、.NET SDK、Python/NumPy/SciPy；音频来源不需要网络。仓库的 `Assembly-CSharp` 反编译参考树用于理解原生流程，不随 Git 分发。构建环境见 [第 08 章](08_编译与部署.md)。

```powershell
# 默认生成 source_audio；--verify 只核对已存在的源与发布副本。
python -X utf8 SteriaBuild/VFXSource/MemoryFlameAudio/build_audio.py --verify
dotnet build SteriaBuild/Steria.csproj -c Release --nologo
dotnet build SteriaBuild/Verification/MemoryFlameAudio/Checks.csproj -c Release
SteriaBuild/Verification/MemoryFlameAudio/bin/Release/net472/Checks.exe .
```

策略检查直接使用本次编译的 Steria.dll 和实际游戏数据类型，覆盖 11 个 XML 对应动作、包隔离、胜负/远程/防御回退，以及生产 `SkillPcmWave` 的精确时长读取。`.NET` 控制台不能代替 Unity 原生接口环境，因此实际 Harmony 派发和播放器创建另在隔离 Unity 2019.3.15f1 Play Mode 中检查。

```powershell
python -X utf8 SteriaBuild/Verification/MemoryFlameAudio/prepare_unity.py
# 隔离工程：output/memory-flame-delivery/UnityProject
# Unity batchmode 入口：MemoryFlameFixture.Run
# 结果：output/memory-flame-delivery/unity-result.txt 和 unity.log
```

Unity 检查先验证真正的私有 PrintSound hook，再用原生 BattleEffectSound、AudioClip、AudioSource 验证一次出手一个实例、正确帧数、FX 音量一次生效、无循环与额外 pitch。自动断言不替代实际听感；优先在模拟工程中混入 BGM 与其他技能声音试听，将配置、触发结果和音频附件路径集中记入本次主日志。仅为无法模拟的具体混音或场景问题补游戏内检查。

## 6. 发布与后续调音

正式交付必须同步**同一候选** DLL 和三个 WAV，并保存备份与 SHA256。以真实 Player.log 中的 D 盘模组加载路径为准，解析 C/D 路径是否同一链接目录，不能把同一目录重复覆盖当作两份部署。无需为这三个 PCM 音效重建 AssetBundle。

仓库可能有其他并行修改。部署器只替换本次 DLL 与 `CustomAudio/MemoryFlame` 下三个文件；若目标书页还没有回忆协奏的 ActionScript，则只同步该书页三个明确节奏属性，不能整表覆盖不相关游戏数据。

后续调整先产出新的试听候选，记录剪辑与增益；用户批准后更新批准哈希、源/发布 WAV 和精确帧数合同。不要靠重新记录哈希掩盖未试听的变化。本轮是否部署、在哪个目录生效以及实机验收边界，以 `output/memory-flame-delivery/` 的交付记录为准。
