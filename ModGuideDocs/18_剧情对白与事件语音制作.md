# 战前、战中、战后剧情与事件语音制作

游戏中的“说话”有两种表现：完整剧情界面用于连续对白、立绘、背景与演出；战斗短台词用于开幕、击杀、死亡等即时反馈。声音也要分别接入：剧情对白通过 `VoiceFile` 标识录音，战斗短台词则需要额外建立台词与录音的绑定。

本章按“做什么、为什么、带来什么效果”逐步说明。关卡配置基础见[第 06 章](06_敌人与关卡系统.md)，动作音效见[第 16 章](16_音效选材合成与书页应用.md)，查找真实调用链的方法见[第 17 章](17_程序集反编译与源码追踪.md)。本章的语音指角色配音，和刀剑、火焰等动作音效分别管理。

**剧情长度与画面接入也要验收：** 先列出误入、交涉、试验能力、开战动机、战后回响等实际情节节点，再按节点检查场景图和人物是否接入。不能用几句解释性台词或只有 XML 条目数来代替完整情节。[AceTaffy 剧情脚本](../AceTaffy/ArtSource/Story/story-script.md)的最终方案仅为独特直播间场景生成配图；进入图书馆后的战前与战后剧情共用原版固定背景 `ch1_library_inside`，安吉拉与罗兰使用原版立绘及表情。场景数量按情节需要确定，不设固定生图配额。

**正式立绘单独建模板。** 自定义剧情演员采用自然人体比例，记录画布、人物高度、裁切、位置和表情配准，切表情时保持人物尺度与站位稳定。战斗立绘的头身数、窄躯干和无裸颈拼接要求只作用于相应战斗模板，详见[第１２章：原版比例与模板约束](12_战斗单位分层建模与核心书页投影.md#原版比例与模板约束)。原版图书馆人物和场景直接复用游戏资源；仅为原版没有的独特场景制作新图。背景已经画入某个角色时，检查是否还需叠加该角色立绘，避免重复出现。

**依据与范围：** 以下原生接口和加载行为已对照仓库中的游戏与 BaseMod 反编译源码，并检查 Steria 当前的 `BookStory.xml`、`StageInfo.xml` 和 `Combat_Dialog.xml`。XML 是制作模板；C# 片段用于说明接入方式。资源目录中的 `Voice/`、录音清单和事件调度规则是本章建议的项目规范，不是游戏已经自动支持的字段。自定义配音接入完成后须编译，并优先在模拟工程中检查播放与试听；本文三个完整类示例已用仓库的游戏引用编译通过，XML 示例已检查格式；未执行实机配音播放。本章功能尚未接入当前 Steria 模组。

## 第 1 步：先确定说话时机和表现形式

### 做什么

制作前先列一张事件表，明确说话者、台词、录音、触发条件、重复范围和是否阻塞战斗。“开幕”要明确是接待开始、每个 Wave 开始，还是每幕开始，不能混用。

| 需求 | 文字与演出入口 | 配音入口 | 触发边界 |
|---|---|---|---|
| 战前连续剧情 | StageInfo 的 `Story Condition="Start"` | StoryText 每句的 `VoiceFile` 加语音资源接入 | 接待开始剧情，不是每幕 |
| 战中阶段剧情 | 主动加载 StoryText / StoryEffect，打开 `BattleStoryUI` | 同一套剧情语音接入 | 阶段变化或指定幕，一次性触发 |
| 战后连续剧情 | `Story Condition="End"` | 同上 | 整场接待胜利后的剧情，不是每 Wave 结束或失败结局 |
| 开幕短台词 | `START_BATTLE` | 战斗语音调度层 | 原生在第一幕开幕动画结束时请求 |
| 每幕提示 | 自行触发 `SPECIAL_EVENT` | 战斗语音调度层 | `OnRoundStart` 等明确回调 |
| 击杀、死亡、同伴死亡 | `KILLS_OPPONENT` / `DEATH` / `COLLEAGUE_DEATH` | 战斗语音调度层 | 对应事件；击杀需保留击杀者与被击杀者 |
| 胜利短台词 | `BATTLE_VICTORY` | 战斗语音调度层 | 原生判定该场交战胜方时可请求，不能直接等同于整场接待结局 |

### 为什么

相似的文字效果可能有不同调用入口。把“开幕”写在每幕回调会反复播；把整场战后剧情写在击杀最后一个当前敌人时，可能抢在后续 Wave 前播放。

### 带来什么效果

后续每条文本与音频都有明确的归属和触发规则，不会因多波次、复活或反击产生意外重复。

## 第 2 步：先整理文本、录音与命名

### 做什么

一条可独立播放的台词对应一个稳定 ID。长剧情每个 Dialog ID 对应一段录音；战斗语音每个可选变体也单独编号。文字和音频共用一次选句结果，不分别随机。

建议目录如下；音频目录必须由自己的加载器读取：

```text
YourMod/
├── Data/
│   ├── StageInfo.xml
│   ├── Combat_Dialog.xml
│   ├── StoryText/
│   │   ├── MyStage_Start.xml          # 根目录后备文本
│   │   ├── MyStage_Mid.xml
│   │   ├── MyStage_End.xml
│   │   └── cn/                       # 可选语言版本，同名文件
│   └── StoryEffect/
│       ├── MyStage_Start.xml
│       ├── MyStage_Mid.xml
│       └── MyStage_End.xml
└── Resource/
    └── Voice/                        # 本章约定，自定义加载
        └── cn/
            ├── Story/MyStage_Start_001.wav
            └── Battle/MyActor/START_BATTLE_0.wav
```

录音清单至少保存：包 ID、说话者 ID、语言、台词 ID、完整台词、录音相对路径、时长、文件哈希和来源。剧情还记录剧情文件基础名与 Dialog ID；事件语音还记录 Type、优先级和重复规则。录音可以使用已有的可靠 WAV/OGG 导入路径，格式必须与解码器一致，不能靠改扩展名转换。

录制或剪辑时去掉非预期的长空白和爆音，保留自然呼吸与句尾，按角色和场景统一听感。配音不设刀剑短音效的固定时长，也不为压缩台词而随意加速或改变音高。素材授权与来源记录沿用第 16 章，配音成品需实际试听。

### 为什么

文件名、台词 ID 和随机变体一旦独立变化，就容易出现字幕 A 配录音 B。按台词切文件也方便跳过、重播日志和替换某一句。

### 带来什么效果

文本、音频和事件可逐条检查；更换语言或重新录制某一句时，绑定关系仍稳定。

## 第 3 步：制作完整剧情的文本与演出

### 做什么

每段剧情使用同基础名的 StoryText 和 StoryEffect。以下为可解析的最小文本结构，`VoiceFile` 用本模组专属键；语音资源接入见第 7 步。

```xml
<?xml version="1.0" encoding="utf-8"?>
<ScenarioRoot>
  <Chapter ID="-1"><Title>示例接待</Title></Chapter>
  <Group>
    <GroupName>MyStage</GroupName>
    <Episode>
      <EpisodeName>Start</EpisodeName>
      <Place>
        <PlaceName>入口</PlaceName>
        <Dialog ID="0" Model="">
          <Teller>来宾</Teller>
          <Title />
          <VoiceFile>MyMod_MyStage_Start_000</VoiceFile>
          <Content>这里就是图书馆吗？</Content>
        </Dialog>
        <Dialog ID="1" Model="">
          <Teller />
          <Title />
          <VoiceFile>None</VoiceFile>
          <Content>门缓缓打开了。</Content>
        </Dialog>
      </Place>
    </Episode>
  </Group>
</ScenarioRoot>
```

无复杂演出时，StoryEffect 可从这个最小结构开始，再增加经过核实的背景、人物和音效配置：

```xml
<?xml version="1.0" encoding="utf-8"?>
<SceneEffect>
  <CG />
  <storyBranch>None</storyBranch>
</SceneEffect>
```

需要某行改变背景、人物或音乐时，在 StoryEffect 中增加该行的 `<Dialogue ID="...">`。它对应 StoryText 的 `<Dialog ID="...">`，两种标签拼写不同。演出条目不必机械地为每句复制一份，按需要配置，但每个引用的 ID 必须存在。`Bgm` 控制背景音乐，`EffectSound` 控制场景音效，不能拿它们冒充逐句配音。

**人物、背景与台词分别核对：** StoryText 的 `Dialog Model` 指向演员资源名，StoryEffect 的 `Character Name` 应使用同一实际键；原版人物应先从原版 prefab 数据核真实键，不要猜译名。当前 AceTaffy 数据所用的原版键为安吉拉 `앤젤라`（Face `normal/smile/sigh`、Body `nomal`）和罗兰 `롤랑`（Face `nomal/worry/sigh/happy`、Body `nomal`）；原资源的 `nomal` 拼写必须照实保留。自定义演员立绘可由 `Resource/StoryStanding/<Name>.png` 提供，背景由 `Resource/StoryBgSprite/<Src>.png` 提供；先核加载器与本模组候选路径，再检查视觉结果。逐句换场景应在对应 `<Dialogue ID>` 中设 `<Bg Src="..." />`；顶层 `<CG>` 不能代替这些逐句背景绑定。同一人物若换表情时使用多个自定义 `Name`，应在切换句停用旧名并启用新名，检查屏幕上只有一张该演员。首句就要有有效背景，避免黑屏开场。核 ID、键和资源文件只是静态检查，仍需实际剧情 UI 确认场景、人物、顺序和遮挡。

多语言文本优先使用 `Data/StoryText/<语言>/`，不放在 `Localize/<语言>/StoryText/`。本仓库 BaseMod 在当前语言目录不存在时选择 `DefaultLocale` 目录；当前语言目录存在但缺某个文件时，不保证再按文件回退到默认语言，可能沿用根目录初始路径。应提供完整同名文件或根目录后备，并核对实际加载结果。

### 为什么

文字与演出分离后，同一句的录音、背景、立绘和特效仍由 Dialog ID 对齐。明确语言加载规则能避免“文件明明在默认语言目录却不播放”。

### 带来什么效果

先得到可以阅读、推进和跳过的完整剧情，再逐步加演出与配音。

### 模组参考

Steria 已有的文字材料可在 [BookStory.xml](../SteriaBuild/SteriaModFolder/Data/BookStory.xml) 和 [Combat_Dialog.xml](../SteriaBuild/SteriaModFolder/Data/Combat_Dialog.xml) 中查看；前者保存核心书页故事，后者保存战斗短台词。它们不是 `StoryText/StoryEffect` 接待剧情示例，也没有演示自定义逐句配音。当前接待剧情入口见 [StageInfo.xml](../SteriaBuild/SteriaModFolder/Data/StageInfo.xml)，完整 `StoryText/StoryEffect` 文件需要按本章模板新增。

## 第 4 步：绑定战前与战后剧情

### 做什么

在已有 Stage 节点中增加或替换这三个字段；下例是片段，不是完整关卡配置：

```xml
<Stage id="1">
  <Story Condition="Start">MyStage_Start.xml</Story>
  <Story Condition="End">MyStage_End.xml</Story>
  <StoryType>MyMod_Story</StoryType>
</Stage>
```

配套准备 `MyStage_Start` 与 `MyStage_End` 的文本和演出文件。`StoryType` 用于剧情组，不能只写类型而省略实际文件绑定。建议完整填写文件名；BaseMod 的基础名匹配能力不应成为混用大小写或扩展名的理由。

### 为什么

Start / End 由接待流程调用，不需要另在被动中再播一遍。End 不是失败回调，也不是每幕结束；需要败北或阶段结局时，另选明确事件。

### 带来什么效果

进入接待前和接待胜利后，游戏自动打开指定完整剧情。

### 模组参考

当前 [Steria StageInfo](../SteriaBuild/SteriaModFolder/Data/StageInfo.xml) 仍有 Start 指向 `Button`、End 为空的占位配置，包内没有对应的 `StoryText/Button` 与 `StoryEffect/Button` 文件。因此本节的 `Steria_Anhier_Start/End` 文件名是新增模板，不是现有剧情；绑定后要同时加入同名文本和演出文件。

## 第 5 步：在战中安全触发完整剧情

### 做什么

选择不会打断伤害结算的时机，在关卡管理器或被动中检查条件，并使用待播放/已尝试状态防止重入。优先在已确认的幕边界播放；伤害回调只登记阶段变化，再由安全边界消费。

| 需求 | 可用入口 | 注意事项 |
|---|---|---|
| 每 Wave 初始化 | `EnemyTeamStageManager.OnWaveStart()` | 每 Wave 都可能进入，整场只播一次需额外状态 |
| 指定幕 | `EnemyTeamStageManager.OnRoundStart()` | 区分幕数和 Wave，条件满足后置位 |
| 本幕行动结束 | `EnemyTeamStageManager.OnRoundEndTheLast()` | 适合阶段剧情，先检查是否已有剧情打开 |
| HP 阶段变化 | 被动登记条件，再在幕边界播放 | 不在每次伤害中重复打开剧情 |
| 自己死亡/其他单位死亡 | `PassiveAbilityBase.OnDie()` / `OnDieOtherUnit(unit)` | 关卡管理器基类没有同名 OnDie 回调；死亡单位可能随后被清理 |

下面的示例从第 3 幕结束开始等待剧情界面空闲，只尝试加载一次，省略音频预加载。类还需按第 06 章注册到自己的关卡。路径使用明确文件名，不实现第 3 步的完整语言目录策略：

```csharp
using System.IO;
using Mod;
using UnityEngine;

public class EnemyTeamStageManager_MyStory : EnemyTeamStageManager
{
    private bool _attempted;

    public override void OnRoundEndTheLast()
    {
        base.OnRoundEndTheLast();
        if (_attempted || Singleton<StageController>.Instance.RoundTurn < 3)
            return;

        var ui = SingletonBehavior<BattleManagerUI>.Instance.ui_battleStory;
        if (ui.isRunning || ui.storyUI.activeSelf)
            return;

        _attempted = true;
        string root = Singleton<ModContentManager>.Instance.GetModPath("YourModId");
        string text = Path.Combine(root, "Data", "StoryText", "MyStage_Mid.xml");
        string effect = Path.Combine(root, "Data", "StoryEffect", "MyStage_Mid.xml");
        if (!StorySerializer.LoadStoryFile(text, effect, root))
        {
            Debug.LogError("[YourModId] Cannot load MyStage_Mid");
            return;
        }
        ui.OpenStory(() => { /* 恢复本次确实改变的状态 */ }, false, true);
    }
}
```

`OpenStory(endFunc, nonskip, blockBattle)` 中，`false, true` 表示允许跳过且剧情期间阻塞战斗。若另暂停 BGM、隐藏角色或改变场景，结束/跳过时都要恢复；不要无条件重启未由本次停止的 BGM。

如果需要行事件，在 `OpenStory` **之后**调用 `ui.AddEvent(dialogId, action)`，因为 OpenStory 会清空此前登记的事件。动作可能因推进或重播而再次触达，应自行保持幂等；初始化时立即出现的首行不适合依赖随后才注册的事件完成关键设置。不要把 `AddEvent` 当成所有配音的统一入口：剧情日志重播走 `PlayVoice`，并不等于重新触发战斗行事件。

### 为什么

剧情加载使用共享静态状态；同一时刻打开两段剧情会覆盖当前上下文。剧情还会改变战斗等待和 UI，遗漏恢复或反复触发都可能卡住流程。

### 带来什么效果

阶段剧情只在合适时机出现，正常读完或跳过后战斗都能继续。

### 模组参考

Steria 当前没有已接入的战中完整剧情被动。剧情文件加载路径和 BattleStoryUI 恢复逻辑可在 `SteriaBuild/BaseMod/Harmony_Patch.cs` 中核对；Steria 新增的触发被动应以此为加载基线，并按本章示例补齐去重状态、空闲检查和结束恢复。

## 第 6 步：制作开幕、击杀等战斗短台词

### 做什么

先接通无声字幕。基础邀请配置在 `StageModInfo.xml` 的 `InvitationFile` 中登记：

```xml
<Dialog Exist="true">
  <Path>\Data\Combat_Dialog.xml</Path>
</Dialog>
```

对应文本使用 `BattleDialog` 子元素，Type 和单句 ID 各有作用：

```xml
<?xml version="1.0" encoding="utf-8"?>
<BattleDialogRoot>
  <Version>1.1</Version>
  <Character ID="1">
    <Type ID="START_BATTLE">
      <BattleDialog ID="START_BATTLE_0">准备好了吗？</BattleDialog>
      <BattleDialog ID="START_BATTLE_1">开始吧。</BattleDialog>
    </Type>
    <Type ID="KILLS_OPPONENT">
      <BattleDialog ID="KILLS_OPPONENT_0">到此为止。</BattleDialog>
    </Type>
    <Type ID="DEATH">
      <BattleDialog ID="DEATH_0">还不能……</BattleDialog>
    </Type>
    <Type ID="COLLEAGUE_DEATH">
      <BattleDialog ID="COLLEAGUE_DEATH_0">我会接着战斗。</BattleDialog>
    </Type>
    <Type ID="BATTLE_VICTORY">
      <BattleDialog ID="BATTLE_VICTORY_0">结束了。</BattleDialog>
    </Type>
    <Type ID="SPECIAL_EVENT">
      <BattleDialog ID="PHASE_2_0">接下来，认真一点。</BattleDialog>
    </Type>
  </Character>
</BattleDialogRoot>
```

`Character ID` 关联的是实际对话数据，不应仅凭敌人 ID 猜测。普通模组路径中，`UnitDataModel.InitBattleDialogByDefaultBook` 按核心书页 LorId 查询；BaseMod 还支持 BookID / CharacterID 关系，以及按 CharacterName 选择 `BattleDialogueModel_<名称>`。检查当前单位的 `battleDialogModel` 确实使用目标数据，尤其是换核心书页、司书使用来宾书页和不同包内同数字 ID 的情况。

特殊事件显式选句：

```csharp
owner.view.DisplayDlg(DialogType.SPECIAL_EVENT, "PHASE_2_0");
```

调用文件需引用 `LOR_XML` 命名空间。这个调用只显示字幕，且该带 ID 重载在原版中针对 Invitation 路径。普通的 `DisplayDlg(type)` / `DisplayDlg(type, targets)` 会通过对话模型选句；targets 还可能影响特定人物之间的对话，不能在加语音时丢掉这个上下文。

### 为什么

`Type` 决定什么时候请求，单句 ID 决定说哪一句。没有正确加载到单位的文本，任何音频补丁都无法修复字幕关联。

### 带来什么效果

先获得事件触发正确、人物关联正确的短台词，再为同一组 ID 绑定录音。

### 当前仓库的具体坑

[当前 Combat_Dialog.xml](../SteriaBuild/SteriaModFolder/Data/Combat_Dialog.xml)内仍可见 `<Dialog>文字</Dialog>`，而对应加载器声明的是 `[XmlElement("BattleDialog")]`；不要照抄这种写法。[斯拉泽雅本地化文件](../SteriaBuild/SteriaModFolder/Localize/cn/BattleDialogues/CombatDialog_Slazeya.xml)使用了 `BattleDialog ID`，可参考语法，但是否生效仍须核对 BaseMod 的本地化加载与单位关联。这是文档审查发现，未在本次修改这些运行时文件。

## 第 7 步：给完整剧情接入逐句配音

### 做什么

先选一段只有两三句的剧情接通配音，再扩展整场。战前、战中、战后的完整剧情都使用同一套逐句配音方法；开幕、击杀等战斗短台词使用第 8 步的事件语音方法。

#### 从一句对白开始：文件、绑定、播放与检查

**1. 准备这句话的录音。** 先确定说话者、台词、情绪和停顿，再录制或制作单句音频。以“这里就是图书馆吗？”为例，下面是新增文件的示意位置，并非当前模组已经存在的资源：

```text
YourMod/Resource/Voice/cn/Story/MyStage_Start_000.wav
```

保留自然的起音与句尾，检查爆音、长空白和音量；先试听该句，再连续听前后对白，确认情绪与节奏相接。需要跨句连续的环境声或音乐应另走场景音效/BGM，避免每次跳句都重复启动。

**2. 在对应对白写 VoiceFile。** 在 `Data/StoryText/MyStage_Start.xml` 的相应 Dialog 中填写稳定语音键：

```xml
<Dialog ID="0" Model="">
  <Teller>来宾</Teller>
  <Title />
  <VoiceFile>MyMod_MyStage_Start_000</VoiceFile>
  <Content>这里就是图书馆吗？</Content>
</Dialog>
```

`ID=0` 负责定位剧情行，`VoiceFile` 负责定位录音。语音键不必等于数字 ID，但应包含模组和剧情信息，避免不同文件的“第 0 句”互相覆盖。有意无配音的对白写 `None`。

**3. 建立语音键到音频文件的映射并预加载。** 下面是自己的语音解析器可以采用的清单格式，游戏不会自动读取这个 JSON：

```json
{
  "packageId": "YourModId",
  "language": "cn",
  "clips": {
    "MyMod_MyStage_Start_000": "Resource/Voice/cn/Story/MyStage_Start_000.wav"
  }
}
```

解析器以实际模组根目录拼出文件路径，使用下文 `VoiceFileLoader.LoadWav` 等已选定的加载方式得到 AudioClip，并按包、语言和键缓存。在打开本段剧情前完成必要音频加载；失败时记录原因并允许按无配音方式继续，不能只创建一个永远未完成的等待状态。

**4. 让剧情播放器取到这份 AudioClip。** 把缓存接入下文的 PlayVoice 音频解析流程，同时保留停止旧句、自动推进、日志重播和淡出时长查询。此步骤需要模组代码，只有 XML 和 WAV 仍不会播放。剧情实例或语音语言切换时使用对应缓存，避免同名键串段或串语言。

**5. 按剧情入口播放。** 战前、战后由 StageInfo 绑定触发；战中由加载 StoryText/StoryEffect 后打开 BattleStoryUI 触发。配音跟随当前 Dialog，不要另外用固定秒数依次播放一列 WAV；玩家可能停留、跳句、跳过或重播。

**6. 完整检查这一句。** 先正常播放，再快速切到下一句、自动推进、静音、日志重播和跳过剧情；确认旧句停止、字幕与声音一致、自动推进按录音长度工作，返回战斗后没有余音。最后临时使用缺失的录音键，确认仍能显示文字并继续剧情。通过后再批量扩展其他句子。

这六步形成的链路是：**台词与录音 → VoiceFile 绑定 → 自定义加载与缓存 → 原生剧情播放控制 → 真实推进与跳过检查**。

#### 原生读取路径与需要补充的接入层

先理解原生调用：

```text
StoryText 的 VoiceFile
  → WorkParser.Dialog.Voice
  → StoryScene.StoryManager.PlayVoice(dialog)
  → Resources.Load<AudioClip>("StoryResource/Voices/Chapter" + chapterID + "/" + voiceKey)
  → 当前 StoryManager 的 voice 播放器
  → 按 clip.length 维护自动推进，并更新语音日志
```

`StorySerializer.LoadStoryFile` 会把模组当前章节设为 `-1`，所以本章示例键默认查询的是：

```text
StoryResource/Voices/Chapter-1/MyMod_MyStage_Start_000
```

它不是 `Resource/Voice/cn/...wav` 的文件路径。将 WAV 放入模组、填写 VoiceFile 或在 XML 改 Chapter ID，都不会自动把磁盘音频注册成 Unity Resources。

为自己的模组建立一层**剧情语音解析器**，职责如下：

1. 在剧情开始前按录音清单预加载 AudioClip，键至少包含模组、语音语言、voiceKey；载入失败记录完整键和路径。
2. 只处理本模组剧情路径和专属 voiceKey。可在 `PlayVoice` 的音频解析处定向替换；也可由受限资源解析适配层返回该键的缓存 AudioClip。选择方案前核对当前游戏 DLL 与其他补丁，避免影响原版和其他模组。
3. 保留原生 `StopVoice`、旧 `_autoClipCoroutine` 停止、voiceVolume、`AudioClipOver(clip.length)`、`dialogLogManager.OnVoice` 的完整语义。若直接替换 PlayVoice，需要逐项实现，不能只加一个 `PlayOneShot` 就跳过原函数。
4. 同时检查 StoryManager 中 Fadeout 对语音时长的查询；它也使用同样的资源路径。只修播放、不修时长查询时，可能在配音没说完前结束淡出。
5. 跳句、跳过剧情、正常结束、退出场景和日志重播都使用同一套 clip 解析和停止规则；异步载入完成前若已换句，旧请求不得再启动旧音频。
6. 缺失录音时保留文字与原生无语音推进，不让剧情等待一个不存在的 clip。`None` 表示有意无配音，与“应有但缺失”分别记录。

原版 `AudioClipOver` 以录音时长再加 0.5 秒维护自动推进；无语音时按文字长度估算。语音静音也不应把一句的阅读时长变为零。若设计需要改变节奏，明确修改自动推进规则，不靠裁短字幕或伪造 clip.length。

可以用 UnityWebRequestMultimedia 从磁盘预加载。以下是独立的单文件加载片段，不包含上述解析器、缓存和补丁注册；由自己的协程宿主在 Unity 主线程上执行：

```csharp
using System;
using System.Collections;
using System.IO;
using UnityEngine;
using UnityEngine.Networking;

public static class VoiceFileLoader
{
    public static IEnumerator LoadWav(string fullPath, Action<AudioClip> done)
    {
        if (!File.Exists(fullPath)) { done(null); yield break; }
        string uri = new Uri(Path.GetFullPath(fullPath)).AbsoluteUri;
        using (var request = UnityWebRequestMultimedia.GetAudioClip(uri, AudioType.WAV))
        {
            yield return request.SendWebRequest();
            if (request.isNetworkError || request.isHttpError)
            {
                Debug.LogError("Voice load failed: " + fullPath + " / " + request.error);
                done(null);
                yield break;
            }
            done(DownloadHandlerAudioClip.GetContent(request));
        }
    }
}
```

该加载片段需引用 `UnityEngine.UnityWebRequestModule.dll`、`UnityEngine.UnityWebRequestAudioModule.dll` 及相应 Core/Audio 模块。这里使用适合本项目 Unity 版本的请求错误检查接口。OGG 等格式须选择对应 AudioType。缓存释放时先停用引用它的播放器，再销毁自行创建的 clip；不要销毁游戏共享资源。

### 为什么

剧情语音同时参与播放、自动推进、淡出和日志。仅让 WAV 发声，可能留下快速跳句时重叠、日志不能重播、剧情提前结束等问题。Steria 当前只有书页故事和战斗短台词数据，没有完整剧情界面配音实现；本节描述的是后续要新增和验收的功能。

### 带来什么效果

逐句配音随文本推进，跳过时停止，日志可重听，缺文件仍能继续。这里描述的是需要实现并验收的接入规范；Steria 现有的 `BookStory.xml`、`Combat_Dialog.xml` 和 BaseMod StoryText 加载逻辑都不能证明模组的 `Voice/` 目录已自动接入。

## 第 8 步：给战斗短台词绑定同一次选句的录音

### 做什么

原生 `LOR_XML.BattleDialog` 只有 `dialogID` 和 `dialogContent`，没有 VoiceFile。其基本链路是：

```text
开幕 / 击杀等事件
  → BattleUnitView.DisplayDlg(type[, targets / id])
  → BattleDialogueModel.GetBattleDlg(...)
  → 返回文字
  → ui_unitListInfoSummary.DisplayDlg(...)
```

因此需要自己的战斗语音绑定与调度层。选句结果至少携带：说话者、Type、单句 ID、文字、clipKey 和本次事件标识。调度层接到一次结果后，同时显示该句字幕并播放对应录音。

```text
选定一次条目 → 根据同一个 ID 找文本和录音 → 排队/抢占 → 同时显示和播放
```

**自动事件的接法：** 在本模组范围内接管实际 `DisplayDlg` 请求或等价的有单位上下文的呈现边界，保留 targets、指定 ID 和角色专属选句规则。确认自己的呈现成功后，阻止该次原字幕重复显示；无匹配数据时保留原路径。各重载只能有一个实际播放出口。不要在 `GetBattleDlg` getter 内直接发声，因为读取文本不等于实际呈现。

**自定义事件的接法：** 阶段、书页或被动触发统一调度入口，不再额外调用一份 DisplayDlg。可用 `SPECIAL_EVENT` 承载手动字幕，显式指定 ID。下面示例演示“已选定 ID、已加载 clip”的一次呈现；它不是完整的自动事件补丁或队列实现：

```csharp
using LOR_XML;
using UnityEngine;

public static class BattleVoicePresentation
{
    public static bool Present(BattleUnitModel speaker, DialogType type,
        string dialogId, AudioSource voice, AudioClip clip, OptionDataModel option)
    {
        if (speaker == null || speaker.view == null ||
            Singleton<StageController>.Instance.stageType != StageType.Invitation)
            return false;
        var model = speaker.UnitData.unitData.battleDialogModel;
        if (model == null) return false;
        string text = model.GetBattleDlg(type, dialogId);
        if (string.IsNullOrEmpty(text)) return false;

        SingletonBehavior<BattleManagerUI>.Instance.ui_unitListInfoSummary
            .DisplayDlg(text, speaker, false, MentalState.Positive);
        if (voice != null)
        {
            voice.Stop();
            voice.clip = clip;
            if (clip != null && option != null)
            {
                voice.loop = false;
                voice.spatialBlend = 0f;
                voice.pitch = 1f;
                voice.volume = option.GetVolumeVoice();
                voice.Play();
            }
        }
        return true;
    }
}
```

播放器由战斗语音管理器持有；不要挂在死亡后立即销毁的角色对象下，否则遗言被截断。上面的方法适合调度层已经决定该句可以播放时使用；不要在原生开幕或击杀仍自动显示字幕的同时，又从被动平行调用它。

### 为什么

原生随机接口返回文字，没有把选中的 ID 一并交给音频层。字幕随机一次、声音再随机一次会错配；事后按字幕反查文件又会受重复文字和多语言影响。

### 带来什么效果

无论是随机开幕、针对某人的击杀台词还是固定阶段宣言，显示与播放始终来自同一个条目。

## 第 9 步：明确开幕、击杀、死亡的触发和并发规则

### 做什么

先选择“沿用原生呈现事件”或“自定义事件”，同一台词只保留一个触发源。原生开幕与击杀的调用依据如下：

| 事件 | 已核对的源码位置 | 制作时要避免的错误 |
|---|---|---|
| 开幕 | `BattleActUI.EndActAnim` 在 actLv==1 时对单位请求 START_BATTLE | 再在每幕 OnRoundStart 无条件播放同一句 |
| 普通交锋击杀 | `RencounterManager` 请求 KILLS_OPPONENT，并分别处理 DEATH / COLLEAGUE_DEATH | 在每次伤害、每颗骰命中时播击杀 |
| 自定义击杀事件 | `BattleUnitModel` 死亡处理有 attacker 时调用 attacker.OnKill，再转发被动等 | 持续伤害无攻击者、复活、多目标击杀时错误归属或重复 |
| 死亡、同伴死亡 | 原生战斗呈现路径；自定义逻辑可监听被动 OnDie / OnDieOtherUnit | 死亡后销毁播放器，或把敌人死亡当同伴死亡 |
| 胜利 | `StageController` 胜负处理请求胜方 BATTLE_VICTORY | 每个敌人死亡都播，或误当成 End 完整剧情 |

群攻有独立的 `BattleFarAreaPlayManager` 路径。普通交锋的语音接通不能自动证明群攻、反击、持续伤害和特殊击杀同样覆盖；按功能要求分别检查。

建议调度规则明确写入实现：

- **去重范围：** 开幕按接待或 Wave；阶段按阶段编号；击杀按被击杀单位的本次死亡事件。支持复活时不能仅用永久单位 ID 去重。
- **同刻多人说话：** 使用一个前景语音队列或明确的有限并发；多名单位开幕时不要所有人同时播放。字幕随真正开始播放的条目呈现。
- **优先级：** 剧情/阶段宣言、死亡、击杀等顺序按设计确定。排队、丢弃与抢占要有统一规则，过期的击杀语音不延迟到下一场。
- **音量：** 配音使用 `OptionDataModel.GetVolumeVoice()`，它已含 master × voice。不要再乘一次总音量，也不要使用 VolumeFX 代替；选项变化时更新正在播放的语音。
- **清理：** 跳过剧情、结束接待、退出、重试和重载时清理队列、停止播放、失效旧异步请求；下一次接待重新建立事件状态。
- **失败：** 缺 clip 保留字幕，缺台词记录键并回退；错误只做有意义的日志，不每帧重试播放或重复读磁盘。

### 为什么

开幕会同时遍历多人，群攻可能一次杀死多人，死亡对象还会退出场景。只实现“某事件 Play 一次”，无法保证这些真实流程中的可听性。

### 带来什么效果

语音有明确说话顺序，不重叠轰鸣、不跨场残留，音量与暂停/跳过行为符合玩家操作。暂停时声音是否继续由项目规则明确决定并实测，不要默认设置 `ignoreListenerPause=true`。

## 第 10 步：优先模拟剧情与语音流程，读取日志后部署

### 做什么

先静态核对路径、XML 标签、ID、重复项与录音清单，再通过本项目构建与模拟工程检查。模拟正常推进、跳句、跳过、日志重播、音量和战斗恢复，为本次运行指定一个主日志，记录行号、语音键、实际 clip、事件次数、停止与恢复结果，再读取分析；方法见[第 08 章](08_编译与部署.md)。音频在外部播放器能打开，只能证明文件基本有效。

| 检查场景 | 通过条件 |
|---|---|
| 战前、战后完整剧情 | 正确文件在正确时机出现，失败结算不误播胜利结局 |
| 战中阶段 | 只触发一次，读完与跳过均恢复战斗，其他剧情打开时不覆盖 |
| 逐句配音 | 文本与声音一致，快速下一句停止旧句，日志重播仍有效 |
| 自动推进与淡出 | 有声、静音、None、缺录音都不会卡住或错误截断 |
| 多人开幕与每幕提示 | 符合接待/Wave/幕的去重范围，队列与字幕一致 |
| 击杀、死亡、同伴死亡 | 对象关系正确；普通交锋与所需群攻/反击/持续伤害路径分别验证 |
| 复活再死、多目标击杀 | 按死亡事件去重，既不永久禁声，也不重复刷屏 |
| 音量和生命周期 | master / voice 调整正确，退出和重试后无残留或旧请求回放 |
| 多语言与缺文件 | 文本与录音按声明策略回退；缺失项有可定位日志 |

记录构建版本、所用资源哈希、验证场景与结果，再同步发布文件。当前教程中的模板和接入建议不等于运行时已完成；交付记录要分别说明字幕、音频加载、播放控制和模拟试听是否通过，并保留主日志与必要音频附件。仅为模拟环境未覆盖的具体场景问题补游戏内验证，不将启动游戏设为默认步骤。

### 为什么

XML 加载成功、DLL 编译成功、声音能播是不同结论。真正可用的语音还要求时间、人物、字幕、场景恢复和选项行为都正确。

### 带来什么效果

获得可复现、可逐项验收的对白与语音，而不是只能在某次单独调用中发声的演示。
