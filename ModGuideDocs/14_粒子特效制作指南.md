# 粒子特效制作指南

本指南面向可变的挥舞、突刺、打击、防御、范围、特殊、点位特效。复用流程为：**核实实际调用 → 同方法重放原始数据 → 用概念图明确视觉职责 → 组合运行时模块 → 逐类视觉验收 → 真实角色上下文 → 精确部署验证**。

**用户已否决旧 `candidate-r4` 美术。** 上轮技术检查和内部预览未证明基本美感达标；其规则化月牙、实心金针、低位匀速波、固定五系统不能再作为推荐模板。“不能完全复刻”允许继承原版成熟的轮廓、笔触、动线、明暗和节奏，也允许运行时引用用户游戏内的原生视觉资产；差异应体现在主题、局部笔触、层间组合与事件编排，而不是刻意弃用成熟基本功。

**当前用户配色修改：**“斩击目前质感还不错，就是黑光太违和，不如改成白金光。”保留Slash10已成立的笔触、破口、主副动线与起刀时序，将黑体改为有亮暗等级的暖白/淡金余光。原版的黑体是技术来源事实，不是主题必须遵守的美术要求。该白金修改已在Slash11完成独立配色/context复审，用户明确满意；不将其通过结果扩展到其它动作。

**最新状态与Hit纠正（2026-09-13）：**白金Slash11已通过原reviewer的配色/角色上下文复审，用户明确“这个斩击我很满意”，其材质与动作固定。Hit则被重新定义为“比横向斩击更有力的刀剑纵砸”，Hit01–04拳式爆点方向全部否决；应恢复Greatsword主刀拖迹，按“主势纵落→剑尖触地→退散”编排。压波/碎光只能次级，不能放大拳星核或将Slash11旋90°代替。当前实施以重制设计第7.4节为准。

## 1. 从实际书页找到真正播放的资源

记录 Card ID、Range、Motion、Detail、EffectRes、ActionScript，并查能力是否动态覆盖或主动创建效果。不能只按角色名搜索 PNG。

1. 阅读 `SteriaBuild/SteriaModFolder/Data/CardInfo.xml` 与对应本地化，区分普通攻击、反击、远程和群攻。
2. 有 ActionScript 时，读取对应 `BehaviourAction_<名称>` 的 `GetMovingAction` 或 `SetFarAreaAtkEffect`。`movingAction.customEffectRes` 能覆盖 XML；FarArea 不靠普通 EffectRes 完成整套播放。
3. 用 `SteriaBuild/VFXSource/NativeAttackReference/references/all/AttackEffectPathInfo.xml` 的 Name/FilePath 关系查资源，再用 manifest 的 `roots[].resource_path` 找 prefab 和依赖。
4. 对主动创建的效果，继续查 `CreateBehaviourEffect`、`Util.LoadPrefab`、`Resources.Load`。图片名和材质名都不能证明书页归属。

例如 `BehaviourAction_BlackSilence_LongSword.cs:21` 实际指定 `FX_PC_RolRang_ShadowSlsah`。玩家罗兰粒子库位于 `prefabs/battle/diceattackeffects/new/fx/pc/rolrang/`；`new/chapter7/blacksilence_j` 是普通 Sprite，不能据此推断整套罗兰攻击。

```powershell
rg -n 'Christasha|9009006|EffectRes|ActionScript' SteriaBuild/SteriaModFolder/Data/CardInfo.xml
rg -n 'customEffectRes|SetFarAreaAtkEffect|CreateBehaviourEffect' SteriaBuild/Assembly-CSharp -g 'BehaviourAction_BlackSilence*.cs'
rg -n 'FX_PC_RolRang_ShadowSlsah' SteriaBuild/VFXSource/NativeAttackReference/references/all/AttackEffectPathInfo.xml
```

先复用已有原版库，仅在资源缺失或版本变化时定向导出。导出范围及剥离 Mono 字段等未知见 `SteriaBuild/VFXSource/NativeAttackReference/README.md`；“所有注册根已遍历”不是所有动态调用都已穷尽。

## 2. 先同方法重放原始数据，再解释其美术

对参考记录具体动作、实际帧、原始层级和时间，而不是只数 PS。每层回答：视觉职责、触发时刻、寿命、速度/旋转/大小曲线、材质与排序、挂点/父尺度、回收责任。

原始输入从 prefab 的 Transform、PS、Renderer、Mesh、Texture、Material、Animator/Clip 一起恢复。不能只取纹理，也不能把原生 torus 归一化成 XY 平片后声称等价重放。Constant 曲线不能把 inactive 的 minScalar 当有效下限；原始片长也不等于战斗秒数，调用方可能改变动画速度。

本次使用的实际锚点：

| 来源 | 已观察的依据 | 应继承的关系 |
| --- | --- | --- |
| 罗兰 Slash_Down | 原 torus、原 Shader、两套旋相；重放经历近环、开放 C、碎锋和余迹 | 瞬间 C 不是固定几何模板；保留快慢主迹与侵蚀形成的锋势 |
| 罗兰 Dagger | 原 Flash 平面、锐线、烟和有向碎屑 | 窄核心与较宽聚束/反冲域并存，不能只剩一条金针 |
| 罗兰 Greatsword / GloveTrail_cross | 前者含主刀、压波、地裂；后者含锐亮核和大型空间拖迹 | 当前Hit恢复Greatsword Main1/Main2/Swing的纵砸主势；Glove拳核不再作Hit来源，地景与大烟幕也不整套搬入 |
| 邵 Xiao_AreaTrail1 | 主波、异速副波、火体、碎屑与侵蚀 | 集中释放和回卷展开；主题版改变火色/火舌身份，保住能量等级 |
| Orchestra_Start | 原始重放是多层大谱环和圆点 | 可提取线条/曲线或改造为开放弦带，不能误称天然就是几条细弦 |

参考和主题候选必须采用同一资源转换、同一 Shader、同一时钟与相机。当前原生参考已能保留原编译 Shader 并确认 `isSupported=True`；若未来某层只能近似重建，应逐项注明原始/近似部分，并让对照双方用相同路径。输出称为 **original data Editor replay**，不是游戏实战录像。不同源 prefab 的独立自动取景不能用于比较绝对尺寸。

### Main1 与 Main2 必须按运行态分别判断

本轮一个关键返修来自把材质默认值误当播放职责：

- **Main_Trail1 / MainTrail Shader**：原材质默认 `MainColor=(2,2,2,0)`，但原 Animator 更新后的 MPB 采样为暗体 `MainColor=0`、窄锋 `OutColor≈1.5`。把宽体恒定设成高 HDR 金色，会出现油箔/蜡面。
- **Main_Trail2 / 独立 Outline Shader**：不能因其材质默认黑色就压黑。运行态 ACTUAL f=1/3/6/10 已采到 `MainColor=(3,3,3,0)`，它承担早段亮锋。09 的附加18ms延迟因此造成17ms全黑起刀；10恢复原生零延迟后解除该问题。
- 两条 Trail 的曲线、Shader 和实际颜色通道各自保留；Main1 的数学不能套到 Main2。“第二层都是暗描边”与“两条同形都是多余壳”都是错误概括。

这段说明原始运行态，不规定新主题必须黑白配色。当前Slash应将原黑覆盖区域映成较弱的暖白/淡金余光，切锋仍更亮，破口保持可透。映射不必只是原RGB乘Tint——原RGB为0时相乘仍为黑；可以按该层职责和时间包络赋予新的主题色，但不能又把整块宽体固定成持续高HDR白金板。该改变已由Slash11的实际新画面复审通过。

完整证据见 [MainTrail 通道与数学](../docs/superpowers/references/christasha-native-redesign/native-maintrail-shader-semantics.md) 及 `SteriaBuild/VFXSource/ChristashaNative/evidence/slash-role-probe/original/metadata.txt`。

Main1 的已核实要点是：`MainTex.r` 控制覆盖，`Noise.r` 与粒子 `COLOR.r` 产生窄锋，`ColorNoise.r` 参与宽填色及 U 向覆盖。`OutColor` 控制窄锋，`MainColor` 控制宽填色；两项相加。`MaskPower` 是门限减项，不是幂指数。该片元不读 MainTex 的 alpha 或两种颜色参数的 alpha。只有透明 alpha、RGB 全白的图片不能充当正确的覆盖 mask。

## 3. 把概念图拆成职责，不把静帧当动画

主题先来自实际卡图；克丽丝塔夏素材位于 `SteriaBuild/SteriaModFolder/Resource/CombatPageArtwork/`。本轮概念板及溯源在 `docs/superpowers/references/christasha-native-redesign/concept-gold-tide-v1.*`。

概念板需要转译成四项可观察行为：

1. 一条更强主刃与错时、错向的细副迹，不能全部等粗等亮。
2. 负形真正切进主体；粗残片、中等金丝、细光屑有不同速度和寿命。
3. 当前Hit先有刀剑纵落主势，触地才有次级压波与碎光；概念中的拳式爆压不能当其主形。突刺仍具有尖锋、聚束、反冲的空间层级。
4. 汐音有厚度、开口和回卷的浪锋，弦线沿浪势延伸并分时退场。

当前Slash使用较强暖白锋、低一级的白金流/淡金余光及金屑，原黑体不再作为其必需层。其它主题的暗琥珀/海灰也只是选择，不是统一规定。各职责不使用同一Tint；颜色沿本次设计的每帧能量映射，不能仅通过统一加亮修复形状。Glow/HDR可以服务短暂重音，既不一律禁用，也不拿持续大泛光掩盖厚片。

允许直接引用用户本地游戏的 Mesh、纹理、Shader 或视觉模块，并在运行时克隆改造。模组不重新分发游戏原图、Mesh、Shader 或参考包；发布本项目代码和原创局部输入。避免只给原 prefab 改名或整体染金，实质区别要落在主题色阶、破锋 mask、副迹、散射或节奏。Imagegen 适合提供局部断笔、泡丝、金叶、开放弦带；不能将四宫格裁成四张完整攻击贴图。

## 4. 运行时按职责组合，保留采样和资源边界

当前原生原型入口在 `SteriaBuild/ChristashaNativeParticleLibrary.cs`，说明见[原生源 README](../SteriaBuild/VFXSource/ChristashaNative/README.md)。已接受 Slash 的保存快照及指纹分别位于 `accepted/slash-10/`、`accepted-slash-10.json`；工作区源码可能同时增加其它动作，不能凭文件名认定它仍与已接受快照逐字节一致。

```csharp
// gameResolver 使用本地游戏 Resources.Load<GameObject>(path)。
// 原创 localBrush 的可读性/采样格式按本库合同提供。
var library = new Steria.Vfx.ChristashaNativeParticleLibrary(gameResolver, localBrush);
var instance = library.CreateSlashPrototype(parent); // inactive，原生单位
var visual = Steria.Vfx.ChristashaNativeParticlePlayback.Play(instance, 19037u, 1f);
visual.Advance(deltaTime); // 调用方每帧一次
visual.StopAndClear();
// 调用方清理全部实例后再 Dispose library；brush 由传入方管理。
```

**先防激活副作用。** 在 inactive staging parent 下克隆，激活前确认游戏 MonoBehaviour、音频、碰撞、刚体、相机、灯光已移除，Animator events/root motion已关闭。不能先激活再等待下一帧删除，否则 Awake/OnEnable 已可能产生震屏或逻辑副作用。保留的视觉层级与原始资源本身不能被修改。

**逐帧还原原采样后映色。** 每个 Renderer 独立缓存原始颜色通道：先还原原值 → 推进 Animator → 保存本帧原始 MPB → 按该 Shader 的职责映色 → 提交。常量动画通道未必每帧重写；若直接把上一帧主题 MPB 再相乘，就会反馈变暗。只改 cloned Material 也可能被 Animator MPB 覆盖。保留非主题属性及 alpha 语义，不将所有颜色 alpha强设1。

**同一个时钟。** Animator、PS和新增模块按同一增量推进；手动模拟时保持PS暂停，只主动推进非sub-emitter系统，避免父子或sub-emitter重复模拟。新生粒子之后执行需要的零时长Simulate同步，不预热、不移动事件时间。Play不增殖层级，StopAndClear清空全部系统；调用者拥有根对象及取消/结束清理。

**分清缓存与实例。** 原 Resources只读；需要动画/主题修改的材质和MPB按实例隔离，不逐帧读取Renderer.material制造隐性副本。模板、克隆材质、派生覆盖纹理和局部Mesh的所有权由library管理。原sharedMaterials可能有未使用null尾槽，只检查实际有效槽的Shader和渲染，不能把空槽误报为平台不支持。

七类都按“来源 → 保留职责 → 主题变化 → 事件/挂点 → 接受帧”填写recipe，而不是套固定弧度或粒子数：

| 类型 | 制作与变化方式 | 最小视觉判断 |
| --- | --- | --- |
| 挥舞 | 先复现实际主锋/轮廓曲线，再调整局部笔触、副迹相位与散射；保留Slash10笔触/动线，Slash11已按用户要求重映白金并获接受 | 主锋先被看见，副迹解释余势，峰后有明显落差；不强制黑体 |
| 打击 | 恢复Greatsword Main1/Main2/Swing原主刀、父系与曲线，按确切Hit剑指地姿态布置纵落；落点层延后 | 先看见重刀纵砸，再触地退散；不能只剩拳爆，也不能将已接受Slash旋90° |
| 突刺 | 保留锐核及轴向运动，再设计聚束、侧向反冲和空气尾迹 | 核心尖锐但攻击域不必是一条窄实心针 |
| 防御 | 先找真实防御动作和承压点，再决定弧、片、屏障或散射，变化由防御语义决定 | 压力方向清楚；与G挂点/防御者一致，不因套模板像落斩 |
| 范围 | 分开施法、展开、回卷与目标反馈，场地大小由真实参与者和设计共同决定 | 一次明确释放，有主次与传播；不等于低位条带匀速移动 |
| 特殊 | 先规定事件语义，再选择谱线、状态流、局部光或其它模块 | 能看懂发生了什么，不能只有常驻装饰或满屏噪声 |
| 点位 | 从实际接触/释放事件设计短核心、碎散和余迹，大小按上下文标定 | 位置稳定、触发一次，表现不伪造未成功的伤害 |

防御、特殊和点位的通用流程不授予新书页绑定或美术PASS。当前各动作的最终参数由实现owner在接受后补入recipe；不把Slash的数值扩展为全库规则。

## 5. 逐类预览验收，再进入角色上下文

先做一个动作并接受，再推广已成立的方法。原始参考与主题候选使用同一Shader、转换、固定相机、seed、时钟及输出方式；先看正常速度媒体或明确标注的时标序列，再看早期、峰值、退场。若只审查时标帧，不声称连续观看了视频。

Slash10采用同方法120Hz手动时钟、60fps输出；代表性帧含0/17/33/50/100/167/283/500ms，起刀专门补看前两帧。对其它动作按实际事件选点，不把这些毫秒数当通用寿命。每份候选保留原/新暗底、中底、灰度和帧时间，检查锋口、负形、透明边、主次及峰后落差。

独立评审输出PASS/REVISE/BLOCK。REVISE需要指明动作、帧与可见问题，回原owner修最小表面，只重跑受影响证据。原生Shader可用、曲线一致、粒子数量或hash正确仅证明技术路径，不能推翻“第一眼仍是香蕉片/油箔/金条”的美术拒绝。反过来，瞬间近环/C本来就存在于原版运动中，不能仅凭一个孤立轮廓禁用它。

保留完整候选和来源hash，重新输出使用新目录，不覆盖已接受或被拒证据。固定seed用于回放；另一个seed只检查细节变化没有破坏方向、接触点和事件顺序。性能记录关注实际峰值粒子、材质实例、透明覆盖与纹理/几何内存；不以固定系统数量为成功标准。

## 6. 用真实PNG、PPU、pivot和父层校准

角色合同见 [native-attachment-contract.json](../docs/superpowers/references/christasha-native-redesign/native-attachment-contract.json)。旧“3单位中性人形”不能替代实际角色尺寸。

| 层级事实 | 本次已核实值 / 处理 |
| --- | --- |
| 角色散图 | 512×512，PPU50；像素位置须按实际Sprite pivot换算，不能按效果alpha包围盒重居中 |
| legacy XML pivot | `((pivot_x+512)/1024, (pivot_y+512)/1024)` |
| Appearance / Motion scale | 原始为1；完整父系仍需保留 |
| 原生攻击根 | 局部 `(-1.92, 2.52, 0)`；尺度诊断另用z=-0.15作显示深度 |
| map scale | S=3、M=2.25、L=1.5；适用时还叠加 `customizeData.height/170` |
| 此Native根脚本 | `FX_Script_AttackBasic`：Initialize scale=1，SetScale为no-op，**不走普通DiceAttackEffect的2×掷骰缩放** |
| 原生初始化角 | Slash/Dagger为(0,0,0)，Greatsword为(-10,0,0)；是具体source合同，不是所有效果通则 |
| 面向 | 继承角色完整父系镜像一次，不在视觉子层再翻一次 |

### 群攻与复制骰合同
