# 粒子特效制作指南

本指南使用克丽丝塔夏 V2 作为首个制作案例，面向可变的挥舞、突刺、打击、防御、范围、特殊、点位特效。目标是使用真实 Unity ParticleSystem 制作能在战斗中正确播放、可以从保存参数重新生成的效果。

**交付状态：candidate-r4 已通过独立视觉与接入验收，并定向部署。** 文中的设计范围与最终实现参数分别记录；可执行命令和交付边界见第10节。正式发布七个粒子prefab，Guard为可运行编辑器示例；没有给防御页新增绑定，也没有声称完成整场游戏实战。

## 1. 先查真正的播放入口

从实际书页开始。记录 Card ID、Range、Motion、Detail、EffectRes、ActionScript，随后查能力是否动态覆盖或主动创建效果。不能只按角色名搜索PNG。

1. 阅读 `SteriaBuild/SteriaModFolder/Data/CardInfo.xml` 与对应 `Localize/cn/BattleCards/`，确定普通攻击、反击、远程还是群攻。
2. 如果有 ActionScript，读取 `BehaviourAction_<名称>` 的 `GetMovingAction` 或 `SetFarAreaAtkEffect`。`movingAction.customEffectRes` 可以覆盖书页EffectRes；FarArea走专门的效果管理器，不靠普通EffectRes完成整套播放。
3. 使用 `SteriaBuild/VFXSource/NativeAttackReference/references/all/AttackEffectPathInfo.xml` 的 Name/FilePath 关系定位原版注册资源，再用manifest的 `roots[].resource_path` 查prefab及依赖。
4. 对能力主动创建的效果，继续查调用中的 `CreateBehaviourEffect`、`Util.LoadPrefab` 或 `Resources.Load`。材质名、图片名不能证明它属于该书页。

已有明确示例：`SteriaBuild/Assembly-CSharp/BehaviourAction_BlackSilence_LongSword.cs:21` 指定 `FX_PC_RolRang_ShadowSlsah`。真实粒子资源位于 `prefabs/battle/diceattackeffects/new/fx/pc/rolrang/`。单独查看 `new/chapter7/blacksilence_j` 只会得到普通Sprite，不能据此推断玩家罗兰整套攻击的实现。

以下为已存在路径上的只读查询示例：

```powershell
rg -n 'Christasha|9009006|EffectRes|ActionScript' SteriaBuild/SteriaModFolder/Data/CardInfo.xml
rg -n 'customEffectRes|SetFarAreaAtkEffect|CreateBehaviourEffect' SteriaBuild/Assembly-CSharp -g 'BehaviourAction_BlackSilence*.cs'
rg -n 'FX_PC_RolRang_ShadowSlsah' SteriaBuild/VFXSource/NativeAttackReference/references/all/AttackEffectPathInfo.xml
```

先复用已有原版库。只有所需资源确实缺失时，才按 `SteriaBuild/VFXSource/NativeAttackReference/README.md` 做定向导出。该库不发布原版图片；不可将 `references/` 复制到模组资源目录。

## 2. 把参考拆成可验证的层级和事件

从manifest找到root、ParticleSystem、ParticleSystemRenderer、材质、Transform、Animator/AnimationClip的元数据。对每一层填写一行：

| 字段 | 需要回答的问题 |
| --- | --- |
| 视觉职责 | 是主体、亮锋、速度线、碎屑、雾、范围波还是点位反馈？ |
| 发射时刻 | 是否t=0爆发？是否晚于主体？是否由动画/脚本激活？ |
| 寿命与数量 | 主锋活多久？余屑多久？burst还是持续发射？ |
| 运动与形状 | Mesh/Billboard/Stretch各做什么？角运动、速度、大小、Noise分别如何变化？ |
| 材质与排序 | Alpha还是Additive？主体与高亮是否混为一层？透明排序是否有意义？ |
| 空间 | Local还是World？随谁移动？尺寸经过哪些父级倍率？ |
| 回收 | 发射何时停止？粒子何时清空？根对象由谁销毁？ |

本次已核实的最小参考组合：

- 罗兰 `fx_pc_rolrang_slash_down`：两个Mesh主拖迹在t=0各发射1个，寿命0.6/0.7s并有Rotation/Color；10个小粒子延迟0.1s发射，有独立Velocity/Noise。其优势是主形和余迹分工，不是系统数很多。
- 罗兰 `fx_pc_rolrang_dagger`：Mesh尖锋有Velocity/Size；Stretch光针、Billboard烟分别收尾。突刺的速度和轴向应在这些模块中形成。
- 邵 `fx_mon_xiao_areatrail1`：主波、多组短副波和延迟碎屑共同形成范围动作。学习范围前锋与余波关系，不能把火焰或龙改成金色后作为原创交付。
- 异想体 `fx_illusioncard_4_n_orchestra_start`：四条独立Mesh线加粒子，线条有Size/Rotation/Color。可用于理解特殊/音乐反馈的稀疏层级。
- 寒昼 `寒昼小兵_刀光_斩击`：Mesh刀光、晚约0.02s的烟、约0.05s的光针、约0.07s的爆点。参考导出位于 `SteriaBuild/VFXSource/AnhierBlueWhiteSlash/hanzhou_vfx_reference_dump.txt`。

结构数据见 `docs/superpowers/references/2026-09-12-christasha-particle-native-evidence.json`，每层可回查原元数据路径。带`minMaxState`的Unity曲线必须先确认模式：Constant时不要把inactive的minScalar误读成真实下限。原始Animator片长也不是最终战斗秒数，游戏脚本可能修改Animator.speed。

## 3. 原创组合与配色

先选本次真实书页卡图，写一句形状/材质目标，再做粒子。克丽丝塔夏实际卡图位于 `SteriaBuild/SteriaModFolder/Resource/CombatPageArtwork/`，本轮已查看金火璀璨之潮、海银工坊：埃利耶、迸射流光、汐音：光耀万海。

本轮的主题是奶白锋口、蜜金潮带、局部琥珀体积和少量金屑。建议初始色板：锋口`#FFF4C4`，主体`#EDBE55`，暗金`#B77A2E`，局部雾影`#51452E`，碎屑`#FFD983`。这是设计选择，并非声称精确采样。

主体承担体积，局部Core承担亮锋，Mist承担空气感。先关闭额外高亮调好主体；再加锋口；最后加碎屑和雾。噪声优先改变内缘和旧尾，保留连续外锋。出现塑料片时，优先改厚薄、破口和颜色层次；出现沙子时，降低全体alpha噪声并恢复完整主形；不要只靠增亮修图。

参考可复用结构关系，成品的mesh、纹理、shader和编排需要本项目原创或有明确使用许可。原版像素重染色、原prefab改名、整套参数原样搬运都不属于本轮原创。Imagegen可以辅助制作原创笔触mask或设计板，但整张动作图加一圈小点不能替代粒子动作设计。

## 4. 七类recipe

共享模块按职责定义：Stroke（弧/楔/针主体）、Core（小面积亮锋）、Streak（有向光针）、Mote（低频碎屑）、Mist（低alpha雾）、Wave（开放环/横波）、Chord（稀疏弦线）。不要求每种效果都启用全部模块。

| 类型 | 首轮配方与调参范围 | 动作必须保留的特征 |
| --- | --- | --- |
| 挥舞 | Stroke开放弧130–175°；前0.14s角程70–110°后减速；Core比主体短；10–18枚切向碎屑；2–4枚雾 | 明确前锋和轻尾，外弧连续，旧尾先退，不能闭环或长期悬停 |
| 突刺 | Stroke尖针长宽比3–6；0–0.08s快速推进；0–3条侧丝；6–12枚轴向光针 | 单尖锋和长轴优先，不能用斩击旋转或粗光柱代替 |
| 打击 | Stroke短楔/短扇；扇角45–100°；小Core；5–8条扇向碎屑；3–5枚雾 | 前部宽钝，先压后散，峰值短；轮廓不同于突刺 |
| 防御 | Wave开放竖弧120–165°；0.06–0.15s收压；中段Core；反向Streak | 上下重量平衡，中段迎击；不做下端重斩或常驻护罩 |
| 范围 | 一份横向Wave前锋；低位Mist；稀疏Mote；宽度按敌阵跨度计算 | 清楚传播方向；避免按目标数复制全场光环；保留角色/UI阅读空间 |
| 特殊 | 3–5条Chord；小Wave；稀疏Mote；调整相位、幅度与间隔 | 有独立事件语义，不用满屏装饰掩盖施法者 |
| 点位 | 小Core；5–9枚Streak；2–4枚Mote；总寿命约0.15–0.45s | 世界点稳定、由真实事件触发一次；不继承目标镜像 |

本轮普通攻击初值：Slash约0.08–0.16s达到大形、总余迹约0.65s；Hit约0.05–0.1s峰值、总0.5–0.6s；Pierce主体0.3–0.4s、总0.55s。它们不采用教程13中另一贴图库的“完整PNG保持250ms”合同。

先调大形与时间，再调材质，最后才调数量。随机变化只作用于细节，初值建议尺寸±10%、发射角±8°及小范围数量变化。前锋方向、接触点、事件顺序不随机。每个变体保存recipe名称、版本、seed、色板与派生资产hash；稳定seed用于复现，第二seed用于证明变化没有破坏动作。

防御和特殊在本轮首先是制作配方，不能因此擅自给所有Guard、Evasion或特殊页绑定新资源。

## 5. 挂点、尺寸和纯视觉合同

本轮冻结bundle名为 `steria_christasha_particle_v2`，七个目标prefab为 `ChristashaV2_Slash`、`ChristashaV2_Hit`、`ChristashaV2_Pierce`、`ChristashaV2_Projectile`、`ChristashaV2_Cast`、`ChristashaV2_Area`、`ChristashaV2_Point`。候选独立接受后才进入部署。

纯Unity共享driver位于 `SteriaBuild/ChristashaParticleVisual.cs`，是普通C#类。接口为 `Steria.Vfx.ChristashaParticleVisual.Play(instance, seed, playbackSpeed)`、`Advance(deltaTime)`、只读`Duration`、`StopAndClear()`。driver不自行Update或销毁根；生产adapter与preview每帧调用一次Advance。内部Pause+Simulate防止自动/手动模拟叠加；所有粒子、shader age与辅助曲线使用同一时钟。

- 资产默认向左`-X`；战斗平面`XY`，`Z`仅作深度。pure visual不再次翻方向、不读取BattleUnit、不判伤害。
- 普通Slash/Hit/Pierce挂施法者J/H/Z原生pivot，完整继承旋转、缩放、镜像一次。防御挂防御者G。不要为了接触敌人将近战根挪到目标或按双方斜率旋转。
- 近战根沿用原生2×及后续`SetScale(1+factor)`，再继承角色父系倍率。不要同时把世界尺寸写入PS.startSize又乘一遍地图倍率。相机中按角色可见高度`Hchar`校准：Slash高约1.15–1.45Hchar，Hit宽0.95–1.4Hchar，Pierce长1.2–1.6Hchar/厚小于0.3Hchar。
- Projectile从Fire世界点发出，采用中立场景根和发射者朝向。普通Initialize没有命中成功信息时，不自行在目标上放确认命中Point；原生受击反馈继续工作。
- Cast、Area、Point分开定位。Area只一份，宽度覆盖敌阵跨度并留适量边距；Point使用成功目标atkEffectRoot世界点，不继承目标负缩放或再乘角色倍率。
- 视觉时间和对象存活时间分开。后续SetDestroyTime只调整销毁，不重新拉伸已经开始的粒子；正常结束、取消、目标消失都清理拥有的实例。

## 6. 群攻与复制骰生命周期

`SteriaBuild/Assembly-CSharp/BattleFarAreaPlayManager.cs` 的BeginAction会通过ActionScript创建FarAreaEffect；ActionPhase等待`isRunning=false`后结算，调用`GiveDamageFromManager(successfulList)`，随后等待`IsDoneEffect`。视觉不直接调用GiveDamage、不从粒子碰撞造成伤害。

汐音本轮初始编排：Cast在0–0.32s低位汇聚并上行；约0.3s起Area展开；约0.5s释放manager继续结算；收到成功列表才创建Point；剩余0.5–1.1s播放余音后完成。

`BehaviourAction_Steria_ChristashaXiyinV2` 调用原生 `SetActionDelay(0, 0)`，让自身0.5s的释放门闸决定视觉时刻。若省略此步，manager默认1s前等待会使预览与真实回调错位。原生Start/EndFarAreaPlay会为下一张页恢复默认等待值。

每颗真实群攻骰创建独立、可清理的播放周期。测试包含成功目标、零成功目标、多个目标和复制后的下一颗骰。重复回调不重复生成Point，成功目标去重并限制16个；零成功目标也会完成余波并退出等待。取消或资源缺失时结束视觉状态，不将战斗留在isRunning等待中。

本轮`9009006`是独立新群攻入口。其他现有Xiao ActionScript保留，不因EffectRes迁移就宣称其特殊动作也已重制。最终绑定数与范围按主线程基线和XML差异核实。

## 7. 材质与预算

材质、纹理与几何共享。每实例变化用MaterialPropertyBlock或粒子CustomData，避免逐帧访问Renderer.material制造材质副本。AB仅序列化Unity原生组件与原创资源；生产driver作为普通C#对象在运行时创建，防止Unity项目程序集与模组DLL的脚本引用不一致。

所有效果明确设置对象Effect layer、Particle sorting layer及各职责order。Layer与sorting layer不是同一概念。Body和Core不能因深度/负缩放产生背面剔除或透明排序反转。Additive只服务局部亮锋，不拿全屏Additive补体积；不默认加Bloom、音效、震屏。

首轮建议从每近战3–6个有效PS、几十个活跃粒子开始，纹理按职责使用256–512px；范围共享Area，点位才按目标数量增加。这是起步预算，不是已测结果或硬性质量指标。需要更多层时先说明新增职责；低于此数也可以达到视觉目标。

候选记录至少包括：峰值活跃粒子数、同时存在实例数、透明覆盖范围、材质实例数、纹理解码体积和真实引擎帧耗时。优先减重叠大透明面和多余副壳，其次减不起作用的碎屑；不要为了减少粒子把主形改成静态整图。

## 8. 可复现预览与接受

先从新bundle重新加载prefab，再用与生产相同的driver推进真实Unity粒子并由GPU渲染。只看母图、CPU合成或源码断言不能证明本轮粒子视觉完成。每份证据记录source/bundle hash、recipe、seed、帧秒、相机与坐标。

1. 正常1×速度观看Slash/Hit/Pierce与完整汐音短片；不同动作固定同一相机，不通过更近镜头制造力度。
2. 近战阶段初值0/17/50/100/180/350/600ms；汐音0/150/320/500/750/1100ms。候选Duration改变可调整采样，但必须覆盖早期、峰值、回收与结束。
3. 至少代表性检查左右朝向和两个体型；近战要有实际动作/挂点或明确标注的中性剪影。诊断辅助线用于确认pivot，孤立展示不能替代附着验证。
4. 暗战斗底与浅灰底各检查边缘：不能有透明矩形、黑边、闭合硬圆、机械阶梯、重复透明壳。金色体积不能被白光吞没，外锋连续而尾部有方向破碎。
5. 比较逐帧粒子数量、位置和寿命，确认主形也在真移动且每帧只推进一次；同seed可重放，第二seed只改变细节。
6. 通过独立预览评审取得PASS/REVISE/BLOCK。REVISE须指明动作、帧和视觉职责，回原owner修最小问题，然后仅重跑受影响验证。

动作辨识是关键：Slash要像弧扫，Hit要像短重击，Pierce要像轴向推进；汐音要看得见施法者、单一范围前锋与成功目标点位。三个攻击只有角度区别，或者群攻只是放大普通刀光，都应返修。

## 9. 构建、绑定和部署收口

本轮使用Unity 2019.3.15f1 / Built-in Gamma / D3D11，独立项目位于 `SteriaBuild/VFXSource/ChristashaParticleV2/UnityProject`。原生构建器验证七个显式根、材质、排序、清空、重播、倍速与调色隔离。r4更新的纯C#驱动不序列化进AB，因此复用未变化的r3素材包，并用新驱动重新完成原生渲染。不能用旧ChristashaDawnCombat包替代。

最终依次核对：新prefab无missing script/丢纹理/looping；共享driver与Release DLL编译；精确书页绑定及群攻manager合同；独立视觉接受；新AB与DLL的部署hash。缺资源必须具名日志并安全结束，不静默回退到废弃的旧克丽丝塔夏效果。

当前已核实主要游戏模组目录是 `D:/Game Center/Steam/steamapps/common/Library Of Ruina/LibraryOfRuina_Data/Mods/SteriaModFolder`；C盘入口是链接别名，部署按解析后的真实路径去重。详见 `ModGuideDocs/08_编译与部署.md`。部署前备份本次涉及文件，完成后从本次验证输出核对DLL、新bundle及相关XML的SHA256；只复制AB而遗漏DLL不算部署完成。

## 10. 本版操作入口与交付记录

详细实际参数、源码函数、材质和Guard示例操作见 [V2源目录README](../SteriaBuild/VFXSource/ChristashaParticleV2/README.md)。研究初值不能覆盖该文件中的已实现配方。三个基础mask为512×128笔触、128×64飞沫和128×128薄雾；Mesh承担形状，纹理不包含完整攻击画面。实例只使用五个有明确职责的粒子系统，七个prefab共享材质和基础纹理。

从仓库根目录运行：
