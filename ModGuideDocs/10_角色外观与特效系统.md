# 角色外观与特效系统

本文档详细介绍如何为核心书页制作角色外观（皮肤），以及如何创建和使用自定义战斗特效。

**贴图攻击制作入口：** [13_贴图攻击特效制作流程](13_贴图攻击特效制作流程.md)。按动作阶段制作独立素材，保留黑紫主体 alpha，并区分书页 EffectRes 与角色动作枢轴的职责。

**新角色制作入口：** [12_战斗单位分层建模与核心书页投影](12_战斗单位分层建模与核心书页投影.md)。新流程以美术效果为先，按 head / wearing 制作可复用部件；原版、带参考生图、直接绘制都可选。本章的整图切割与抠图代码保留用于历史资源维护，部件生成优先使用容易去除的纯色背景。

**先锁定用途再定比例：** 战斗单位动作图、剧情正式立绘与卡图分别建规格。“几头身”指全身高度除以头高；“头：身”若把身定义为下巴至脚底，两者就不能互换。本次 AceTaffy 的最终口径为原版 Default 实测约三头身，替代先前两头身和“头：身＝１：２．５”的草案。制作时还须锁定头部长宽、肩胸腰宽、下巴与衣领遮挡、统一尺度及表情锚点，先完成 Default 再派生动作。测量表、可填写的模板规格和验收规则统一见[第１２章：原版比例与模板约束](12_战斗单位分层建模与核心书页投影.md#原版比例与模板约束)；其他角色按选定的原版模板实测确定。

**自定义特效加载先证实工厂链：** 下文的 BaseMod `CustomEffects` 自动登记示例只在其扫描到效果类型时成立。当前仓库的 BaseMod 根层 DLL 扫描与 `Assemblies/` 中能力程序集的加载是两条路径；类名、`EffectRes`、贴图文件与 `Prewarm` 全部正确，仍可能在 `CreateBehaviourEffect` 处返回空。逐一核 DLL 所在目录、扫描范围、注册字典、真实工厂调用和实例的 `Initialize/SetScale`。若采用限定资源名的私有 Harmony 工厂前缀，只接管自己的精确键并放行其他资源；不要依赖稍后可能被 BaseMod 初始化重建的共享字典。可参照 `AceTaffy/src/TaffyVfx.cs` 的四键实现及第 13、14 章的渲染验收边界。

## 一、角色皮肤概述

角色皮肤是核心书页在战斗中显示的立绘/动画。

### 在EquipPage中关联皮肤

```xml
<Book ID="10000001">
    <CharacterSkin>my_character_skin</CharacterSkin>
    <CharacterSkinType>Custom</CharacterSkinType>
    <RandomFace>true</RandomFace>  <!-- 可选：随机面部表情 -->
</Book>
```

| 标签 | 说明 |
|------|------|
| `CharacterSkin` | 皮肤名称，对应 `Resource/CharacterSkin/` 下的文件夹名 |
| `CharacterSkinType` | 散图模式设为 `Custom`，AssetBundle模式设为 `Lor` |
| `RandomFace` | 可选，启用随机面部表情 |

### 方式A: AssetBundle（推荐用于复杂动画）


### 动作图片规格

| 属性 | 推荐值 |
|------|--------|
| 格式 | PNG（带透明通道） |
| 尺寸 | 512x512 或 1024x1024 |
| 色彩模式 | RGBA |

### 角色大小调整（重要）

**关键原理**：游戏会将图片拉伸到固定大小显示，因此：
- 直接缩小图片分辨率（如512→256）只会让图像变模糊，不会改变角色显示大小
- 要调整角色大小，需要改变人物在画布中的占比

**正确做法**：在固定尺寸画布（如512x512）中，通过增加透明边距来控制角色大小。

**参考数据**（来自实际mod分析）：
- 画布尺寸：512x512
- 站姿内容：约200x250像素，占画布约40%
- 攻击动作：约300-400像素宽，占画布60-80%
- 人物底部距画布底部：约100-150像素

**Python处理脚本示例**：
```python
from PIL import Image

# 将原图缩小后放到512x512画布中央
img = Image.open('原图.png').convert('RGBA')
content_size = (200, 200)  # 目标内容大小
img_small = img.resize(content_size, Image.LANCZOS)

# 创建透明画布
canvas = Image.new('RGBA', (512, 512), (0, 0, 0, 0))

# 放置位置（居中，底部留100像素）
x = (512 - content_size[0]) // 2
y = 512 - content_size[1] - 100
canvas.paste(img_small, (x, y), img_small)
canvas.save('输出.png')
```

### 绿幕抠图（历史整图处理示例）

背景纯净且与人物颜色不重合时，可以按绿幕背景处理。以下旧示例是硬阈值示意，没有边缘去色处理；含绿色人物细节时不能直接套用。新部件流程见第 12 章：

```python
from PIL import Image

def remove_green(img):
    """去除绿幕背景"""
    img = img.convert('RGBA')
    pixels = img.load()
    w, h = img.size
    for y in range(h):
        for x in range(w):
            r, g, b, a = pixels[x, y]
            # 绿色明显高于红蓝时视为背景
            if g > 100 and g > r * 1.3 and g > b * 1.3:
                pixels[x, y] = (0, 0, 0, 0)
    return img
```

### 方向翻转（重要：原始动作图默认朝左）

《废墟图书馆》会根据单位当前的战斗方向自动水平翻转整个角色根节点. 精确来说, 游戏并不是修改 PNG, 而是在运行时持续设置 `characterRotationCenter` 的 Y 轴旋转:

```csharp
int yRotation = model.direction == Direction.LEFT ? 0 : 180;
characterRotationCenter.localRotation = Quaternion.Euler(0f, yRotation, zRotation);
```

因此 `ClothCustom` 中只需要一套统一朝向的动作图, 不要分别制作“玩家版”和“敌人版”. 本项目约定原始 PNG **全部朝屏幕左侧**:

| 原始动作图 | 敌方通常为 `LEFT` | 我方通常为 `RIGHT` | 结果 |
|------------|-------------------|--------------------|------|
| 朝左（正确） | 不翻转, 朝左 | 游戏翻转后朝右 | 双方都朝向对手 |
| 朝右（错误） | 不翻转, 朝右 | 游戏翻转后朝左 | 双方都背向对手 |

现有 `Ailierel`、`Christasha`、`Sivier`、`Velia` 的攻击动作都遵循这一规则: 武器、突刺方向或攻击动势在原始 PNG 中指向左侧. 正面站姿可能不容易判断, 应优先检查 `Slash`、`Penetrate`、`Hit`、`Fire` 和 `Move`.

`<Direction>Front</Direction>` 与 `<Direction>Side</Direction>` 表示动作采用正面视图还是侧面视图, **不是**角色面向左或右, 也不会关闭游戏的自动翻转.

如果生成或切割出的整套动作统一朝右, 在导入前将全部动作水平翻转一次. 请在副本上执行, 避免重复运行后又翻回错误方向:

```python
from PIL import Image
import os

for f in os.listdir('.'):
    if f.endswith('.png'):
        img = Image.open(f)
        img = img.transpose(Image.FLIP_LEFT_RIGHT)
        img.save(f)
```

如果只有某一个动作朝向不一致, 只翻转该文件. `process_velia_skin.py` 就曾仅对 `Evade` 做单独翻转. 导入后必须分别用敌方和我方各预览一次, 不能只根据资源浏览器中的原图判断游戏内朝向.

## 三、ModInfo.xml配置详解

散图模式必须包含 `ModInfo.Xml` 配置文件（注意文件名大小写）：

### 基础配置（推荐）

```xml
<ModInfo>
  <ClothInfo>

    <Default>

      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Default>
    <Guard>

      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />

    <Evade>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Evade>
    <Damaged>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Damaged>
    <Slash>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Slash>
    <Penetrate>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Penetrate>
    <Hit>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Hit>
    <Move>
      <Direction>Front</Direction>
      <Pivot pivot_x="0" pivot_y="-200" />
      <Head head_x="0" head_y="0" rotation="0" head_enable="False" />
    </Move>
  </ClothInfo>
</ModInfo>
```

### 关键参数说明

| 参数 | 说明 |
|------|------|
| `pivot_x` | 增大时 Sprite 锚点向右, 画面中的人物反向向左移动 |
| `pivot_y` | 增大时 Sprite 锚点向上, 画面中的人物反向向下移动 |
| `Direction` | `Front`（正面视图）或 `Side`（侧面视图）, 不代表左右朝向 |
| `head_enable` | 是否启用独立头部动画 |

### Pivot 设定值与画面移动方向相反（重要）

`pivot_x`、`pivot_y` 不是直接加到人物位置上的位移量. 加载器先把 XML 数值换算成 Sprite 内部的归一化锚点:

```csharp
pivot.x = (pivot_x + 512f) / 1024f;
pivot.y = (pivot_y + 512f) / 1024f;
```

这个锚点会对齐角色站位. 锚点在图片内部向一侧移动时, 图片内容相对站位会向另一侧移动, 所以微调方向与设定值增减方向相反:

| 想让游戏画面中的人物移动 | 应如何调整 XML |
|--------------------------|----------------|
| 向右 | 减小 `pivot_x` |
| 向左 | 增大 `pivot_x` |
| 向上 | 减小 `pivot_y`（例如 `-240` 改为 `-260`） |
| 向下 | 增大 `pivot_y`（例如 `-260` 改为 `-240`） |

换句话说: `pivot_x + 20` 不是“人物向右 20”, 而是锚点向右、人物向左; `pivot_y - 20` 会让锚点向下、人物向上.

### 调整技巧

- 先以 `Default` 对齐脚底和站位, 再逐个调整攻击动作.
- 每次只改一个轴, 建议以 10～30 为步长; 数值变化过大时很容易误判方向.
- 每个动作可以有不同的 pivot 值. 攻击图因武器和特效占比不同, 不应机械复制站姿数值.
- 不要同时修改图片透明边距和 Pivot; 先固定画布内容, 再调 Pivot, 否则无法判断是哪一层造成偏移.
- 水平翻转后要重新检查 Pivot. 非对称动作翻转后, 原先为武器留出的透明边距也会换边.

### 本项目与 Git 历史中的验证

- 游戏源码 `Assembly-CSharp/BattleUnitView.cs` 的 `UpdateRotationState()` 对 `Direction.RIGHT` 使用 Y 轴 `180` 度旋转, 对 `Direction.LEFT` 保持 `0` 度, 证明角色左右朝向由运行时自动翻转.
- `Assembly-CSharp/Workshop/WorkshopAppearanceItemLoader.cs` 使用上述 `(value + 512) / 1024` 公式创建 Sprite Pivot, 证明 XML 数值改变的是锚点, 显示位移方向必然相反.
- 提交 `f048ad1`（`Art: 新增角色皮肤和卡面资源`）加入了批量翻转说明, 并把 Velia 所有动作的统一占位 Pivot 改成逐动作数值; 提交说明明确记录了“角色皮肤 pivot 位置调整优化”.
- 提交 `c655406`、`bb4ae96`、`e5972d7` 分别加入 Ailierel、Sivier、Christasha 皮肤. 当前这些皮肤的方向性攻击动作均在源 PNG 中朝左, 与游戏自动翻转逻辑一致.

## 五、动作音效绑定

**先用原版默认声音。** `resources.assets` 中的 `[Prefab]Appearance_Custom` 自带 `CharacterSound` 和六种动作的胜负声；核心书页不写 `SoundInfo` 时，`SdCharacterUtil.CreateSkin` 不调用 `SetMotionSounds`，保留这份原表。原版 `RencounterManager.PrintSound` 仍按动作与胜负选择，由 `CharacterSound.PlaySound` 按 FX 音量播放。AceTaffy 的来宾与司书核心页均采用此路径；其 Hit、Penetrate、Guard、Evade 使用原版动作声，SteamDetonation 是 H 动作也用原版 H 声，不另加爆轰音。

| 原版 Motion | 胜利 AudioClip.name | 失败 AudioClip.name |
|---|---|---|
| J | `Sword_Vert` | `Defensed_Vert` |
| H | `Sword_Hori` | `Defensed_Hori` |
| Z | `Sword_Stab` | `Defensed_Stab` |
| G | `Defense_Guard_Win` | `Defense_Guard` |
| E | `Defense_Evasion` | 原表为空 |
| F | `Atk_Stepan` | 原表为空 |

**确实要换声时，写在核心书页 `<Book>` 下。** 当前游戏 `BookXmlInfo.motionSoundList` 使用 `[XmlElement("SoundInfo")]`；BaseMod 的 `BookXmlInfo_New` 和 `OrcTools` 传递这份列表，`SdCharacterUtil.CreateSkin` 才交给 `CharacterSound.SetMotionSounds`。下面示范完整显式复用原版六行，项目要替换某动作时改对应行并验证整个表，因为 `SetMotionSounds` 会重建 `_motionSounds`，没有逐项叠加保留默认表。`WinExternal="false"`、`LoseExternal="false"` 时，`Win`/`Lose` 是原生 `Resources.LoadAll<AudioClip>("Sounds/MotionSound")` 中区分大小写的 `AudioClip.name`，不是小写资源路径或 WAV 文件名。

```xml
<Book ID="10000001">
  <!-- 仅需显式覆盖声音时使用；省略这些 SoundInfo 即保留原版默认表。 -->
  <SoundInfo Motion="J" WinExternal="false" Win="Sword_Vert" LoseExternal="false" Lose="Defensed_Vert" />
  <SoundInfo Motion="H" WinExternal="false" Win="Sword_Hori" LoseExternal="false" Lose="Defensed_Hori" />
  <SoundInfo Motion="Z" WinExternal="false" Win="Sword_Stab" LoseExternal="false" Lose="Defensed_Stab" />
  <SoundInfo Motion="G" WinExternal="false" Win="Defense_Guard_Win" LoseExternal="false" Lose="Defense_Guard" />
  <SoundInfo Motion="E" WinExternal="false" Win="Defense_Evasion" LoseExternal="false" Lose="" />
  <SoundInfo Motion="F" WinExternal="false" Win="Atk_Stepan" LoseExternal="false" Lose="" />
</Book>
```

外部文件只有明确设置对应 `WinExternal`/`LoseExternal="true"` 时才从 `ModUtil.GetMotionSoundPath` 取路径，即模组根下 `Resource/MotionSound/`，不是 `Char/<皮肤>/MotionSound/`。原版预制体只有表中六行，不能推断 H2/J2/Z2 或其它动作已有声音。旧 `<ClothInfo><SoundList>` 示例在当前游戏/BaseMod 皮肤加载链中没有读取入口，不能当作当前版本的绑定方法；其它框架版本若有皮肤声表，须单独核该版本加载器。源码依据：`BookXmlInfo.cs`、BaseMod 的 `BookXmlInfo_New.cs`/`OrcTools.cs`、`SdCharacterUtil.cs`、`CharacterSound.cs` 与 `ModUtil.cs`。

### 1. LineRenderer 激光特效

游戏中的激光效果（如R社鲁道夫）使用 `LineRenderer` + 贝塞尔曲线实现。

**源码参考**: `Assembly-CSharp/RCorp_RudolphLaserRenderer.cs`

```csharp
// 激光渲染器核心实现
[RequireComponent(typeof(LineRenderer))]
public class DiceAttackEffect_MyMod_BezierLaser_Z : DiceAttackEffect
{
    private LineRenderer _lineRenderer;
    private List<Vector3> _controlPoints = new List<Vector3>();
    private List<Vector3> _curvePositions = new List<Vector3>();
    private int _curPosIdx = 1;
    private float _elapsedMoving = 0f;
    private float _laserSpeed = 5f;

    public override void Initialize(BattleUnitView self, BattleUnitView target, float destroyTime)
    {
        base.Initialize(self, target, destroyTime);

        // 创建 LineRenderer
        _lineRenderer = gameObject.AddComponent<LineRenderer>();
        _lineRenderer.material = new Material(Shader.Find("Sprites/Default"));
        _lineRenderer.startWidth = 0.2f;
        _lineRenderer.endWidth = 0.1f;
        _lineRenderer.startColor = new Color(0.5f, 0.8f, 1f, 1f);  // 淡蓝色
        _lineRenderer.endColor = new Color(1f, 1f, 1f, 0.5f);

        // 初始化贝塞尔曲线控制点
        InitBezierCurve();
    }

    private void InitBezierCurve()
    {
        Vector3 start = _selfTransform.position;
        Vector3 end = _targetTransform.position;
        Vector3 mid = (start + end) / 2f + Vector3.up * 2f;  // 中间点向上偏移

        // 生成曲线上的点
        int segments = 20;
        _curvePositions.Clear();
        for (int i = 0; i <= segments; i++)
        {
            float t = (float)i / segments;
            Vector3 pos = CalculateBezierPoint(t, start, mid, end);
            _curvePositions.Add(pos);
        }

        _lineRenderer.positionCount = 2;
        _lineRenderer.SetPosition(0, start);
        _lineRenderer.SetPosition(1, start);
    }

    // 二次贝塞尔曲线
    private Vector3 CalculateBezierPoint(float t, Vector3 p0, Vector3 p1, Vector3 p2)
    {
        float u = 1f - t;
        return u * u * p0 + 2f * u * t * p1 + t * t * p2;
    }

    protected override void Update()
    {
        base.Update();

        // 逐步延伸激光
        if (_curPosIdx < _curvePositions.Count)
        {
            _elapsedMoving += Time.deltaTime * _laserSpeed;
            if (_elapsedMoving >= 1f)
            {
                _elapsedMoving = 0f;
                _curPosIdx++;
                _lineRenderer.positionCount = _curPosIdx + 1;
            }

            if (_curPosIdx < _curvePositions.Count)
            {
                Vector3 prevPos = _curvePositions[_curPosIdx - 1];
                Vector3 nextPos = _curvePositions[_curPosIdx];
                Vector3 currentPos = Vector3.Lerp(prevPos, nextPos, _elapsedMoving);
                _lineRenderer.SetPosition(_curPosIdx, currentPos);
            }
        }
    }
}
```

```csharp
// 闪光效果核心实现
public class DiceAttackEffect_MyMod_Flash_H : DiceAttackEffect
{
    private MaterialPropertyBlock _mpb;
    private MeshRenderer _meshRenderer;
    private int _fillPhaseId;
    private int _fillColorId;
    private float _flashProgress = 0f;

    public override void Initialize(BattleUnitView self, BattleUnitView target, float destroyTime)
    {
        base.Initialize(self, target, destroyTime);

        _mpb = new MaterialPropertyBlock();
        _fillPhaseId = Shader.PropertyToID("_FillPhase");
        _fillColorId = Shader.PropertyToID("_FillColor");

        // 获取目标的渲染器
        _meshRenderer = target.GetComponentInChildren<MeshRenderer>();
        if (_meshRenderer != null)
        {
            _meshRenderer.GetPropertyBlock(_mpb);
            StartCoroutine(FlashRoutine());
        }
    }

    private IEnumerator FlashRoutine()
    {
        int flashCount = 3;
        float interval = 0.016f;  // 约60fps
        Color flashColor = Color.white;
        WaitForSeconds wait = new WaitForSeconds(interval);

        for (int i = 0; i < flashCount; i++)
        {
            // 闪光开
            _mpb.SetColor(_fillColorId, flashColor);
            _mpb.SetFloat(_fillPhaseId, 1f);
            _meshRenderer.SetPropertyBlock(_mpb);
            yield return wait;

            // 闪光关
            _mpb.SetFloat(_fillPhaseId, 0f);
            _meshRenderer.SetPropertyBlock(_mpb);
            yield return wait;
        }
    }
}
```

### 3. 带物理的拖尾效果

游戏中的拖尾效果支持重力、阻力、湍流等物理模拟，产生类似闪电的抖动效果。

**源码参考**: `Assembly-CSharp/RFX4_TrailRenderer.cs`

```csharp
// 带湍流的拖尾特效（产生闪电般的抖动）
public class DiceAttackEffect_MyMod_LightningTrail_J : DiceAttackEffect
{
    private LineRenderer _lineRenderer;
    private List<Vector3> _positions = new List<Vector3>();
    private List<Vector3> _velocities = new List<Vector3>();

    // 物理参数
    private float _gravity = 0.01f;
    private float _drag = 0.01f;
    private float _turbulenceStrength = 0.5f;  // 湍流强度（越大越像闪电）
    private float _amplitude = 2f;
    private float _frequency = 1f;

    public override void Initialize(BattleUnitView self, BattleUnitView target, float destroyTime)
    {
        base.Initialize(self, target, destroyTime);

        _lineRenderer = gameObject.AddComponent<LineRenderer>();
        _lineRenderer.material = new Material(Shader.Find("Sprites/Default"));
        _lineRenderer.startWidth = 0.15f;
        _lineRenderer.endWidth = 0.05f;
        _lineRenderer.startColor = new Color(0.8f, 0.9f, 1f);
        _lineRenderer.endColor = new Color(0.5f, 0.7f, 1f, 0.3f);

        // 初始化轨迹点
        _positions.Add(_selfTransform.position);
        _velocities.Add(Vector3.zero);
    }

    protected override void Update()
    {
        base.Update();
        UpdateTrail();
        ApplyTurbulence();
        _lineRenderer.positionCount = _positions.Count;
        _lineRenderer.SetPositions(_positions.ToArray());
    }

    private void UpdateTrail()
    {
        Vector3 currentPos = Vector3.Lerp(
            _selfTransform.position,
            _targetTransform.position,
            _elapsed / _destroyTime);

        if (_positions.Count == 0 ||
            Vector3.Distance(currentPos, _positions[_positions.Count - 1]) > 0.1f)
        {
            _positions.Add(currentPos);
            _velocities.Add(Vector3.zero);
        }
    }

    // 使用 Perlin Noise 产生湍流抖动
    private void ApplyTurbulence()
    {
        for (int i = 0; i < _positions.Count; i++)
        {
            Vector3 pos = _positions[i] / _frequency;
            float time = Time.time * 0.5f;

            Vector3 turbulence = Vector3.zero;
            turbulence.x = (Mathf.PerlinNoise(pos.z + time, pos.y) * 2f - 1f)
                           * _amplitude * Time.deltaTime * _turbulenceStrength;
            turbulence.y = (Mathf.PerlinNoise(pos.x + time, pos.z) * 2f - 1f)
                           * _amplitude * Time.deltaTime * _turbulenceStrength;

            _velocities[i] += turbulence;
            _velocities[i] *= (1f - _drag * Time.deltaTime);  // 阻力
            _positions[i] += _velocities[i] * Time.deltaTime;
        }
    }
}
```

## 十三、Steria 案例：克丽丝塔夏原生粒子库

本节以 Steria 实际使用的克丽丝塔夏原生粒子实现为例，展示如何从一张书页追到运行时配方、资源层级、时钟和清理责任。主要源码为 `SteriaBuild/ChristashaNativeParticleLibrary.cs`、`SteriaBuild/ChristashaNativeMassRecipes.cs` 与 `SteriaBuild/ChristashaNativePierceRecipes.cs`。它们是模组自己的实现，不依赖其他模组的 prefab 或贴图。

### 从书页找到运行时入口

`SteriaBuild/SteriaModFolder/Data/CardInfo.xml` 中 ID `9009006`「汐音：光耀万海」将骰子 `ActionScript` 绑定到 `Steria_ChristashaXiyinV2`。`BehaviourAction_Steria_ChristashaXiyinV2.cs` 创建 `FarAreaEffect_Steria_ChristashaXiyinV2`，后者按 Cast、Area 与 Point 的职责调用原生视觉库。这个调用链说明了卡页数据、动作调度和视觉配方各自负责哪一段。

### 效果层级如何组织

| 配方 | Steria 实现 | 职责 |
|---|---|---|
| Slash / Hit | `ChristashaNativeParticleLibrary.cs` | 组合主笔触、回迹、碎屑和环境粒子；共享手动时钟推进，取消时统一清理 |
| Pierce / Projectile | `ChristashaNativePierceRecipes.cs` | 管理突刺、飞剑、命中确认、拖尾和取消；伤害仍由游戏交锋回调处理 |
| Cast / Area / Point | `ChristashaNativeMassRecipes.cs` | 施法阶段显示环绕乐谱，群攻阶段展开浪潮，成功目标各自生成命中反馈 |

汐音 Cast 配方创建五张网格乐谱，只发射一次；随后按各自轨道围绕施放者旋转并翻转。Area 配方沿用运行时载体，再以不同 `WaveVariant` 参数改变浪潮弧线、展开时间和起伏。每个配方通过同一 `Advance` 时钟更新，不由多个脚本分别驱动。

### 实现与生命周期约束

- 由单一 factory 创建配方模板和实例，调用者负责实例的父物体与生命周期。
- 生成阶段放在 inactive staging root 中完成；只保留效果所需组件，避免引用对象携带原行为脚本进入新实例。
- 运行时动画、材质属性、线条和粒子共享一个时钟；不要在每帧重复生成 GameObject、Mesh 或材质。
- 每个播放实例保存需要修改的初始 Transform。`StopAndClear` 关闭渲染、清空粒子，并恢复缩放、位置和旋转，确保取消后可安全重播。
- 效果代码不负责施加伤害。汐音的 Area 结束、成功目标筛选和 Point 反馈由 `FarAreaEffect_Steria_ChristashaXiyinV2.cs` 与原版回调共同管理。

### 构建与验收

原生粒子配方在 Unity 2019.3.15f1 Play Mode 中运行；检查时应同时看实际帧、播放/取消/重播和组件数量。`SteriaBuild/VFXSource/ChristashaNative/run-frame-loop.ps1` 提供可复用入口，`-RequireStable` 要求候选稳定完成。每次运行的帧图和日志是本地生成的验收输出，不是 AssetBundle，也不应作为运行时资源复制进模组包。

本案例的关键经验是先把责任拆成可读层级和时序，再把每层落到 Steria 自己的组件、贴图或网格；不要把某个示例的粒子数量、材质值或 Mesh 尺寸直接套给另一种动作。
