# 贴图攻击特效制作流程

贴图攻击的制作单位是一次攻击的完整时间线：明确起始方向、接触亮峰、主体形状和尾部退场，然后分别绘制水体、墨色、火焰、泡沫等职责。多张图可以使用不同画布。不要把一张完整图的慢放大和整体淡出当作完整动作。

本章示例为安希尔 `AnhierTextureCombat`。生产核心使用 Unity 2019 的 SpriteRenderer 和保留原始 alpha 的 PNG；没有新 Shader 或 AssetBundle。当前交付按用户要求使用托管模拟：执行实际生产适配器和原版基类方法，再将输出矩阵用于 CPU 合成。它明确不是 Unity GPU 或游戏截图；本轮模拟就是批准的验收路径，无须打开游戏。

## 1. 从书页和实际原版效果建立设计

先看 `Resource/CombatPageArtwork/9001001.png` 等实际编号书页卡图，再看 `VFXSource/NativeAttackReference/references/all/` 的原版贴图索引、枢轴和动画信息。`ArtWork/SeaTides.png`、`BurningMemory.png` 是 Buff 图标，只能补充配色和题材，不能代替战斗卡图。

原版导出必须留在参考目录，不能复制到模组 `Resource/Effects/`，也不能复制或绑定巴达皮肤。在 manifest 中记录参考用途、生成或绘制方式、输入和输出 SHA256。安希尔海潮为蓝色水体和泡沫；回忆同时保留黑紫主体与橙红燃烧。当前斩击采用独立纵向落斩母图，上尾较轻、下方锋面较重；打击采用前重后轻的横向主笔触；刺保留完整尖锋和长尾；守备是防御者身前的竖弧。原版用于校准动作空间、尺度和时间，成品是通用原创组件。

## 2. 先规划阶段，再制作素材

近战与守备在攻击事件首帧显示完整主形，持续保持到 250ms，之后按原版曲线淡出，约 667ms 视觉结束；默认对象寿命为 1s。阶段图在保持期只改变局部锋缘与游离碎屑，不能提前掏空主攻击域。JSON 中的时刻规范化于初始化寿命，并精确使用帧序号除以 60。`Initialize` 确定视觉时钟；后续 `SetDestroyTime` 改变销毁时间，不重新缩放已初始化的动画。

远程水击采用 500ms 窗口：攻击事件同时展现枪口水锋和目标接触水花，强态保持到约 333ms，随后淡至 500ms。无需追加 33ms 飞行或长蓄力，也不能把水锋拉成长光柱。游戏自己处理胜利后的伤害火花，本组件只表达动作和水体接触。

每张阶段图应保有自身形态，允许重新画锋头、改变局部压力、裂出新的空隙或替换冲击形状。可以组合多张生成的阶段母图，也可直接绘制。整张同步淡入淡出不提供方向信息；等距排列同一种火舌也会变成链条而非燃烧。

| 职责 | 素材要求 | 本示例渲染方式 |
| --- | --- | --- |
| 主体 | 一体绘制黑紫/蓝色主体与局部火舌/泡沫，保留厚薄和空隙 | RGBA alpha 混合 |
| 游离余烬 / 飞沫 | 仅分离真正断开的少量碎屑，与主体像素互斥，不复制主体外壳 | 独立 PNG，RGBA alpha 混合 |
| 远程接触水花 | 目标端独立姿态，事件首帧出现，保持后散开 | 远程额外一个 SpriteRenderer |

主渲染器为两层，远程三层；共享一个 `Sprites/Default` 材质。亮度由画出的颜色和 alpha 表达，没有自动加泛光。需要新增层时先指出该层解决的可见问题。

## 3. 使用参考生图、好抠背景或直接绘制

用户可选择多次生图、多个独立画布、直接绘制或混合方式。参考生图应附实际卡图与原版效果索引，提示词写清方向、轮廓、亮峰位置、素材职责、宽高比例和空隙。明确禁止角色、文字、场景、棋盘格和模拟透明阴影。

优先取得真实透明 RGBA。如果接口只能输出有底色图片，选择与效果颜色不重合的平坦高饱和底色。例如黑紫火焰用纯绿色，不要用黑底后按亮度抠图：黑紫实体会一起消失。水体可使用品红底，避免蓝绿底与水色重叠。

抠图要结合底色距离、边缘连通关系和抗锯齿边缘去色。保留主体内部暗部；检查深、浅背景下是否出现底色污染、灰边或半透明矩形。不要仅硬阈值删除所有某颜色像素，也不要把黑紫颜色重新换算成透明度。透明像素外缘应留足安全边距，压缩/缩小时重新检查。

保存原始响应、提示词、参考输入、可重现清理参数、抠图后的独立母图与阶段输出。素材生成是美术输入；时间配置、阶段侵蚀、枢轴和游戏适配是独立受控步骤。程序绘制试稿不能因生成器运行成功就冒充最终接受的美术。

## 4. PNG、alpha 和枢轴的运行时约定

`AnhierTextureTimeline.cs` 是游戏和托管模拟共同使用的渲染核心。每个 Profile JSON 记录持续时间、帧时刻、主体/游离碎屑文件、像素每单位和归一化枢轴。素材在原生倍率之前按 alpha 内容尺寸归一化；随后由原版 `Initialize` 和 `SetScale` 应用普通近战 `2 × (1 + roll factor)`，守备基础尺度减半。禁止再次叠乘旧版画布尺度，或把地图尺度夹到 1.75。输出画布使用真实比例；优化分辨率时同步调整 PPU。

渲染使用原版 `Particle` sorting layer，子层 order 为 0/1；GameObject 的 `Effect` layer 是另一个概念，交给原版 `SetLayer` 及子层同步。两者都应在模拟契约中检查。

加载使用 `TextureFormat.RGBA32`、Bilinear、Clamp、无 mipmap；`LoadImage(..., true)` 释放 CPU 像素副本。贴图及 Sprite 按需缓存；manifest 明确记录全部 Profile 的未压缩 RGBA 字节预算。不要让几十张高分辨率阶段图无意消耗数百 MiB。

所有实例共享材质，逐实例只改变 Sprite、位置、旋转和 `SpriteRenderer.color`。不要读取或赋值 `Renderer.material` 来动画化共享参数，以免产生材质实例或相互污染。缺图/坏图需要记录具体 Profile 与路径，移除已创建的对象并保留游戏自带受击反馈。

旧的 `SteriaEffectSprites.GetEffectMaterial` 会亮度抠图，不能用于新的回忆暗色主体。本实现新增专用加载路径，旧特效调用者继续使用原系统。

## 5. 书页主题和角色动作的职责

`CardInfo.xml` 的 `Behaviour/EffectRes` 决定书页主题。`HarmonyPatches.InitCustomEffects()` 注册六个唯一名称，路由到薄 `DiceAttackEffect` 适配器。无论哪个角色使用这些书页，都应得到对应主题，不能用角色身份全局替换所有攻击效果。

实际优先级是 `movingAction.customEffectRes` 高于书页 XML `EffectRes`，确定资源名后才进入特效管理器与自定义字典查找。动作脚本若显式提供 customEffectRes，会覆盖 XML。不存在一个可以可靠代表所有皮肤和书页的“按角色全局兜底”；更换角色皮肤也不会自动替换已确认的书页主题。

| Profile | EffectRes | 书页及骰子 |
| --- | --- | --- |
| SeaFarHit | Steria_AnhierTextureSeaFarHit | 9001001 第1骰；9001008 第1骰 |
| SeaPierce | Steria_AnhierTextureSeaPierce | 9001007 第1骰 |
| MemorySlash | Steria_AnhierTextureMemorySlash | 9001002 两骰；9001003 第2骰；9001004 第1骰；9001005 两骰；9001009 第1骰；9001010 第2骰 |
| MemoryPierce | Steria_AnhierTextureMemoryPierce | 9001004 第3骰 |
| MemoryHit | Steria_AnhierTextureMemoryHit | 9001004 第2骰；9001009 第2骰 |
| MemoryGuard | Steria_AnhierTextureMemoryGuard | 9001003 第1骰；9001006 两骰；9001009 第3骰 |

共 14 颗攻击骰、4 颗守备骰。寒地后勤 9001010 属于回忆；回避、海潮守备、空白反击、EGO 和其他角色原有绑定保留。

角色皮肤提供 Slash、Penetrate、Hit、Fire、Guard 动作枢轴。近战主效果直接保留在 `self` 对应枢轴下，明确路由 H/J/Z/G，继承完整父系旋转、缩放和镜像一次；不再用目标斜率覆盖动作方向。原创主图统一面向原生左侧，镜像由角色旋转中心负责。守备使用防御者 `self` 的 Guard 枢轴；回忆打击是攻击者 Hit 枢轴上的完整横向笔触，不生成目标伤害星爆。

远程使用中立 SceneRoot：枪口跟随 `self` 的 Fire 枢轴，独立水花仅追踪 `target.atkEffectRoot` 的世界位置，保留发射者方向，不继承目标的镜像、旋转或尺度。原版远程尺度链不额外乘角色地图倍率；缩放后再次更新接触位置，避免 Initialize/SetScale 之间的临时偏移。不存在 Fire 动作的皮肤应按原生动作规则回退，不能把站姿冒充开火动作。

游戏已有攻击音效、胜负判断和受击反馈。本效果保留 `HasDamagedEffect=false`，不重复播放声音、震屏或修改全局时间。

## 6. 可重复验证和交付

在仓库根执行：

```powershell
powershell -ExecutionPolicy Bypass -File SteriaBuild/VFXSource/AnhierTextureCombat/run_managed_preview.ps1 -BuildRelease
```

最终母图、原始生成响应、提示词、抠图脚本与来源元数据保存在 `imagegen_masters/`，`inputs.json` 仅使用相对路径，可离线重新派生阶段图。远程使用 v2 压力锋头和独立水花；初稿 v1 是被用户否定的圆滑造型，不进入最终输入清单。早期直接绘制试稿已隔离到 `experiments/procedural_v0/`，它的生成器也只写该实验目录，不能覆盖最终清单、阶段图或发布目录。

`run_managed_preview.ps1` 是当前唯一推荐入口，串联现有准备脚本、.NET 8 托管契约、独立人形绘制和媒体封装。它核对生产副本和发布 PNG/JSON，再执行 `Initialize -> SetScale -> SetLayer -> Update`，使用输出矩阵渲染原创中性人形、两种体型和相反朝向。近战共用合理交战距离；远程保留较远间距；所有画面使用同一相机。主画面不包含巴达像素或皮肤自带 Effect(9) 层。源/发布哈希检查、原生枢轴与尺度、初始化视觉时钟与可变销毁时间检查独立记录。

脚本正常运行复用已提取的只读原版参考，不启动游戏或 Unity。仅在参考缓存缺失时调用现有提取脚本。两套已安装 Unity 2019 的许可证校验失败，所以不再用旧 `run_preview.ps1` 作为本轮验收门槛。更改母图时才额外运行 `import_masters.py`；未改素材无需重新生成。

当前交付文件均以 `independent-` 开头：`independent-all-six-60fps.mp4`、`independent-all-six-30fps.gif`、各 Profile 的 `independent-<Profile>-two-sizes-60fps.mp4`、`independent-phase-contact.png` 和 `independent-two-size-contact.png`。MP4 使用每张实际 60fps 模拟帧，播放两种体型并留空白回放间隔；GIF 隔帧采样，用 30/40/30ms 延迟表达真实速度，避免浏览器延长过短帧。阶段接触表覆盖 0/17/50/150/250/400/667ms。`candidate-hashes.json` 记录核心、适配器、配置、PNG、脚本、模拟输出、检查、媒体和 Release DLL 的精确 SHA256。

原版/候选 A/B 只作为明确标注的参考；旧顶层 `all-six-*`、旧接触表和站姿预览已经失效。生成的原版基类、角色参考图片和运行时缓存均 gitignored，不进入发布包。

检查并发实例材质/阶段互不污染、每个 Profile 亮峰到时、正常结束关闭渲染器以及资源失败提示。再由另一位评审独立查看实际动态和静态预览，返回 PASS / REVISE / BLOCK；编译通过不能代替视觉接受。

本轮按用户要求以模拟完成验收：检查代表近战、远程与守备的正常速度画面、两种体型/方向和原版契约证据，由独立评审返回 PASS / REVISE / BLOCK，再由主线程收口。GPU、实际游戏摄像机与音效混音不在这组证据内，不因此新增开游戏的前置条件。部署属于主线程的独立步骤，只同步授权的新 DLL、本次 CardInfo 与 `Resource/Effects/AnhierTextureCombat`，并核对部署和候选哈希。此 PNG 路线没有 AssetBundle 构建步骤。
