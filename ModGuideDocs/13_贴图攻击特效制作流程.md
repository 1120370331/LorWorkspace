# 贴图攻击特效制作流程

贴图攻击的制作单位是一次攻击的完整时间线：明确起始方向、接触亮峰、主体形状和尾部退场，然后分别绘制水体、墨色、火焰、泡沫等职责。多张图可以使用不同画布。不要把一张完整图的慢放大和整体淡出当作完整动作。

本章示例为安希尔 `AnhierTextureCombat`。生产核心使用 Unity 2019.3.15f1 的 SpriteRenderer 和保留原始 alpha 的 PNG；没有新 Shader 或 AssetBundle。正文中的 Unity 预览是生产渲染代码的确定性夹具，不能代替游戏内战斗验收。

## 1. 从书页和实际原版效果建立设计

先看 `Resource/CombatPageArtwork/9001001.png` 等实际编号书页卡图，再看 `VFXSource/NativeAttackReference/references/all/` 的原版贴图索引、枢轴和动画信息。`ArtWork/SeaTides.png`、`BurningMemory.png` 是 Buff 图标，只能补充配色和题材，不能代替战斗卡图。

原版导出必须留在参考目录，不能复制到模组 `Resource/Effects/`。在 manifest 中记录参考用途、生成或绘制方式、输入和输出 SHA256。安希尔海潮为蓝色水体和泡沫；回忆必须同时保留黑紫主体与橙红燃烧。斩是低宽横扫，刺是尖细前锋，击是短促不对称爆发，守备是防御者身前的竖弧。

## 2. 先规划阶段，再制作素材

默认时间配置为 `0 / 0.0167 / 0.0333 / 0.0667 / 0.1167 / 0.1833 / 0.2833 / 0.4167` 秒，约 0.45–0.50 秒结束。实际 JSON 保存精确的 `帧序号 / 60`，避免把 0.0167 写成比第1帧稍晚的阈值而跳过一帧。远程压力击采用更短的 0.40 秒时间线，接触后很快裂散，不能长期停留成结晶扇面。它从游戏攻击事件开始播放，不在命中之后追加一段长蓄力。1–3 帧内形成主亮峰，较晚阶段优先侵蚀尾迹、打断水带或留下少量暗碎片。

每张阶段图应保有自身形态，允许重新画锋头、改变局部压力、裂出新的空隙或替换冲击形状。可以组合多张生成的阶段母图，也可直接绘制。整张同步淡入淡出不提供方向信息；等距排列同一种火舌也会变成链条而非燃烧。

| 职责 | 素材要求 | 本示例渲染方式 |
| --- | --- | --- |
| 主体 | 一体绘制黑紫/蓝色主体与局部火舌/泡沫，保留厚薄和空隙 | RGBA alpha 混合 |
| 游离余烬 / 飞沫 | 仅分离真正断开的少量碎屑，与主体像素互斥，不复制主体外壳 | 独立 PNG，RGBA alpha 混合 |
| 远程接触水花 | 目标端独立姿态，短亮峰、快速散开 | 远程额外一个 SpriteRenderer |

主渲染器为两层，远程三层；共享一个 `Sprites/Default` 材质。亮度由画出的颜色和 alpha 表达，没有自动加泛光。需要新增层时先指出该层解决的可见问题。

## 3. 使用参考生图、好抠背景或直接绘制

用户可选择多次生图、多个独立画布、直接绘制或混合方式。参考生图应附实际卡图与原版效果索引，提示词写清方向、轮廓、亮峰位置、素材职责、宽高比例和空隙。明确禁止角色、文字、场景、棋盘格和模拟透明阴影。

优先取得真实透明 RGBA。如果接口只能输出有底色图片，选择与效果颜色不重合的平坦高饱和底色。例如黑紫火焰用纯绿色，不要用黑底后按亮度抠图：黑紫实体会一起消失。水体可使用品红底，避免蓝绿底与水色重叠。

抠图要结合底色距离、边缘连通关系和抗锯齿边缘去色。保留主体内部暗部；检查深、浅背景下是否出现底色污染、灰边或半透明矩形。不要仅硬阈值删除所有某颜色像素，也不要把黑紫颜色重新换算成透明度。透明像素外缘应留足安全边距，压缩/缩小时重新检查。

保存原始响应、提示词、参考输入、可重现清理参数、抠图后的独立母图与阶段输出。素材生成是美术输入；时间配置、阶段侵蚀、枢轴和游戏适配是独立受控步骤。程序绘制试稿不能因生成器运行成功就冒充最终接受的美术。

## 4. PNG、alpha 和枢轴的运行时约定

`AnhierTextureTimeline.cs` 是游戏和预览共同使用的完整渲染核心。每个 Profile JSON 记录持续时间、帧时刻、主体/亮层文件、像素每单位、归一化枢轴、角色尺度系数。输出画布使用真实比例，不固定拉伸到 16:9。优化分辨率时，同步调整 PPU，保证世界尺寸不变。

加载使用 `TextureFormat.RGBA32`、Bilinear、Clamp、无 mipmap；`LoadImage(..., true)` 释放 CPU 像素副本。贴图及 Sprite 按需缓存；manifest 明确记录全部 Profile 的未压缩 RGBA 字节预算。不要让几十张高分辨率阶段图无意消耗数百 MiB。

所有实例共享材质，逐实例只改变 Sprite、位置、旋转和 `SpriteRenderer.color`。不要读取或赋值 `Renderer.material` 来动画化共享参数，以免产生材质实例或相互污染。缺图/坏图需要记录具体 Profile 与路径，移除已创建的对象并保留游戏自带受击反馈。

旧的 `SteriaEffectSprites.GetEffectMaterial` 会亮度抠图，不能用于新的回忆暗色主体。本实现新增专用加载路径，旧特效调用者继续使用原系统。

## 5. 书页主题和角色动作的职责

`CardInfo.xml` 的 `Behaviour/EffectRes` 决定书页主题。`HarmonyPatches.InitCustomEffects()` 注册六个唯一名称，路由到薄 `DiceAttackEffect` 适配器。无论哪个角色使用这些书页，都应得到对应主题，不能用角色身份全局替换所有攻击效果。

实际优先级是 `movingAction.customEffectRes` 高于书页 XML `EffectRes`，确定资源名后才进入特效管理器与自定义字典查找。动作脚本若显式提供 customEffectRes，会覆盖 XML。不存在一个可以可靠代表所有皮肤和书页的“按角色全局兜底”；更换角色皮肤也不会自动替换已确认的书页主题。

| Profile | EffectRes | 书页及骰子 |
| --- | --- | --- |
| SeaFarHit | Steria_AnhierTextureSeaFarHit | 9001001 第1骰；9001008 第1骰 |
| SeaPierce | Steria_AnhierTextureSeaPierce | 9001007 第1骰 |
| MemorySlash | Steria_AnhierTextureMemorySlash | 9001002 两骰；9001003 第2骰；9001004 第1骰；9001005 两骰；9001009 第1骰；9001010 第2骰 |
| MemoryPierce | Steria_AnhierTextureMemoryPierce | 9001004 第3骰 |
| MemoryHit | Steria_AnhierTextureMemoryHit | 9001004 第2骰；9001009 第2骰 |
| MemoryGuard | Steria_AnhierTextureMemoryGuard | 9001003 第1骰；9001006 两骰；9001009 第3骰 |

共 14 颗攻击骰、4 颗守备骰。寒地后勤 9001010 属于回忆；回避、海潮守备、空白反击、EGO 和其他角色原有绑定保留。

角色皮肤提供 Slash、Penetrate、Hit、Fire、Guard 动作枢轴。适配器取枢轴世界位置，再根据目标与使用者的世界方向定向，避免父节点翻转后再翻一次。守备取防御者 `self` 的 Guard 枢轴，不能移动到攻击者 `target`。回忆打击是接触爆点，其偏右亮点枢轴落在稳定的 `target.atkEffectRoot`；不能借用对手的攻击动作枢轴，也不能把爆点留在自己身前。远程水锋在实际两点之间移动，接触水花也落在稳定目标根，长度保持角色尺度，不把贴图横向拉成长光柱。

游戏已有攻击音效、胜负判断和受击反馈。本效果保留 `HasDamagedEffect=false`，不重复播放声音、震屏或修改全局时间。

## 6. 可重复验证和交付

在仓库根执行：

```powershell
python -X utf8 SteriaBuild/VFXSource/AnhierTextureCombat/import_masters.py
python -X utf8 SteriaBuild/VFXSource/AnhierTextureCombat/verify_source.py
dotnet build SteriaBuild/Steria.csproj -c Release
powershell -ExecutionPolicy Bypass -File SteriaBuild/VFXSource/AnhierTextureCombat/run_preview.ps1
```

最终母图、原始生成响应、提示词、抠图脚本与来源元数据保存在 `imagegen_masters/`，`inputs.json` 仅使用相对路径，可离线重新派生阶段图。远程使用 v2 压力锋头和独立水花；初稿 v1 是被用户否定的圆滑造型，不进入最终输入清单。早期直接绘制试稿已隔离到 `experiments/procedural_v0/`，它的生成器也只写该实验目录，不能覆盖最终清单、阶段图或发布目录。

`run_preview.ps1` 将生产核心原文件复制到隔离的 Unity 2019.3.15f1 项目，使用实际生产 JSON/PNG 输出：权威 60fps MP4、兼容浏览器的 30fps GIF、起始/展开/接触/完整/退场接触表、左右朝向与深浅背景、关闭游离碎屑层的对照。MP4 按每张实际渲染帧编码；GIF 隔帧采样，用 30/40/30ms 延迟表达真实速度，避免某些浏览器把 10ms 延迟强行延长、把攻击看成慢动作。`candidate-hashes.json` 记录源、配置、贴图和预览 SHA256；夹具明确标注参考角色、模拟场景和其证据边界。

检查并发实例材质/阶段互不污染、每个 Profile 亮峰到时、正常结束关闭渲染器以及资源失败提示。再由另一位评审独立查看实际动态和静态预览，返回 PASS / REVISE / BLOCK；编译通过不能代替视觉接受。

最终游戏验收应覆盖一个近战和一个远程书页、成功守备，以及实际使用角色的方向和攻击枢轴。部署只同步新 DLL、本次 CardInfo 与 `Resource/Effects/AnhierTextureCombat`，先确认真实 D 盘游戏目录，再核对部署和候选哈希。此 PNG 路线没有 AssetBundle 构建步骤，不应为了流程形式额外引入 AB。
