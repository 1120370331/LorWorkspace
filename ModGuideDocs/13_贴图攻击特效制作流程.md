# 贴图攻击特效生产规范

**验收方式：** 优先复用模拟工程加载实际候选与必要原版资源，每次运行明确一个主日志文件，读取日志中的时点、变换、结果及渲染附件再判断。具体命令与日志规范见[第 08 章](08_编译与部署.md)。仅为模拟无法覆盖的具体问题补游戏内验证；历史“未实机”记录仍按当时证据保留。

**贴图存在不代表画面出现：** 验收从 CardInfo 的实际 `EffectRes` 走到加载器和 `DiceEffectManager.CreateBehaviourEffect`，确认返回实例、`Initialize` 产生渲染组件、附着到动作挂点、原生缩放与镜像各生效一次，再逐帧核 GPU 像素及退场。资源 `Prewarm` 或 PNG 解码通过只能证明资源可读。Python 合成预览适合审形状、透明边和节奏草案；它用近似挂点与软件合成，不能证明 Unity 工厂、材质、父级变换或实机可见。记录每种证据使用的相机、角色图、pivot 与合成方式，避免把近似预览标为真工厂渲染。

本规范固化用户已接受的独立原创贴图效果做法。制作单位是完整动作：先确定轮廓、方向、受力前锋和拖尾，再设计保持与退场。原版提供动作空间、尺度与时间依据，书页卡图提供题材；成品通过书页资源名复用，不绑定或复制任何角色皮肤。

当前库位于 `SteriaBuild/VFXSource/AnhierTextureCombat`，发布资源仍使用 `Resource/Effects/AnhierTextureCombat`。历史路径保留以兼容已有模组，不代表安希尔专用。库包含潮汐斩/打/突/防与回忆斩/打/突/防八种近战动作，以及独立远程辅助 SeaFarHit，共九个 Profile。回忆四种和原海潮突/远程是 `440d8ba` 已接受基线；SeaSlash、SeaHit 在候选 `668599` 已通过独立接受，用户随后追加 SeaGuard 补齐潮汐守备。

## 1. 设计与素材输入

先读相关书页、原版挂点/动画/排序数据及现有效果。卡图必须对应实际书页，例如艾莉蕾尔 `9007001.png` 与希维尔“海愿斩”等；Buff 图标只能补充配色。原版导出只保留在参考目录，不进入模组 `Resource/Effects/`，不复制巴达皮肤、动作内建 Effect(9) 层或原版攻击像素。

- 潮汐以深蓝承压体积、青蓝水脉和局部白色泡沫构成。斩是完整开放纵弧，上尾轻、下锋重；打是前重后轻的横向水体扫击；突是明确尖锋和长轴拖尾；防是上下端重量平衡、前方中段承压的开放竖弧。远程枪口与目标水花各负其责。
- 回忆保留黑紫实体与局部橙红燃烧，不能把暗部抠成透明。斩、打、突、防各自沿用已接受母图和动作语法，新增主题不能反过来改写它们。
- 先完成独立母图的形状和材质，再制作时间阶段。禁止把旧横图旋转成纵斩、把回忆火焰换蓝冒充水体，或用复制透明外壳制造“厚度”。

参考生图应附实际卡图和已接受效果，并写清轮廓、主次、方向、内容比例与负形。本轮延续用户选择，三张新增母图均使用平坦纯 `#00FF00` 背景；禁止绿色光晕、角色、武器、场景、文字、符号、棋盘格与落地阴影。一般任务可直接取得透明 RGBA，或选择与效果不冲突的纯色键背景，但不能用黑底后按亮度抠黑紫主体。

键控结合颜色差、背景区域与边缘抗锯齿去色；不全局删除青色，也不把深蓝或黑紫亮度换算成 alpha。检查原尺寸与约 500px 缩小图在深、浅底下的绿边、灰边、半透明矩形与安全透明边。保存原始响应、精确提示词、参考路径及 SHA256、清理代码/参数、透明母图、QA 和来源元数据。源图和提示词是可追溯输入，不能用流程运行成功代替美术接受。

SeaSlash/SeaHit 母图保存在 `imagegen_masters/tide_library/`，新增 SeaGuard 单独保存在 `imagegen_masters/tide_guard/`，不覆盖先前已接受的输入。SeaSlash 原始开口向右、弧面向左，不翻图，按 alpha 内容高度归一化为局部 3.5 单位。SeaHit 原始前锋向右，导入时离线翻为左，按内容宽度归一化为局部 4.4 单位，保留真实宽高比。主线程接受 SeaHit 约 3.31 的原始内容比例，不为追逐初始 2.6–3.2 参考区间拉伸水体。SeaGuard 凸面朝左、开口朝右，原图不翻转，内容局部高度 4.4，沿用原生 G 半尺度；中段泡沫表达防御接触，上下端逐渐变薄，不做下端沉重落斩。三者均使用中心 pivot `(0.5, 0.5)`。

## 2. 时间线与分层

普通近战和守备从攻击事件首帧给出完整主形：首帧主体 alpha 质量至少峰值 85%，17–250ms 保持至少 85%。250ms 之后才逐步侵蚀局部拖尾，原生 alpha 曲线到约 667ms 淡尽；默认对象寿命为 1s。首帧不能只有细线，也不能在 150ms 已碎成余迹。保持期间允许少量锋缘、水脉或游离碎屑变化，不能掏空主攻击域。

SeaSlash 单独采用“上方轻尾先退、下方压力锋后收”的阶段侵蚀；图像坐标 `v` 的上端为 0，所以它使用 `1-v` 表达退场方向。这个分支只属于新 SeaSlash，既有 MemorySlash 输出不变。SeaHit 导入后左锋、右尾，优先收右侧拖尾。SeaGuard 在 250ms 后先收上下两端与游离飞沫，迎击中段保留到较晚阶段；不沿攻击方向扫过，也不表现持续护盾状态。

SeaFarHit 使用 500ms 窗口：攻击事件同时展现枪口水锋和目标水花，强态保持到约 333ms，再淡至 500ms。不追加 33ms 飞行或长蓄力，也不将贴图拉成长光柱。

`Initialize` 固定本次视觉时钟；后续 `SetDestroyTime` 只改对象销毁时刻，不重缩已初始化的动画。这两个时钟必须分开验证。JSON 中的阶段位置按初始化时长归一化，使用精确帧序号除以 60，避免小数近似跨过帧阈值。

| 层的职责 | 素材要求 | 渲染 |
| --- | --- | --- |
| 主体 | 一体绘制蓝色/黑紫体积与局部泡沫/火舌，保留厚薄和空隙 | RGBA alpha |
| 游离飞沫/余烬 | 只分离真正断开的碎屑；主体与碎屑像素互斥 | 第二个 SpriteRenderer |
| 远程目标水花 | 独立接触姿态，从事件首帧出现 | 仅 SeaFarHit 的第三层 |

普通实例只有两层；新增层必须说明独立的可见职责。共用一个 `Sprites/Default` 材质，亮度由母图颜色和 alpha 表达，不额外加自动 Bloom、泛光、音效、震屏、时停或伤害判断。

## 3. 原生附着、尺度与资源约定

`AnhierTextureTimeline.cs` 是唯一共享渲染核心，薄适配器只决定 Profile 和动作。H/J/Z/G 明确路由到 `self` 的 Hit/Slash/Penetrate/Guard 枢轴，效果保留在完整父系中，继承旋转、缩放和镜像一次。不得用目标斜率覆盖动作方向、把近战脱离父级移到对手，或再次翻转已经继承角色朝向的贴图。守备的 `self` 是防御者。

素材按 alpha 内容尺寸在原生倍率之前归一化。普通近战保留原生 `2 × (1 + roll factor)`，Guard 基础尺度减半；后续完整继承角色地图尺度，不做 1.75 截断或弱化掷骰缩放。优化新素材分辨率时同步调整 PPU，保持形状真实比例和世界尺寸；禁止为了新增预算重编码已接受六组图。

远程效果使用中立 SceneRoot。枪口跟随 `self` Fire 枢轴，目标水花只追踪 `target.atkEffectRoot` 世界位置，保留发射者方向，不继承目标镜像/旋转/尺度；不额外乘角色地图倍率。缩放后执行更新再量测接触位置。缺少 Fire 动作的皮肤遵循原生回退，不能将 Default 站姿宣称为开火动作。

渲染使用 `Particle` sorting layer 和子层 order 0/1；GameObject 的 `Effect` layer 由原版 SetLayer 及子层同步，两者不能混淆。使用 TextureFormat.RGBA32、Bilinear、Clamp、无 mipmap；`LoadImage(..., true)` 释放 CPU 像素。贴图和 Sprite 按 Profile 共享缓存，实例只修改 Sprite、变换和颜色；禁止读取/赋值 `Renderer.material` 制造材质实例。

九 Profile 的 decoded RGBA 实测总量为 **91,631,360 字节，约 87.39 MiB**，记录于 manifest 和候选清单；96 MiB 是本库上限，不是目标。缺图/坏图需记录 Profile 与路径并清理本次对象；游戏原有受击反馈继续有效。旧的亮度抠图加载路径不适用于新原创暗色主体。

主题由书页确定，动作由骰子与角色枢轴决定。Profile 是素材/时间线，EffectRes 是公共资源名；它们不是角色身份。新书页优先使用下表语义名称，直接指向同一个实现类型和素材缓存。

| --- | --- | --- | --- |
| 潮汐斩 | `Steria_TideSlash` | SeaSlash | J / Slash |

## 5. 可重现生成、模拟与验收

`imagegen_masters/inputs.json` 使用相对路径指定母图与导入配置。新增或修改某个 Profile 时仅派生该 Profile，保护已经接受的像素与配置。例如用户追加潮汐防御时只生成该新增项，已接受的八种均不重编码：

```powershell
python -X utf8 SteriaBuild/VFXSource/AnhierTextureCombat/import_masters.py --profiles SeaGuard
powershell -ExecutionPolicy Bypass -File SteriaBuild/VFXSource/AnhierTextureCombat/run_managed_preview.ps1 -BuildRelease
```

`accepted-six-baseline.json` 固定 `440d8ba` 的 222 个相关文件哈希、六组输入/配置/母图/阶段元数据与完整 CardInfo 结构摘要。`accepted-tide-attacks-baseline.json` 另外固定已接受 SeaSlash/SeaHit 的 68 个文件及输入/配置/行为，同时记录九个守备视觉替换；原六组基线文件本身仍字节不变。源验证器检查八组素材逐字节一致，并逆向还原 21+9 个指定属性后比较完整原 XML；兼容/语义注册各唯一。对新素材检查透明边、可见绿边、互斥层、尺寸、250ms 主体保持、上尾/双端退场方向与实际预算。

托管夹具使用未替写的生产适配器、共享核心和原版基类方法，执行 `Initialize -> SetScale -> SetLayer -> Update`，通过输出矩阵驱动 CPU 合成。它覆盖完整枢轴旋转/缩放/镜像、原生倍率、初始化视觉时钟、后改销毁时间和实际存活状态。主展示用原创不透明中性人形、scale 3 与 2.25、相反朝向与同一相机。近战共用 `self ±3 / target ∓3` 的交战距离，远程单独保留较远距离；不能换近相机或捏造世界坐标来证明效果尺寸。

新库媒体以 `library-nine-` 开头：九种正常速度 60fps MP4、30fps GIF、逐 Profile 两体型短片、阶段接触表和两体型接触表。阶段覆盖 0/17/50/150/250/400/667ms；MP4 每张源帧按 60fps 编码，GIF 隔帧采样并使用 30/40/30ms 延迟，最短不低于 30ms，防止浏览器延长过短帧造成慢动作。已接受六种的 `independent-all-six-*` 和已接受八种的 `library-eight-*` 媒体保留为清楚命名的历史接受版本。本次新增视觉评审聚焦 SeaGuard，已接受攻击效果凭未变哈希复用原审查证据。

`candidate-hashes.json` 固定生产源、别名与书页配置、原创 PNG、母图/提示词/清理来源、模拟数据、检查、媒体和 Release DLL 的 SHA256。独立评审需要在正常速度和阶段帧中确认轮廓、方向、前锋/拖尾层级、材质与边缘，给出 PASS / REVISE / BLOCK；编译成功不等于视觉接受。返修仅重跑被修改表面影响的验证。

本轮明确采用模拟，不启动游戏或 Unity，不探测或修复许可证。原版画面只作参考，不宣称验证真实 Unity GPU、游戏摄像机或音效混音，也不增加开游戏作为完成前提。部署和提交由主线程在独立接受后处理，核对新 DLL、授权 CardInfo 和资源目录的候选/目标哈希。

## 6. 归档与禁止退回的旧做法

旧站姿夹具、世界脱离/目标斜率重定向、1.75 尺度截断、微弱掷骰倍率、33ms 才完整的渐现和过早解体、目标星爆替代 H 主笔触均不再是生产规范。`author_assets.py` 的试稿只写 `experiments/procedural_v0/`，不覆盖最终母图或资源。旧顶层 `all-six-*` 与站姿接触表是被替换的早期版本，不与已接受的 `independent-all-six-*` 混淆。

生成的原版基类副本、游戏皮肤/参考图片、Unity/托管运行缓存继续 gitignored，不进入发布包。当前路线只需要原创 PNG/JSON 和模组 DLL，无 Shader 或 AssetBundle 构建步骤。完成边界是明确候选通过比例适当的源码/编译/模拟检查和独立视觉接受，不以文件数、测试数或重复构建次数为目标。

## 7. 案例：4费蒸汽爆轰的专属形态与阶段

AceTaffy 的卡 `1883009` 仅首骰引用 `AceTaffy_SteamDetonation`。先保存旧图、旧代码和同尺度普通打击作为基线，再确定专属轮廓与独立运动层。设计及实际参数边界见[爆轰设计合同](../AceTaffy/ArtSource/Effects/ultimate-design-v1.md)，生成记录见[贴图提示词](../AceTaffy/ArtSource/Effects/ultimate-v1/PROMPTS.md)。视觉接受以候选的实际预览和独立审查为准。

1. **按视觉职责分别制图。** 主体是短粗活塞压锋，上下蒸汽带留出透明通道；第二张是凸面朝前、开口朝后的破裂压弧。主锋负责出手力量，压弧负责短促分离，少量碎汽负责退场。素材分别生成，保留原始 RGBA、完整提示词与哈希。
2. **检查真实透明度。** 同时看 alpha 数据、深浅底和实际渲染。图像隐藏 RGB 中的灰色不能直接当作实心雾，也不能为去掉灰色而按亮度删除蒸汽暗褶。纹理尺寸、可见包围盒和 PPU 联合确定世界尺寸；保留母图原比例。
3. **让专属效果独立计时。** 原生攻击事件创建实例后，首帧给出完整主形；压弧在约 0.05 秒出现，约 0.22 秒清空，主体和碎汽随后退散。现有准备动作属于 ActionScript，不能在效果 Initialize 中重复增加前摇或延迟伤害。每次实例独立计时，后续 SetDestroyTime 不重启画面。
4. **从原版数据核挂点。** 本例原版 `resources.assets` 的 `[Prefab]Appearance_Custom` 为 GameObject path ID `33898`。其 H 专属挂点引用为空，因此读取原生回退 `AtkEffectRoot`，位置为 `(-1.92, 2.52, 0)`，完整变换证据见[挂点提取记录](../AceTaffy/Verification/Vfx/native-hit-pivot.json)。结合当前皮肤 XML 的 Pivot 和 quality 重建人物，保留父系镜像与原生倍率。该值是本例数据，不能当作所有皮肤的通用手点。
5. **用角色上下文修正位置。** 检查前锋、尾端与拳套的连接，以及双方脸部遮挡。修正专属效果的局部位置与统一尺度时，持续复查出气口接缝；不能只把整团移开人脸却让尾端离手，也不能靠拉远对手或换镜头隐藏问题。
6. **同时看阶段帧与正常速度。** 至少包含首帧、压弧分离、主体保持、退散及空场，检查左右朝向、高低掷骰倍率、取消和多实例。普通效果与新效果使用同一相机、挂点和人物尺度；历史人工挂点图必须另行标注。若视频使用队列参数驱动姿态而未重放完整 MoveRoutine，明确记录模拟边界。
7. **按精确资源隔离改动。** 首骰的专属时间线保留现有工厂类型与 H 路由，其余打击、突刺和防御沿用原参数。新增压弧加入缓存、预热和取消清理；缺失时保留主体并记录错误。独立视觉审查通过后，再冻结源码与贴图、构建、部署并核对哈希。

本例独立审查还发现了两个可复用的检查点：

- **喷口锚点要跨倍率稳定。** 主体采用画布中心 pivot 时，原生倍率从 3 变为 4，会把窄尾拉到施放者身后。将母图窄尾坐标作为该素材独立的 Sprite pivot，让统一缩放与固定倾角围绕发射端发生；短推位移另行补偿原生倍率。至少比较低、中、高倍率的同一时点与出手阶段，同时看尾端和拳套，不能仅凭脸部无遮挡就判定挂接正确。
- **GIF 要检查编码后的真实时长。** GIF 帧延时以 10 毫秒为单位，每帧写 33 毫秒可能被编码成 30 毫秒。30fps 预览可按 30／40／30 毫秒循环分配延时，尾帧按片段总长补齐；导出后重新读帧延时总和，与 MP4 的帧数／帧率比较。标称帧率不能代替实际编码检查。
